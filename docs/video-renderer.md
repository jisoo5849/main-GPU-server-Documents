# 영상용 렌더러 (2026-11-11, v1)

제작진 모드와 프롬프트 도우미가 만든 이미지 프롬프트와 별도로, 영상 모델(Wan 2.2 I2V·T2V)에 맞는 '움직임 프롬프트'를 쓰는 단계다.
v1 코드는 이 저장소에 있고 개발 PC 의 단위 테스트로만 확인했다. **메인 실기기에서는 아직 실행하지 않았다.**

## 1. 왜 필요한가

- 지난 영상 시험(Wan 2.2 I2V, 도우미 5편 + 제작진 5편)은 이미지 프롬프트 끝에 같은 문장("카메라가 천천히 다가가며 은은하게 움직인다")을 덧붙여 영상을 만들었다.
  - 백엔드에 영상용 프롬프트 기능이 없어서 그렇게 했다. 그래서 그 시험은 '제작진 모드의 효과'가 아니라 '이미지 + I2V 가 이어지는지'만 보여 준다.
- I2V 는 첫 화면 이미지가 외형(대상, 조명, 색, 구도)을 정한다. 프롬프트가 할 일은 **무엇이 어떻게 움직이는가**와 **카메라가 어떻게 움직이는가**다.
  - 이미지 프롬프트는 정지 장면의 외형을 길게 설명하는 글이라 영상 모델에 그대로 넣으면 움직임 지시가 약하다.
- 제작진 모드의 단계(배경, 조명, 색, 장르)에는 카메라 움직임, 속도, 마무리 칸이 없었다. 러다이트 예시의 "카메라가 천천히 다가간다"에 해당하는 부분이다.
- 사용자 의도 최우선 원칙(11-11 개편)을 영상에도 그대로 적용한다. 예: '천천히', '드론', '360도', '루프'를 사용자가 쓰면 선택과 글 모두에서 지킨다.

## 2. v1 범위 (11-11 결정)

| 포함 | 제외 (v2 이후) |
|---|---|
| Wan 2.2 I2V 단일 클립, Wan 2.2 T2V 단일 클립 | 컷 구성(두 컷·세 컷, 클립 나눠 잇기) |
| 첫 화면 이미지를 시각 모델로 읽기 | LTX 프로필과 사운드 칸 |
| 프레임 수·fps 는 **제안만** 표시 (노드에 자동으로 넣지 않음) | |

## 3. 흐름

```
I2V: 요청(도우미 칸) + 첫 화면(LoadImage) → [시각 모델: 첫 화면 읽기] → [확장 모델: 영상 제작진 초안 → 검사 → 고쳐 쓰기] → 움직임 프롬프트
T2V: 요청(도우미 칸) → [확장 모델: (도우미 결과가 없으면) 장면 확장 → 영상 제작진 초안 → 검사] → 장면 + 움직임 + 그림체 고정 문장
```

- 렌더러는 외형을 다시 쓰지 않는다. I2V 결과는 움직임 문장뿐이고 그림체 고정 문장도 붙이지 않는다(첫 화면이 이미 정했다).
- T2V 는 첫 화면이 없으므로 장면이 필요하다. 패널의 도우미 확장 결과가 있으면 그것을 쓰고, 없으면 같은 GPU 차례 안에서 도우미(제작진 모드 포함)로 장면부터 쓴다(`promptx.expand_in_turn`).
- 허브는 워크플로우를 만들지 않는다. 결과 글과 설정 제안만 돌려주고, 패널이 선택한 노드의 글 입력칸에 넣는다(이미지 도우미와 같다).

## 4. 영상 제작진 단계

요청이 제품·공간·풍경이면(이미지 제작진과 같은 `crew.route`) 단계 메뉴에서 고른다. 그 밖의 요청(사람, 캐릭터 정본, 손 숨김, 분야 없음)은 메뉴 없이 규칙과 '선택 아이디어'만으로 쓴다.
단계는 `hub/app/video_knowledge.json` 에 있고, 메뉴 재료는 라이브러리의 `video_motion` 칸(1,132개)을 묶음으로 나눠 쓴다(`crew_lib.retrieve` 의 `only`).

| 단계 | 제품 | 공간 | 풍경 |
|---|---|---|---|
| 카메라 | camera_* (7묶음) | camera_* | camera_* |
| 대상 움직임 | product_motion, liquid_motion, fabric_hair_motion | light_motion, fabric_hair_motion, liquid_motion, urban_motion | nature_motion, liquid_motion |
| 환경 움직임 | light_motion, air_particle_motion, liquid_motion, still_background | air_particle_motion, light_motion, still_background | air_particle_motion, light_motion, urban_motion, still_background |
| 속도 | pacing | pacing | pacing |
| 마무리 | ending_state, loopable | ending_state, loopable | ending_state, loopable |

- 단계마다 8개 안팎을 요청마다 새로 뽑는다. 사용자 영상 말과 맞는 항목을 먼저 넣고, 한 단계에 요구가 둘이면(예: '천천히 다가가는') 둘 다 맞는 항목을 먼저 넣는다.
- 환경 움직임에는 늘 '배경은 고요하게'(still_background) 선택지가 있다. 모든 영상이 배경까지 움직이지 않게 하려는 것이다.
- 요청에 사람이 없으면 사람이 나오는 항목은 뺀다(기존 거름). 글자·로고·간판을 지시하는 항목 7개(라벨 클로즈업, 네온 간판 등)는 영상 메뉴에서 늘 뺀다.
- 메뉴 항목은 '움직임 방식 · 예시 대상'(예: '15도 작은 호 이동 · 향수병')이다. 지시문은 예시 대상이 아니라 이 요청의 대상에 방식을 적용하라고 한다.

### 라이브러리 보강 (11-11)

설계 때 모자랐던 칸에 16개를 직접 썼다(검사 스크립트 통과).

| 더한 것 | 개수 |
|---|---:|
| 풍경 다가가기·물러나기 (원래 4개) | 6 |
| 풍경 고정 카메라 (원래 2개) | 4 |
| 공간·제품 고정 카메라 | 4 |
| 배경은 고요하게 (새 묶음 still_background) | 2 |

### 사용자 영상 말 (`crew_intent.json`)

영상 의도 14개를 더했다(사전 전체 162개). 영상 렌더러만 이 말을 요구로 보고, 이미지 확장과 이미지 제작진은 보지 않는다.

| 종류 | 말 (예) | 확인어 (예) |
|---|---|---|
| 카메라 | 다가가는·줌인, 멀어지는·줌아웃, 드론·항공, 360도·오빗, 회전하는, 패닝, 틸트, 고정 카메라·삼각대, 핸드헬드, 따라가는 | push in, pull back, drone, orbit, rotates, pan, tilt, static, handheld, tracking |
| 속도 | 천천히, 슬로모션, 빠르게·역동적 | slow, slow motion, fast |
| 마무리 | 루프, 반복되는 | loop, seamless |

- 날씨·시간 말(눈 오는, 비 오는, 안개 …)도 영상 글에 보여야 한다. 눈·비·안개는 움직이는 것이기 때문이다.
- 장르·색·조명·분위기 말은 첫 화면이 이미 따르므로 검사하지 않고 "움직임이 어긋나지 않게" 알려만 준다.
- 영상 항목은 태그가 '드론 비행' 같은 구절이라 낱말 태그로는 거의 잡히지 않아, 영문 문장의 확인어로도 요구 항목을 찾는다.

## 5. 초안 검사 규칙 (`video.check_video`)

| 규칙 | 막는 것 |
|---|---|
| 메뉴 id | 단계마다 그 요청의 메뉴 안에서 하나. 대상 움직임과 환경 움직임은 서로 다른 항목 |
| 사용자 영상 말 (선택) | 그 말과 맞는 항목이 메뉴에 있었으면 어느 단계에서든 하나는 골라야 한다 |
| 사용자 말 (글) | 영상 말과 날씨 말마다 확인어가 글에 낱말로 있어야 한다. T2V 는 장면 + 움직임을 함께 본다 |
| 외형 반복 금지 | 첫 화면(장면) 프롬프트와 6낱말 이상 연달아 같은 구절 |
| 카메라 이동은 하나 | 다가가기·물러나기·패닝·오빗·트래킹·크레인(틸트 포함) 중 둘 이상을 섞은 경우 [추정]. 주어가 카메라일 때만 세고, 사용자가 이동을 둘 썼으면 둘까지 허용한다 |
| 한 컷 | cut to, scene change, transition to 같은 장면 전환 |
| 길이 | I2V 25~90 낱말, T2V 움직임 부분 20~70 낱말 [추정] |
| 사람 | 요청에도 첫 화면에도 사람이 없는데 사람·손을 넣은 경우 |
| 손 숨김, 글자·로고, 부정어, 영문만, 한국어 설명 3칸 | 이미지 제작진과 같다 |

- 걸리면 한 번(`VIDEO_REPAIR_ROUNDS`) 고쳐 쓰게 한다. 제작진 단계 초안이 끝내 걸리면 메뉴 없이 다시 쓰고 패널에 알린다. 남은 위반은 패널에 그대로 보여 준다.

## 6. 첫 화면 읽기

- 패널이 화면의 LoadImage 노드(선택한 것 우선)에서 첫 화면 파일을 찾아 보낸다. 입력 폴더 또는 결과 폴더(`[output]`)의 이미지만 읽고, 폴더 밖 경로는 거부한다.
- 시각 모델(`VIDEO_FRAME_MODEL`, 비우면 `IMAGE_INSPECT_MODEL` = qwen3-vl:8b-instruct)이 대상, 위치, 배경, 사람 수, 움직일 수 있는 것, 샷을 JSON 으로 돌려준다. 긴 변 1024px 로 줄여 보낸다.
- 시각 모델이 확장 모델과 다르면 GPU 차례를 한 번 더 쓴다(한 차례에는 모델 하나만 올린다). 같은 모델이면 한 차례 안에서 처리한다.
- 파일을 못 찾거나 못 열거나 시각 모델이 실패해도 글만 보고 계속 쓰고 패널에 알린다. 패널의 체크를 끄면 읽지 않는다. 40MB 넘는 파일은 읽지 않는다.
- 첫 화면을 읽지 않았으면 그림에 사람이 있는지 모르므로 '사람 금지' 규칙을 적용하지 않는다.

## 7. 모델 프로필 (`video_knowledge.json` 의 `profiles`)

| 프로필 | 상태 | 문체 | 설정 제안 |
|---|---|---|---|
| wan22_i2v | 모델은 지난 영상 시험에서 씀 (렌더러 글은 미시험) | 짧은 움직임 문장: 카메라 → 대상 → 배경 → 마무리 | 16fps, 최대 81프레임(약 5초), 4n+1 프레임 |
| wan22_t2v | 모델 파일만 있음, 미시험 | 장면 다음에 움직임 문장 | 16fps, 최대 81프레임 [추정: I2V 와 같다고 봄] |

- 코드는 모델 이름을 모른다. 프로필을 더하면 패널 목록에 나온다(`GET /mgs/api/video_profiles`).
- 지난 영상 시험의 Wan 2.2 I2V 구성: 14B 고·저노이즈 fp8 + lightx2v 4스텝 LoRA, cfg 1, shift 5, 640×640, 81프레임, 16fps, 한 편 약 1분 반.
- 길이를 모델 한계보다 길게 적으면 81프레임으로 맞추고 "클립을 나눠 이어 붙여야 한다"고 알린다.

## 8. API와 패널

- `POST /mgs/api/expand_video` (환경 포트, 로그인 쿠키)
  - 받는 값: `text`, `notes`, `style`, `crew`, `profile`, `seconds`, `image`({filename, subfolder, type}), `image_prompt`, `read_frame`
  - 돌려주는 값: `prompt`(최종), `motion`, `scene`(T2V), `ko`(카메라·움직임·시간 설명), `crew`(고른 항목), `frame`(첫 화면 읽기), `settings`(프레임·fps·초), `violations`, `advice`, `rounds`
  - 접속 기록: `video_expand` (프로필, 회차, 남은 위반 수, 첫 화면 사용 여부, 제작진 분야·사용 여부)
- 패널: '영상 프롬프트' 카드(도우미 카드 아래)
  - 요청·꼭 지킬 특징·그림체·제작진 모드 체크는 도우미 칸의 값을 그대로 쓴다. 도우미 확장 결과가 있으면 `image_prompt` 로 함께 보낸다.
  - 프로필, 길이(초), 첫 화면 읽기 체크(I2V)를 고르고 '영상 프롬프트 만들기'를 누른다.
  - 결과: 영상 제작진 고른 항목, [카메라][움직임][시간] 설명, 첫 화면 읽기 요약, 프롬프트, 권장 설정, 위반·안내, 복사·선택한 노드에 넣기

## 10. 비용 [추정, 메인에서 재야 함]

- I2V + 첫 화면 읽기: GPU 차례 2번(시각 8B, 확장 27B). 확장 쪽은 초안 1~2회(+ 실패 시 메뉴 없이 1~2회).
- T2V(도우미 결과 없음): 차례 1번 안에서 장면(제작진 초안 + 도우미 확장)과 움직임 초안. 기본 설정에서 호출 2~9회.
- 영상 생성 자체가 한 편 약 1분 반이라 확장 시간이 상대적으로 작다고 본다.

## 11. 위험과 모르는 것 [TBD]
