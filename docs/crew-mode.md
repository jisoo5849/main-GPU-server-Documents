## 2026-11-11 개편: 사용자 의도 최우선, 선택지 확대

영상 시험(Wan 2.2 I2V)에서 제작진 모드의 실제 결함이 드러났다.

- "SF 영화처럼 보이는 향수 광고" 에서 SF 가 사라지고 '어두운 프리미엄 배경, 고급스럽게' 로 덮였다.

- "눈 오는" 요청이 비 오는 장면이 됐다.
- 원인: 단계마다 6~8개짜리 고정 메뉴, 장르 단계 없음, 사용자가 적은 말을 지켰는지 보는 검사 없음.

고친 것은 네 가지다.

1. **사용자 의도 사전** (`hub/app/crew_intent.json`, 이미지 의도 148개·한국어·영어 말 446개, 11-11 영상 렌더러용 영상 의도 15개 추가(1인칭 포함))
   - 장르·화풍·시대(73), 분위기(23), 색(22), 날씨·시간(18), 조명(12) 말만 넣었다. 요청이나 '꼭 지킬 특징' 칸에 이 말이 있으면 '반드시 지킬 말' 이 된다.
   - 형용사는 활용형도 잡는다. 예: 따뜻한 → 따뜻하고·따뜻하게, 신비로운 → 신비롭게, 푸른 → 푸르게
   - 제작진 초안은 그 단계에서 그 말에 맞는 항목을 골라야 하고, 영문 메모에도 확인어(예: SF → science fiction, futuristic)가 있어야 한다. 어기면 고쳐 쓰게 한다.
   - 도우미 확장도 같은 말을 'USER WORDS' 로 받고, 최종 프롬프트에 확인어가 없으면 위반으로 고쳐 쓰게 한다.
   - 확인어는 낱말로만 센다. 예: 'film grain' 의 grain, 'rainbow' 는 rain 으로 보지 않는다
   - 대상 이름은 넣지 않았다. 라이브러리 태그 전체로 요구를 뽑았을 때 대상이 요구로 잡혔기 때문이다.
     - 예: '향수 광고' 의 향수(perfume) → 향수 어린(nostalgia) 분위기, '우산' → 비 오는 날씨
2. **장르·스타일 단계 신설**: 세 분야 모두 마지막 단계가 장르다. 1~3개를 섞어 고를 수 있고, '지정 없음' 이 늘 메뉴에 있다.
3. **라이브러리 확대**: 고정 메뉴 대신 `hub/app/crew_library/*.jsonl` 16,053개 항목(11-17 전문가 검수 뒤)에서 요청마다 메뉴를 새로 뽑는다(아래 표).
4. **편향 제거**
   - 지시문 규칙: 사용자 말이 먼저이고, 요청이 없으면 '어두운 프리미엄' 을 기본값으로 쓰지 않는다.
   - 메뉴를 요청마다 무작위로 섞어 뽑으므로 같은 요청도 매번 다른 메뉴가 된다.
   - 도우미 메타 규칙에 '다양성'(10번)을 더했다.

## 동작

- 패널의 도우미 카드에서 '제작진 모드'를 켜 두고(기본 켬) 프롬프트 확장을 누르면, 서버가 요청을 분야로 나눈다.
  - 분야는 낱말 단위 키워드 점수로 정한다(한글은 앞뒤가 한글이면 다른 낱말의 일부로 보고 조사만 허용). 점수가 같은 모호한 요청은 기존 도우미로 간다.
    - 예: "우산"의 "산", "아이스크림"의 "아이", "bathroom"의 "room" 은 키워드로 잡지 않는다.
  - 다음 요청은 제작진 모드를 건너뛰고 패널에 이유를 알린다: 캐릭터 정본 이름(`CREW_GUARD_NAMES`)이 있는 요청, 손을 숨기라는 요청, 사람이 나오는 요청.
    - 11-26: 정본 이름 중 인물 라이브러리에 있는 인물만 나오는 요청은 건너뛰지 않고 정본 장면 분야(`cast_scene`)로 간다 (`CREW_CAST_MODE`).
  - 분야가 없는 요청(예: 책상 위 고양이)은 알림 없이 기존 도우미로 간다.
- 같은 GPU 차례(`llm_turn`) 안에서 LLM 을 두 단계로 부른다. 모델을 다시 올리지 않으므로 GPU 차례는 한 번이다.
  1. 제작진 초안: 단계마다 라이브러리에서 뽑은 메뉴(8개, 장르는 9~10개)에서 고르고, 한국어 지시서 네 칸과 영문 메모 3~6줄을 쓴다. 스키마 enum 으로 그 요청의 메뉴 밖 값을 막는다.
  2. 도우미 확장: 영문 메모를 '꼭 지킬 특징'에 더해 기존 규칙으로 최종 프롬프트를 만든다.
- 초안은 코드가 검사하고(`crew.check_crew`) 걸리면 한 번 고쳐 쓰게 한다. 그래도 걸리면 초안을 버리고 기존 도우미로 처리하며 패널에 안내가 뜬다.
- 응답에 `crew`(분야, 고른 항목, 한국어 지시서, 영문 메모, 위반)가 더해지고, 패널이 '제작진 지시서'로 보여 준다.

### 분야별 단계

| 분야 | 단계 (라이브러리 칸) |
|---|---|
| 제품 | 연출(product_presentation) → 배경(location_set) → 조명 → 카메라 → 색(color_palette) → 분위기(mood_emotion) → 장르(genre_style, 1~3개) |
| 공간 | 장소(location_set) → 조명 → 카메라 → 색 → 소품(props) → 분위기 → 장르 |
| 풍경 | 장소(location_set) → 날씨·시간(time_weather) → 구도(composition) → 색 → 대기(atmosphere) → 분위기 → 장르 |

### 메뉴를 뽑는 순서 (`crew_lib.retrieve`)

1. 사용자 요구 항목(의도 사전에서 나온 말과 맞는 항목, 요구마다 2개까지). 한 단계에 요구가 둘이면(예: '눈 오는 밤') 둘 다 맞는 항목을 먼저 넣는다
2. 요청 말과 태그·낱말이 겹치는 항목 (같은 점수 안에서는 무작위)
3. 분야 핵심 묶음(`crew_knowledge.json` 의 `prefer`)에서 고르게, 메뉴의 약 75%
4. 나머지 묶음에서 다양성 칸, 약 25%
5. 순서를 섞는다.

걸러 내는 것 (`crew_lib.allowed`, 사용자 요구 항목에도 똑같이 쓴다):

| 거름 | 막는 것 |
|---|---|
| 요청에 사람이 없으면 사람이 나오는 항목 제외 | 제품 컷에 모델·손이 끼는 것 |
| 요청과 다른 제품이 나오는 항목 제외 | 향수 광고 메뉴에 핸드백 연출 |
| 대상 이름과 같은 말의 분위기·색·조명 항목 제외 | 향수(perfume) 광고에 '향수 어린' 분위기 |
| 사용자가 장소를 말하면 그 장소 묶음에서만 고름 (`place_hints` 43개 말) | '집 안' 요청에 정글 롯지, 카지노 |
| 어두운 항목(라이브러리에 `"dark": true` 로 표시한 220개: 호러·스릴러·전쟁·범죄·재난·종말 장르, 전장 연기, 유령 저택 등)은 요청에 어두운 말(`dark_words`, 예: 호러·유령·전쟁·종말)이 있을 때만 | '바다' 태그로 '심해 괴물 호러' 가 끼는 것 |
| 분야 라벨이 다른 분위기 항목 제외 | 풍경 요청에 '(실내)' 분위기 |

## 2026-11-26 캐릭터 정본 장면 (`CREW_CAST_MODE`)

사용자 요청: "니키 장면에도 제작진 모드를 쓸 수 있게 해줘". 설계는 작업 보관 폴더의 `design.md`(11-26) 이고, 결정 세 가지는 다음과 같다.
1. 기본은 `safe`: 한 장 그림(패널 도우미·스튜디오 이미지·글→영상 장면 이미지)과 긴 영상·대사 영상의 영화 전체 초안 하나. 영상 렌더러의 클립 움직임은 지금처럼 건너뛴다.
2. 라이브러리 화풍(rich warm colours)일 때 색 단계는 따뜻한·중립 묶음(`cast_palette_warm`)만 쓴다. 사용자가 말한 색은 must 로 들어온다.
3. 정본 이름 + 손 숨김 요청은 계속 건너뛴다(`hidden_hands`). 라이브러리에 없는 정본 이름(퀼린스·타오바·일리아·일로케·일루키)은 `character`,
   라이브러리 이름 + 일반 사람 낱말('니키와 소년')은 `person` 으로 건너뛴다.

**판정** (`crew.cast_entries`·`cast_block_reason`·`cast_route`)
- 정본 이름 가드는 그대로 두고(`crew.route`·`skip_reason` 은 바뀌지 않음), 가드에 걸린 요청 중 이름이 낱말로 맞고 `cast_lib.known_in` 에도 나오는
  인물만 센다. known_in 은 한글 이름을 부분 일치로 찾아 '니키타' 에도 걸리기 때문이다.
- 가드 이름에만 조사 `에게·한테·께·야·네·와의·과의` 를 더했다(`crew_lib.GUARD_PARTICLES`). '니키에게…' 가 가드를 빠져나가 사람 없는 일반
  제작진으로 가던 구멍이다. 사람 낱말·분야 키워드·의도 말의 조사는 그대로다.

**분야** (`crew_knowledge.json` 의 `cast_categories`, `categories` 와 따로 두어 route 점수에 끼지 않는다)

| 분야 | 단계 (라이브러리 칸) | 쓰는 곳 |
|---|---|---|
| `cast_scene` | 조명 → 시간·날씨 → 카메라 → 구도 → 색 → 대기 → 분위기 | 한 장 그림 |
| `cast_film` | 시간·날씨 → 조명 → 색 → 대기 → 분위기 | 긴 영상·대사 영상의 영화 전체 (카메라·구도는 장면 shot·G0 대사 컷 규칙과 부딪혀 뺐다) |

- 장르·소품·장소·제품·재질 단계는 없다. 그래서 화풍·소품·옷감은 스키마 enum 에 나올 수 없다. 장소는 사용자 말과 전역 규칙이 지킨다.
- 단계마다 `only` 묶음만 쓰고(카메라는 shot_size·angle·lens_optics·focus_depth·camera_height·viewpoint, 구도는 인물 배치·가장자리 자르기·
  제품·그래픽 묶음을 뺐다, 대기는 magical_effect·digital_effect 를 뺐다), 색의 사용자 요구 항목도 화풍을 바꾸는 묶음(`must_skip`: duotone·
  tritone·monochrome·film_grade·fashion_beauty·textile_dye·art_medium·era_palette)은 넣지 않는다.

**막는 장치 다섯 겹**
1. 메뉴 거름: `crew_lib.CAST_BAN_EN_RE` (손·팔·들기·자세, 옷·모자·망토·머리·안경·수염, 사람·무리·형상·실루엣, 얼굴이 가려지는 화면(익스트림
   클로즈업·뒷모습·로우키), 피부, 글자 자리 구도). 기존 사람 거름(`PEOPLE_EN_RE`)도 그대로 걸린다.
2. 스키마 enum: 메뉴 id 만 허용하므로 1번이 곧 enum 이다.
3. 초안 검사(`check_crew(…, cast=…)`): 그 분야 단계 칸의 요구만 본다(장르 요구 'SF 느낌' 은 화풍 칸이 맡는다). 메모 줄마다 금지어
   (`crew.cast_bad_words`: 메뉴 금지어 + he·she·his·her + 손 낱말 + 사람(조건 없이) + 화풍 낱말 + 그 인물의 외형·소품 글에서 뽑은 명사(`cast_terms`))를 본다.
   글자 검사(`TEXT_NOTE_RE`)는 그대로다.
4. 메모 다듬기(`sanitize_cast_notes`): 고쳐 쓴 뒤에도 남은 위반이 정본 금지어뿐이면 그 줄만 지운다. 남은 줄이 3줄 미만이거나 다시 검사해
   걸리면 지금처럼 초안을 버린다.
5. 따로 싣기: 통과한 메모는 도우미의 '꼭 지킬 특징' 칸에 넣지 않고 `Crew look plan (light, camera and air only …)` 칸에, 정본 인물 외형은
   `Fixed characters (copy each look word for word …)` 칸에 싣는다(정본 우선, 11-10 보강 과제). 추가 아이디어는 끈다.

**11-10 실패 셋을 막는 곳**

| 11-10 실패 | 막는 장치 |
|---|---|
| 숨긴 손이 드러남 (V05 'one arm slightly raised to channel magical energy') | 손 숨김 요청은 건너뜀(결정 3), 메뉴 금지어(arm·raise·hand…, magical_effect 묶음 제외), 메모 금지어(손 낱말·he/she), 'Fixed characters' 칸 |
| 지어낸 글자 (G0 V07 시계 다이얼) | 글자 검사 `TEXT_NOTE_RE` 그대로, 글자 자리 구도 항목을 메뉴에서 뺌. 이미지 모델이 스스로 그리는 글자는 여전히 못 막는다 [TBD] |
| 목적 이탈 (인물 대신 배경을 연출) | 분야 규칙 "Keep every character fully readable (medium shot or wider, face toward the camera, signature items visible)", 알아볼 소품을 'keep visible' 로 알림, 익스트림 클로즈업·뒷모습·실루엣 항목 제외, 소품·장소·장르 단계 없음 |

**영화 전체 초안** (`crew.draft_film`, `CREW_CAST_MODE=safe`)
- `video.storyboard` 의 `video_story` 차례 안에서 구성안보다 먼저 받는다(새 GPU 차례 0회, 호출 +1~2회). 문맥 길이는 구성안과 같은 값이다:
  storyboard 가 `story_num_ctx(…, extra=LOOK_PLAN_RESERVE)` 로 한 번 정해 초안과 구성안에 똑같이 준다 (Ollama 는 num_ctx 가 바뀌면 모델을 다시 올린다).
- 구성안에는 'Look plan from the crew (not the user's words; never copy it into style_said …)' 로 붙인다. 'Must-keep details from the user' 에
  넣으면 style_said 로 옮겨져 라이브러리 화풍이 바뀌기 때문이다.
- 빛 계획(`story.crew`)은 LLM 메모가 아니라 고른 라이브러리 항목의 영문 원문이다(빛 160자, 대기 100자, 계획 600자). bible.light 에 고른 조명
  확인어가 없으면 덧붙이고 320자로 묶는다(`video.add_crew_look`): 정지 그림 지시문이 넘치면 compose 끝의 손·얼굴 문장부터 잘리기 때문이다.
- 장소 그림(`place_card_prompt`)에 `Air: …` 가 더해진다. 사람 없는 컷의 장면 그림 글은 장면마다 제작진을 돌리지 않고 이 빛 계획을 쓴다
  (`director._long_scene`, 같은 장소의 인물 컷과 빛이 어긋나지 않게).
- 정본 잠금(apply_to_story 의 외형·기준 그림 덮어쓰기, style_lock, 첫 화면 검사, G0 대사 판정)은 그대로다.
- 운영자 화면: 감독이 `film_crew` 이벤트(used·rounds·picked·violations)를 남기고, 긴 영상 보기와 '제작진' 칸에 빛 계획이 보인다.

## 설정 (`.env`)

```
CREW_MODE=auto
CREW_REPAIR_ROUNDS=1
CREW_GUARD_NAMES=니키,niki,...
CREW_CAST_MODE=safe
```

- `CREW_MODE=off`(또는 0, false, no)는 서버에서 끄므로 패널에서 켜도 쓰지 않는다. 그 밖의 값은 `auto` 로 본다.
- `auto` 에서는 패널의 체크박스(기본 켬)가 `crew: true/false` 로 전달되어 그 요청만 따르고, 값이 없으면 켠 것으로 본다.
- `CREW_GUARD_NAMES`: 정본 이름. 인물 라이브러리에 있는 이름은 정본 장면 분야로, 없는 이름은 건너뛴다.
- `CREW_CAST_MODE` (11-26): `safe`(기본) = 한 장 그림 + 긴 영상·대사 영상의 영화 전체 초안, `image` = 한 장 그림만, `off` = 예전처럼 정본 장면은
  건너뜀. 모르는 값은 safe. 단 가드 이름의 조사 추가('니키에게' 등을 정본 이름으로 봄)는 off 에서도 적용된다.

## 비용

- 제작진 초안 한 번이 같은 차례 안에 더해진다. GPU 차례는 늘지 않는다.

  - 표본이 작고 요청이 서로 달라 약 5초 추가로 본다 [추정].
