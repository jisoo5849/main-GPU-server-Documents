## 2. 설계 결정과 이유

### 채택: 편집 공간과 GPU 실행 공간 분리
- **편집 공간**: 사용자·프로젝트마다 Docker 컨테이너 1개, 항상 켜져 있음, **GPU 없음**(`--cpu`, GPU 장치 미연결, `NVIDIA_VISIBLE_DEVICES=void`). 편집·노드 설치·검증만 한다.
- **GPU 실행 공간**: 허브가 순서가 된 작업 하나를 위해 띄우는 컨테이너. **항상 최대 1개.** 접수 때 고정한 환경 버전의 사본으로 실행한다. 직전 작업과 버전이 같으면 켜 둔 것을 재사용.
- 왜: 세 설계안(편집·실행 겸용 / 분리 / 단순 운영안)을 만들어 실용성 심사·기술 심사·레드팀 점검을 거쳤다.
  겸용안은 편집 공간이 GPU 를 항상 갖고 있어 다른 사용자의 노드가 작업 중 VRAM 을 잡아도 **막을 수 없고 사후 감지만 가능** → 탈락.
  단순 운영안의 구조에 분리안의 네트워크 격리(icc=false, 편집↔실행 접속 차단)를 더한 것이 최종.

### 환경 고정 = btrfs 스냅샷
- `/srv/envs` 는 btrfs 전용 파티션. 작업공간은 `live/<slug>` subvolume, 실행 접수 때 `snap/<slug>/vNNNN` 읽기 전용 스냅샷.
- 변경 감지는 `btrfs subvolume show` 의 **Generation** 비교 (find-new 는 삭제를 못 잡아서 쓰지 않음).
- 노드 설치(pip/uv/git) 진행 중이면 끝날 때까지 기다린 뒤 스냅샷.
- 입력 이미지도 접수 때 `input/_mgs_pinned/<job>/` 에 reflink 사본으로 고정.
- 모델 파일은 접수 때 경로·크기·mtime 기록, 실행 직전에 바뀌었으면 작업을 거부하고 이유 기록.

### GPU 한 건 보장 장치 (여러 겹)
1. 편집 공간에 GPU 장치 없음 (장치 수준)
2. GPU 는 `dockerctl.run_worker()` 만 요청, 실행 공간 이름은 하나(`mgs-worker`)
3. DB 순번 `seq` 는 advisory lock 안에서 발급 → 커밋 순서 = 순번
4. 스케줄러 싱글턴 (advisory lock 4242)
5. `jobs_one_gpu_holder` 고유 인덱스: starting/running/cleaning 상태 작업은 DB 에 1건만 존재 가능
6. 컨테이너 네트워크 `enable_icc=false` + 방화벽: 컨테이너는 메인의 LLM 중계 포트만 접근
7. GPU 감시(2초): 허용되지 않은 프로세스가 GPU 를 쓰면 `incidents` 기록
8. 사용자에게 메인 터미널·docker 권한 없음

### 메모리 해제 확인 (scheduler._cleanup)
- NVML 로 메인에서 직접 측정. 기준: 유휴 사용량 B0(실행 공간·Ollama 모델 없을 때의 최솟값) + 실행 공간 기본 점유 ctx_mb.
- 단계: ① `/free unload_models` (30초) → ② `/free free_memory` (30초) → ③ 실행 공간 종료 (60초) → ④ LLM 이면 Ollama 재시작 → ⑤ 실패 시 `settings.blocked` 설정, 대기열 정지, 관리자 화면 배너. 접수는 계속 받는다.
- 끝낼 때 먼저 내부 LLM 호출을 막고(`lease_open=False`) 진행 중인 호출이 끝난 뒤 확인한다.

### LLM·임베딩
- 허브가 11434 포트에서 Ollama/OpenAI 형식 그대로 중계. 실제 Ollama 는 127.0.0.1:11435.
- 생성·채팅·임베딩은 같은 `jobs` 대기열(kind llm/embed). 모델 목록 조회는 바로 응답.
- **실행 중 실행 공간 IP 에서 온 호출은 대기열 없이 직통** (워크플로우 안 Ollama 노드의 교착 방지), `llm_calls.nested=true`.
- LLM 작업 전에는 켜 둔 실행 공간을 끈다 (ComfyUI 와 Ollama 가 동시에 VRAM 을 잡지 않게).
- Ollama: `KEEP_ALIVE=0`, `MAX_LOADED_MODELS=1`, `NUM_PARALLEL=1`.

### 결과물
- `--output-directory /srv/results/<사용자>`, 접수 때 `filename_prefix` 를 `<환경>/<날짜>/...` 로 바꿔서 `사용자/환경/날짜/` 구조.
- 작업마다 `<job_id>.json` 사이드카 (워크플로우, 모델, 환경 버전, 시간).
- Samba `[results]`: `read only = no`, 그룹 `comfyusers` 강제, `vfs objects = recycle` → `.recycle/%U/` 30일.
- 작업 이력(`/history`)은 모든 사용자 작업을 보여 주고, 파일이 없으면 "파일 없음" 표시.

### 쓰지 않기로 한 것
- Redis·Celery: GPU 1장, 순서 보장은 PostgreSQL 잠금 + LISTEN/NOTIFY 로 충분. 대기열과 기록이 한 DB 에 있어 불일치 없음.
- 사용자별 ComfyUI 1개 공유안(최초안): 커스텀 노드가 프로세스 전역이라 요구 3 을 못 맞춤.
- ZFS: 기능은 좋으나 관리자 1명 운영에는 btrfs 가 단순.
- `nvidia-smi -c EXCLUSIVE_PROCESS`: 내부 LLM 호출과 충돌하므로 미사용.

## 3. 검증된 사실 (ComfyUI v0.42.5 소스 기준, 2026-10-23)

- `POST /prompt` 는 클라이언트가 `prompt_id` 를 줄 수 있다(소문자 UUID 필수). 허브가 job_id 를 만들어 그대로 쓴다.
- 검증은 POST 안에서 동기 실행되며 그 인스턴스의 커스텀 노드·모델 목록에 의존 → 편집 공간에서 `/mgs/validate` 로 검증.
- `/free` 는 플래그만 세우고 즉시 200. 실제 해제는 워커 루프의 다음 반복. 완료 신호 없음 → NVML 폴링 필요.
- `/history` 는 메모리(최대 1만 건), 재시작하면 사라짐 → DB 에 복사(`jobs.comfy_history`, `comfy_job`).
- `/api/jobs` 응답 형식: `{"jobs":[{id,status(pending|in_progress|completed|failed|cancelled),priority,create_time,...}],"pagination":{...}}`. 허브가 DB 로 같은 형식을 만든다.
- WebSocket: `ws?clientId=` 로 재연결 가능. 실행 메시지는 제출한 client_id 로만 간다. 허브는 실행 공간에 `gw-<job>` 으로 붙고 브라우저 탭(`env_id, client_id`)으로 그대로 전달한다. `status` 의 `queue_remaining` 은 메인 전체 기준으로 바꿔 보낸다.
- 프론트엔드는 `location.pathname` 기준으로 API 주소를 만든다. 포트별 원점(origin)이 가장 안전(localStorage 도 환경별로 분리).
- `userdata/workflows%2Fx.json` 처럼 `%2F` 가 들어오므로 중계 때 raw path 를 유지해야 한다 (proxy.py 가 `scope['raw_path']` 사용).
- ComfyUI-Manager 는 pip 패키지 `comfyui_manager`(4.2.2) + `--enable-manager`. 127.0.0.1 리스너일 때 '로컬'로 인식. git URL·pip 설치는 `config.ini` 의 `allow_git_url_install`, `allow_pip_install` 과 `--enable-manager-legacy-ui` 필요.
- Manager 재시작은 `os.execv` 로 같은 PID 유지 → 컨테이너 안에서도 그대로 동작.
- `--temp-directory X` 는 실제로 `X/temp` 를 쓰고 시작 때 비운다 → 환경별로 따로.
- `extra_model_paths.yaml` 의 `is_default: true` 가 기본 다운로드 위치. 새 모델 파일은 재시작 없이 목록에 뜬다.
- NVIDIA Container Toolkit 1.20.x: `nvidia-ctk runtime configure` 는 `--set-as-default` 없이는 기본 런타임을 바꾸지 않는다. GPU 요청 없는 컨테이너에는 `/dev/nvidia*` 가 없다.
- Docker 28.3+ 는 CDI 기본 활성. `--gpus device=0` 또는 `--device nvidia.com/gpu=0`.
- Blackwell(sm_120) 은 드라이버 R580+ 와 torch cu130 휠 필요.

**검토에서 지적됐지만 고치지 않은 것 (이유)**

| 항목 | 이유 |
|---|---|
| 허브가 root 권한(privileged, docker.sock)으로 동작 | 의도된 설계. 허브는 관리자 전용 구성 요소이고 사용자는 메인 셸·docker 권한이 없다 |
| `jobs._queue_tuple` 이 prompt 를 빈 dict 로 채움 | 프런트엔드 1.57+ 는 `/queue` 를 쓰지 않고 `/jobs` 를 쓴다. 형식은 백엔드와 같아 문제 없음 |
| 정상 완료 시 `executing: null` 메시지를 브라우저에 안 보냄 | `execution_success` 에서 화면이 이미 상태를 초기화한다 |
| feature_flags 를 못 받은 탭(허브 재시작 뒤)은 미리보기가 메타데이터 없는 구형식으로 감 | 동작에 지장 없음 |
| 사용자별 `/srv/results/<사용자>` 아래 `.recycle` 폴더 소유권 | smbd 가 접속 사용자로 만들며 그룹 권한은 유지됨 |
| Manager 패키지(comfyui_manager 4.2.2) 내부에서 `prompt_queue.put` 을 직접 부르는지 | 소스 트리에 없어 미확인. 편집 공간은 어차피 허브를 거치지 않으면 실행이 안 되므로 영향 없음 |
| 메인에 `nmbd` 미실행 → `\\main` 이름 해석은 DNS/hosts 필요 | 설치 안내에 적혀 있음. IP 로 접속해도 됨 |
| `useradd` uid 가 1000 번대 자동 할당 → 관리자 계정과 섞임 | 기능상 문제 없음 |

**검토에서 정상으로 확인된 것** (실기기에서 다시 볼 필요가 낮음)

Docker SDK 호출 옵션(GPU 장치 요청, 네트워크 icc=false, cap_drop 등), btrfs 스냅샷·세대 번호 명령, NVML API 와 cgroup v2 PID 매핑,
asyncpg 코덱·파라미터 타입, PostgreSQL 고유 인덱스·interval 문법, postgres:18 데이터 경로, uvicorn 다중 소켓 포트 분기,
WebSocket clientId 매핑과 바이너리 미리보기 전달, `execution_error` 합성 메시지, 완료 감지 순서, `/view` 경로와 결과 파일 경로 일치,
ComfyUI 실행 옵션 전부, `extra_model_paths.yaml` 형식과 `custom_nodes` 항목, mgs_bridge 의 라우트 등록 시점과 `validate_prompt` 시그니처,
Samba 설정 문법, ufw 포트 범위 문법, compose 의 env 우선순위.

아래 후보는 검토 뒤에도 실기기에서만 확인되는 것들이다.

예상되는 첫 문제 후보 (코드를 읽을 때 먼저 볼 곳)
- `scheduler._check()` 의 PID→컨테이너 매핑: 허브는 `pid: host` 로 실행되므로 NVML PID 가 메인 PID 여야 한다. 아니면 `gpu.pid_container` 가 None 을 돌려 모든 프로세스를 '외부'로 본다.
- `proxy.handle_ws` 의 `status` 메시지 가공이 프론트엔드 큐 표시와 맞는지.
- `entrypoint.sh` worker 모드의 socat 11434 → `host.docker.internal` 이 실행 공간 네트워크에서 메인에 닿는지 (ufw 규칙 `WORKER_SUBNET`).
- 편집 공간 `--cpu` 에서 CUDA 필요 노드 import 실패 시 `/mgs/validate` 가 `missing_node_type` 을 내고, `ACCEPT_MISSING_NODES=true` 로 접수되는지.
- btrfs 스냅샷을 허브 컨테이너(privileged, 같은 경로 마운트) 안에서 실행하는데, 마운트 전파가 필요할 수 있다. 안 되면 `hub` 를 메인의 systemd 서비스로 돌리는 대안 (설계안 '단순 운영안'의 원안).
