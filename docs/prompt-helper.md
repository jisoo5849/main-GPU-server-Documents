# 프롬프트 도우미와 결과 자동 검사 (2026-10-27)

ComfyUI 화면의 '메인 GPU' 패널에 두 기능을 붙였다.
니키와 이상한 나침반 컨셉아트 작업에서 손으로 지킨 규칙과 손으로 한 검수를 서버가 대신 하게 만든 것이다.

## 1. 프롬프트 도우미 (메타 규칙 확장)

- 짧은 요청을 메인 Ollama 의 LLM(기본 `qwen3.8:27b`)이 생성용 영문 프롬프트로 늘린다.
  - 예: "책상 위 고양이" → 조명, 카메라, 배경, 질감을 채운 60~160 단어 프롬프트
- LLM 에는 시스템 지시로 규칙을 주고, 돌아온 결과를 허브 코드가 다시 검사한다 (`hub/app/promptx.py` 의 `check_expansion`).
- 규칙에 어긋나면 어긋난 점을 알려 주고 다시 쓰게 하며, 최대 횟수는 `PROMPT_EXPAND_REPAIR_ROUNDS` (기본 2회)다.
- 끝까지 남은 위반은 패널에 그대로 보여 주고, 사람이 보고 쓸지 정한다.

### 규칙

| 규칙 | 지시 | 코드 검사 |
|---|---|---|
| 주제 유지 | 사용자가 준 대상·동작·수·색·이름을 바꾸거나 빼지 않는다 | `keep` 목록의 말이 프롬프트에 그대로 있는지 |
| 시각 요소 | 조명, 카메라, 배경, 질감을 반드시 넣는다 | 네 항목이 비어 있지 않고 프롬프트 안의 구절인지 |
| 긍정문만 | no, not, without, avoid, never, -free 를 쓰지 않는다 | 부정어 검색 |
| 몸이 읽히게 | 인물 수, 팔·손·다리의 동작을 적고, 두 명 이상이면 위치와 색으로 구분한다 | 지시만 (검사는 결과 자동 검사에서) |
| 그림체 고정 | 그림체 문장은 코드가 끝에 그대로 붙이고, LLM 은 다른 그림체 말을 넣지 않는다 | 고정했을 때 8K, Unreal Engine, photorealistic 같은 말 검색 |
| 오독 단어 | silhouette, ducking 같은 말을 피한다 | 사용자가 쓰지 않았는데 나오면 위반 |
| 길이 | 60~160 단어 | 40 미만, 220 초과면 위반 |
| 손 숨김 | 요청에 손을 소매 속에 숨기라는 말이 있으면 hand, holding, grip 같은 말을 쓰지 않고, 물건은 소매 끝에 끼우거나 몸에 기대게 쓴다 | 손·쥐는 동작 단어가 프롬프트나 `keep` 에 있으면 위반 |
| 해 주는 동작 | "~해 주는", "~에게", "~와 함께" 처럼 상대가 있는 동작이면 그 사람도 그리고, 위치와 색으로 구분한다 | `people` 이 2 미만이거나 위치 말(left, right 등)이 없으면 위반 |

- 오독 단어는 이번 작업에서 실제로 나온 오류에서 가져왔다.
  - 예: "silhouette" 는 배경에 사람 모양 그림자를, "ducking" 은 오리를 그렸다.
- 기존 작품·작가 이름을 넣지 않는 규칙은 지시에만 있고 코드 검사는 없다 [TBD].
- 손 숨김과 해 주는 동작 규칙은 2026-10-27 메인 시험에서 나온 오류에서 가져왔다.
  - 예: "비 오는 날 우산을 씌워 주는 소녀" + "손은 항상 긴 소매 속에 숨김" → "holding a large umbrella" 가 들어가 두 장 모두 손이 그려졌고, 우산을 씌워 줄 상대가 빠졌다.
- 이 두 경우에는 패널 결과 아래에 '참고' 안내를 붙인다.
  - 예: 손 숨김은 글만으로 잘 지켜지지 않으니 Qwen-Image-Edit 편집 단계를 계획하라는 안내
- 손 단어를 빼도 Z-Image 가 손을 그리지 않는지는 메인 반영 뒤 확인한다 [TBD].

### 제작진 모드 (2026-11-10)

- 제품·공간·풍경 요청에는 확장 앞에 분야별 전문가 지식 초안 단계가 붙는다. 자세한 내용은 [crew-mode.md](crew-mode.md) 에 있다.
- 응답에 `crew` 가 더해지고, `POST /mgs/api/expand` 는 `crew`(true/false)를 받아 그 요청만 켜거나 끈다.

## 2. 결과 자동 검사 (시각 모델)

- 패널에서 '결과 자동 검사' 를 켜면, 이 화면에서 실행한 작업이 끝날 때마다 결과 이미지를 시각 모델(기본 `qwen3-vl:8b-instruct`)이 본다.
- 팔·다리·손가락 개수, 머리 없음이나 목 없음, 두 몸이 붙음, 떠 있는 팔다리 같은 해부학 오류를 찾는다.
- '꼭 보여야 할 특징' 에 한 줄씩 적으면 각각 보이는지도 확인한다.
  - 예: hands hidden inside long sleeves
- 문제가 있으면 알림을 띄우고, '시드 바꿔 다시 실행' 버튼으로 같은 설정에 시드만 바꿔 다시 대기열에 넣는다.
- 시각 모델도 개수 세기에서 틀릴 수 있으므로, 결과는 사람이 확인할 후보를 고르는 용도로 쓴다.

### 사람별 부위 검사 (2026-10-27 추가)

- 메인에서 시험해 보니, 세 명이 있는 시트 전체를 보여 주면 시각 모델이 세 번째 손을 놓쳤다.
  - 예: `niki_5_s15155` 의 오른쪽 인물 옆구리에 붙은 세 번째 손
- 같은 인물만 잘라 "손이 몇 개냐" 고 물어도 틀렸고, "오른쪽 옆구리에 손이 하나 더 있느냐" 처럼 구체적으로 물으면 맞혔다.
- 그래서 검사를 한 차례 안에서 세 단계로 나눴다.
  1. 전체 그림으로 특징과 눈에 띄는 오류를 본다 (기존 검사).
  2. 그림 속 인물마다 상자(0~1000 좌표)를 받는다.
  3. 허브가 상자대로 잘라(Pillow) 인물마다 머리·팔·손·다리를 한 줄씩 나열하게 하고, 개수는 코드가 센다 (`body_issues`).
- 손·팔·다리가 3개 이상이면 `extra_limb`, 머리가 없거나 둘이면 `missing_head`·`extra_head`, 몸에 안 붙은 손이 있으면 `floating_limb` 다.
- 소매 속에 숨긴 손은 나열하지 않게 했으므로 손이 적은 것은 문제로 보지 않는다.
- 인물 찾기가 실패하면 1단계 결과만 돌려준다.
- 인물이 많을수록 호출이 늘어난다 (인물 수 + 2회, 최대 인물 8명).
- 나열 방식이 세 번째 손을 실제로 잡아내는지는 메인 반영 뒤 다시 확인한다 [TBD].

## GPU 대기열과 비용

- 두 기능 모두 GPU 를 쓰므로 다른 작업과 같은 DB 대기열을 거친다 (`hub/app/llm.py` 의 `llm_turn`).
- 확장 한 번은 대기열 한 건이며, 고쳐 쓰기 반복은 같은 차례 안에서 모델을 다시 올리지 않고 처리한다.
- 검사는 이미지 한 장마다 대기열 한 건이며, 그 안에서 인물 수 + 2번 모델을 부른다.
- 두 기능 모두 생각 단계(`think`)를 끄고 부른다 (메인 측정: 켜면 27b 확장 한 번 약 100초).
- LLM 차례가 오면 켜 둔 ComfyUI 실행 공간을 먼저 끄므로, 다음 이미지 작업은 실행 공간을 다시 띄우는 시간이 더 든다.
- 차례를 기다리는 최대 시간은 `HELPER_WAIT_SECONDS` (기본 900초)다.
- 기록은 `llm_calls` 에 `helper:prompt_expand`, `helper:image_inspect` 로, 접속 기록에 `prompt_expand`, `image_inspect` 로 남는다.

## API (환경 포트, 로그인 쿠키)

- `POST /mgs/api/expand` 에 `{"text", "notes", "style"}` 를 보내면 `{"prompt", "violations", "rounds", "keep", "categories", "model", "advice"}` 을 돌려준다.
- `POST /mgs/api/inspect` 에 `{"filename", "subfolder", "type": "output", "expect": []}` 를 보내면 `{"ok", "people", "issues", "traits", "figures"}` 를 돌려준다.
- `figures` 는 인물별 `{"label", "box", "hands", "arms", "issues"}` 이다.

## 설정 (`.env`)

```
PROMPT_EXPAND_MODEL=qwen3.8:27b
PROMPT_EXPAND_REPAIR_ROUNDS=2
IMAGE_INSPECT_MODEL=qwen3-vl:8b-instruct
HELPER_WAIT_SECONDS=900
```
