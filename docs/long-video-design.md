# 긴 영상 + 소리 설계 초안 (2026-11-16)

채팅 스튜디오에 "유튜브에 올릴 수준의 긴 영상"과 "모든 영상에 소리"를 더하는 설계다. 지금의 5초 영상(장면 이미지 → Wan I2V)은 품질이
확인됐으므로 그대로 두고, 그 위에 새 길을 만든다. 구현 전 초안이며, 0단계 실측 결과로 숫자와 결정을 고친다.

## 0. 사용자 결정 (11-16)

| 번호 | 결정 |
|---|---|
| U1 | 길이: 유튜브에 나오는 수준의 긴 영상 (20초 한 번 생성보다 길게) |
| U2 | 소리: 환경음·효과음에 **배경음악도 기본**. 대사는 요청할 때 |
| U3 | 짧은 영상도 **전부 소리 포함** |
| U4 | 컷: 요청에 맞으면 한 번 생성 안에서 2~3컷(멀티샷), 단순한 요청은 한 컷 |

## 1. 메인에 이미 있는 재료 (11-16 확인: 모델 폴더 목록과 공식 템플릿)

| 용도 | 모델·파일 | 공식 템플릿 | 비고 |
|---|---|---|---|
| 영상 + 소리 한 번에 | LTX-2.5 22B distilled int8, Gemma 4 12B 글 인코더, 영상·소리 VAE, 잠재 업스케일러 x2, 프롬프트 확장기(Gemma 4 e2b) | `video_ltx2_5_i2v`, `video_ltx2_5_t2v`, `video_ltx2_5_flf2v` | 기본 5초·24fps·1280×720, 2단(반 해상도 8스텝 → 업스케일 3스텝). 한 번 생성 최대 20초로 알려짐 [공개 자료, 실측 전]. 한 번 생성에 여러 컷(멀티샷) |
| 영상 + 소리 (이전 판) | LTX-2.3 22B dev·distilled fp8, IC-LoRA, ID-LoRA | `video_ltx2_3_i2v`, `video_ltx2_3_ia2v`(사진 + 소리 → 입 모양) 등 | 대사 영상(입 모양 맞추기)에 쓸 수 있다 |
| 배경음악 | ACE-Step 1.5 XL Turbo, Qwen 0.6B·4B 인코더, ACE 1.5 VAE | `audio_ace_step1_5_xl_turbo` | 글 → 음악, 길이 지정(템플릿 기본 120초), 8스텝 |
| 말하는 영상 (나중) | Wan2.2 S2V, InfiniteTalk, wav2vec2·whisper | `video_wan2_2_14B_s2v` 등 | 소리 파일을 받아 분 단위 영상 |
| 없는 것 | 영상 → 효과음 전용 모델(MMAudio 류), 로컬 한국어 음성 합성(TTS) | | Stable Audio 3 은 조건부 라이선스(매출 US$1M)이고 설치되어 있지 않다 |

LTX 라이선스는 그룹 매출 US$10M 미만 무료(`models/README_KO.md`, 확인됨). MiniMax H3 템플릿도 있지만 라이선스가 대한민국을 제외해 쓰지 않는다.

## 1.1 0단계 실측 결과 (2026-11-16, 메인, 공식 템플릿 그대로, 1280×720(실제 1280×704), 24fps, 프롬프트 확장기 끔)

| 시험 | 실행 시간 | 결과 |
|---|---|---|
| LTX-2.5 글→영상 5초 (소리 포함) | 49.6초 | 영상·소리 한 파일(mp4, 소리 48kHz 스테레오), 1.3MB |
| LTX-2.5 글→영상 10초 | 57.0초 | 소리 있음, 1.8MB |
| LTX-2.5 글→영상 20초 | 137.0초 | 한 번 생성으로 20.04초, 소리 20초 내내 이어짐(2초 구간 음량이 0.10~0.14로 고름), 생물 모습이 20초 동안 유지, 3.5MB |
| LTX-2.5 이미지→영상 10초 (앞 시험의 첫 프레임 사용) | 62.4초 | 첫 화면의 모습을 유지하며 왼쪽에서 오른쪽으로 지나가 프레임 밖으로 나감(프롬프트대로) |
| LTX-2.5 글→영상 5초, 한국어 대사 | 30.4초 (모델 캐시가 따뜻함) | 사람 얼굴이 또렷하고 입이 움직임, 소리는 말소리처럼 음량이 오르내림. **한국어 발음이 맞는지는 귀로 확인해야 한다 [미확인]** |
| ACE-Step 1.5 XL Turbo 배경음악 180초 (반주만) | 22.6초 | 180초 스테레오 mp3, 5.8MB, 처음과 끝이 서서히 작아지는 모양 |

- 비교 기준: Wan 5초 높음(1024×576, 20스텝)은 약 11분, 빠름(848×480)은 약 40~50초였다. LTX-2.5 는 **720p 20초가 약 2분 17초**, 소리까지 들어 있다. 20초에 걸린 시간이 5초의 약 2.8배라 길이에 거의 비례하지 않는다.
- 위 시간은 실행(execution) 시간이다. 첫 실행의 모델 올리기(콜드 스타트)가 더해질 수 있고, 장면 이미지·LLM 시간은 별도다.
- **결론**: 20초 한 장면을 소리까지 2~3분에 만들 수 있고, 3분 영상(20초 × 9장면)은 영상 약 20분 + 음악 약 25초 + 장면 이미지·LLM 몇 분으로 추정된다 [추정]. L6(GPU 시간)은 이 숫자를 계획 카드에 보이는 쪽으로 정한다.
- 20초를 넘겨 한 번에 만들기(`LTXVContextWindows`)와 1080p 업스케일은 아직 시험하지 않았다.

## 2. 구조: 한 요청 = 사용자에게는 한 작업

```
요청 ─▶ ① 구성안 (LLM 27B)
          총 길이, 장면 목록(장면당 10~20초, 장면 안 컷 1~3), 장면마다 화면·움직임·소리(환경음·효과음·대사),
          배경음악 설명(장르·분위기·빠르기·악기, 반주만), 인물·장소 설정집(모든 장면에 같은 말로 넣는다)
     ─▶ 계획 카드: 장면표·총 길이·예상 시간 → [승인]
     ─▶ ② 장면마다: 장면 이미지(Z-Image) → LTX-2.5 이미지→영상 (환경음·효과음·대사 포함, 음악은 넣지 않음)
     ─▶ ③ 배경음악: ACE-Step 으로 전체 길이 한 곡 (반주만)
     ─▶ ④ 합치기 (CPU, ffmpeg): 장면 이어 붙이기, 장면 소리 + 음악 섞기(대사 동안 음악을 줄임), 음량 맞춤(-14 LUFS)
     ─▶ 결과 영상 하나 (채팅에는 이것만)
```

- **짧은 영상(20초 이하)도 같은 길**이다. 장면이 하나일 뿐이다. 음악을 LTX 에 함께 시킬지(한 번에), ACE-Step 으로 따로 깔지는 0단계에서 비교한다.
- **GPU 차례**: 장면 이미지·장면 영상·음악이 각각 별도 작업으로 대기열에 들어간다. 그래서 긴 영상 하나가 GPU 를 몇십 분 독점하지 않고,
  다른 사람 작업이 장면 사이에 끼어든다 (기존 원칙 "한 번에 한 작업, DB 순번"을 그대로 따른다).
- **합치기는 GPU 를 쓰지 않는다.** ComfyUI 노드(ConcatenateVideo·AudioMerge)로 합치면 모든 프레임을 메모리에 올려야 해서
  (3분 720p ≈ 4,300프레임, float 로 약 140GB) 쓰지 않는다. 허브 컨테이너에 ffmpeg 를 넣고 파일 단위로 스트리밍해 합친다.
- **사용자에게 보이는 것**: 진행 카드 하나("구성안 → 장면 1/9 → … → 음악 → 마무리"), 결과 영상 하나. 장면 이미지·장면별 클립·음악 파일은
  결과 폴더에만 남는다 (지금의 장면 이미지와 같다).

## 3. 장면 사이 이어짐

| 경우 | 방법 |
|---|---|
| 같은 장소, 동작이 이어짐 | 앞 장면의 마지막 프레임을 다음 장면 첫 화면으로 쓴다 (장면 이미지를 새로 만들지 않는다) |
| 장소·시간이 바뀜 | 새 장면 이미지. 설정집의 인물·장소 묘사를 글자 그대로 넣어 모습을 맞춘다 |
| 인물 얼굴 (2단계) | 인물 기준 이미지를 한 번 만들고, 장면마다 Qwen 편집으로 그 인물을 넣는다 |
| 장면 경계의 소리 | 장면 소리는 짧게 겹쳐 잇고(교차 페이드), 음악은 한 곡이라 끊기지 않는다 |

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| **0. 실측** (먼저) | 메인에서 공식 템플릿으로: LTX-2.5 I2V 5·10·20초 720p 의 시간·VRAM·품질·소리 / 같은 요청의 Wan 5초와 비교 / ACE-Step 60·180초 시간·품질 / 한국어 대사 / `LTXVContextWindows` 로 20초 넘게 한 번 생성 가능성 | 숫자 표와 영상 몇 개, L2·L6·L7 결정 |
| 1. 모든 영상에 소리 (한 장면, 20초까지) — **구현함(11-16, 메인 시험 전)** | LTX-2.5 레시피 `ltx25_i2v_sound`, 영상 프롬프트 프로필 `ltx25_i2v_long`(네 단락 + 'Audio:' 소리 단락을 따로 씀, 배경음악은 LTX 가 같이 만든다), 길이 칸 2~20초, 소리 칸(자동·포함·없음), 화질 높음은 소리 없는 Wan | 채팅에서 20초 소리 영상이 계획 카드 → 결과까지 |
| 2. 긴 영상 (여러 장면) | 구성안 LLM, 장면 반복, ffmpeg 합치기, 계획 카드의 장면표, 장면 하나만 다시 만들기 | 1~3분 영상 한 요청으로 |
| 3. 다듬기 | 인물 기준 이미지, 내레이션, 자막, 1080p, 썸네일, 9:16 쇼츠 | |

## 5. 정해야 할 것

| 번호 | 질문 | 권장 |
|---|---|---|
| L1 | "유튜브 수준" 길이의 첫 목표 | 2단계는 3분까지, 실측을 보고 늘린다 |
| L2 | 짧은 영상: LTX 로 바꿀까, Wan 영상 + 음악만 깔까 (Wan 에는 효과음을 만들 모델이 없다) | 0단계에서 같은 요청으로 비교한 뒤 정한다 |
| L3 | 비율 | 16:9 기본, 9:16(쇼츠) 칸 |
| L4 | 해상도 | 720p 기본. 1080p 는 업스케일 시간을 잰 뒤 |
| L5 | 배경음악 크기, 대사 때 얼마나 줄일지 | 음악 -18 LUFS 안팎, 대사 때 6dB 줄임 [추정, 들어 보고 정함] |
| L6 | 긴 영상의 GPU 시간 (3분 = 20초 장면 9개) | 실측 뒤. 길면 계획 카드에 시간을 보이고, 필요하면 밤 시간 대기 같은 규칙 |
| L7 | 대사 언어 | 한국어 대사 품질을 들어 보고 정한다. 안 되면 대사는 영어, 한국어는 자막 |
| L8 | LTX 라이선스 | 매출 US$10M 미만 무료. 사업 조건이 바뀌면 다시 확인 |

## 6. 지금 코드에서 바뀌는 곳 (1·2단계 예상)

- `hub/app/studio/recipes/`: LTX-2.5 I2V 레시피(길이는 초 단위 자리, 소리 출력 포함), ACE-Step 음악 레시피

- `hub/app/studio/director.py`: 장면 반복과 음악·합치기 단계 (지금의 숨은 두 단계를 여러 장면으로 넓힌다)
