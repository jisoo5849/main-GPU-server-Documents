# 긴 영상 + 소리 설계 초안 (2026-11-16)

채팅 스튜디오에 "유튜브에 올릴 수준의 긴 영상"과 "모든 영상에 소리"를 더하는 설계다. 지금의 5초 영상(장면 이미지 → Wan I2V)은 품질이
확인됐으므로 그대로 두고, 그 위에 새 길을 만든다. 구현 전 초안이며, 0단계 실측 결과로 숫자와 결정을 고친다.

## 0. 사용자 결정 (11-16)

| 번호 | 결정 |
|---|---|
| U1 | 길이: 유튜브에 나오는 수준의 긴 영상 (20초 한 번 생성보다 길게) |
| U2 | 소리: 환경음·효과음에 **배경음악도 기본**. 대사는 요청할 때 |
| U3 | 짧은 영상도 **전부 소리 포함** |
| U4 | 컷: 요청에 맞으면 한 번 생성 안에서 2~3컷(멀티샷), 단순한 요청은 한 컷 |

## 1. 메인에 이미 있는 재료 (11-16 확인: 모델 폴더 목록과 공식 템플릿)

LTX 라이선스는 그룹 매출 US$10M 미만 무료(`models/README_KO.md`, 확인됨). MiniMax H3 템플릿도 있지만 라이선스가 대한민국을 제외해 쓰지 않는다.

## 1.1 0단계 실측 결과 (2026-11-16, 메인, 공식 템플릿 그대로, 1280×720(실제 1280×704), 24fps, 프롬프트 확장기 끔)

| 시험 | 실행 시간 | 결과 |
|---|---|---|
| LTX-2.5 글→영상 5초 (소리 포함) | 49.6초 | 영상·소리 한 파일(mp4, 소리 48kHz 스테레오), 1.3MB |
| LTX-2.5 글→영상 10초 | 57.0초 | 소리 있음, 1.8MB |
| LTX-2.5 글→영상 20초 | 137.0초 | 한 번 생성으로 20.04초, 소리 20초 내내 이어짐(2초 구간 음량이 0.10~0.14로 고름), 생물 모습이 20초 동안 유지, 3.5MB |
| LTX-2.5 이미지→영상 10초 (앞 시험의 첫 프레임 사용) | 62.4초 | 첫 화면의 모습을 유지하며 왼쪽에서 오른쪽으로 지나가 프레임 밖으로 나감(프롬프트대로) |
| LTX-2.5 글→영상 5초, 한국어 대사 | 30.4초 (모델 캐시가 따뜻함) | 사람 얼굴이 또렷하고 입이 움직임, 소리는 말소리처럼 음량이 오르내림. **한국어 발음이 맞는지는 귀로 확인해야 한다 [미확인]** |
| ACE-Step 1.5 XL Turbo 배경음악 180초 (반주만) | 22.6초 | 180초 스테레오 mp3, 5.8MB, 처음과 끝이 서서히 작아지는 모양 |

- 비교 기준: Wan 5초 높음(1024×576, 20스텝)은 약 11분, 빠름(848×480)은 약 40~50초였다. LTX-2.5 는 **720p 20초가 약 2분 17초**, 소리까지 들어 있다. 20초에 걸린 시간이 5초의 약 2.8배라 길이에 거의 비례하지 않는다.
- 위 시간은 실행(execution) 시간이다. 첫 실행의 모델 올리기(콜드 스타트)가 더해질 수 있고, 장면 이미지·LLM 시간은 별도다.
- **결론**: 20초 한 장면을 소리까지 2~3분에 만들 수 있고, 3분 영상(20초 × 9장면)은 영상 약 20분 + 음악 약 25초 + 장면 이미지·LLM 몇 분으로 추정된다 [추정]. L6(GPU 시간)은 이 숫자를 계획 카드에 보이는 쪽으로 정한다.
- 20초를 넘겨 한 번에 만들기(`LTXVContextWindows`)와 1080p 업스케일은 아직 시험하지 않았다.

## 2. 구조: 한 요청 = 사용자에게는 한 작업

```
요청 ─▶ ① 구성안 (LLM 27B)
          총 길이, 장면 목록(장면당 10~20초, 장면 안 컷 1~3), 장면마다 화면·움직임·소리(환경음·효과음·대사),
          배경음악 설명(장르·분위기·빠르기·악기, 반주만), 인물·장소 설정집(모든 장면에 같은 말로 넣는다)
     ─▶ 계획 카드: 장면표·총 길이·예상 시간 → [승인]
     ─▶ ② 장면마다: 장면 이미지(Z-Image) → LTX-2.5 이미지→영상 (환경음·효과음·대사 포함, 음악은 넣지 않음)
     ─▶ ③ 배경음악: ACE-Step 으로 전체 길이 한 곡 (반주만)
     ─▶ ④ 합치기 (CPU, ffmpeg): 장면 이어 붙이기, 장면 소리 + 음악 섞기(대사 동안 음악을 줄임), 음량 맞춤(-14 LUFS)
     ─▶ 결과 영상 하나 (채팅에는 이것만)
```

- **짧은 영상(20초 이하)도 같은 길**이다. 장면이 하나일 뿐이다. 음악을 LTX 에 함께 시킬지(한 번에), ACE-Step 으로 따로 깔지는 0단계에서 비교한다.
- **GPU 차례**: 장면 이미지·장면 영상·음악이 각각 별도 작업으로 대기열에 들어간다. 그래서 긴 영상 하나가 GPU 를 몇십 분 독점하지 않고,
  다른 사람 작업이 장면 사이에 끼어든다 (기존 원칙 "한 번에 한 작업, DB 순번"을 그대로 따른다).
- **합치기는 GPU 를 쓰지 않는다.** ComfyUI 노드(ConcatenateVideo·AudioMerge)로 합치면 모든 프레임을 메모리에 올려야 해서
  (3분 720p ≈ 4,300프레임, float 로 약 140GB) 쓰지 않는다. 허브 컨테이너에 ffmpeg 를 넣고 파일 단위로 스트리밍해 합친다.
- **사용자에게 보이는 것**: 진행 카드 하나("구성안 → 장면 1/9 → … → 음악 → 마무리"), 결과 영상 하나. 장면 이미지·장면별 클립·음악 파일은
  결과 폴더에만 남는다 (지금의 장면 이미지와 같다).

## 3. 장면 사이 이어짐

| 경우 | 방법 |
|---|---|
| 같은 장소, 동작이 이어짐 | 앞 장면의 마지막 프레임을 다음 장면 첫 화면으로 쓴다 (장면 이미지를 새로 만들지 않는다) |
| 장소·시간이 바뀜 | 새 장면 이미지. 설정집의 인물·장소 묘사를 글자 그대로 넣어 모습을 맞춘다 |
| 인물 얼굴 (2단계) | 인물 기준 이미지를 한 번 만들고, 장면마다 Qwen 편집으로 그 인물을 넣는다 |
| 장면 경계의 소리 | 장면 소리는 짧게 겹쳐 잇고(교차 페이드), 음악은 한 곡이라 끊기지 않는다 |

## 7. 2단계 세부 설계 (2026-11-17, 첫 목표 3분)

사용자 결정 (11-17): **L1 = 3분부터**. 1단계 이후 메인에 반영된 연출 계획표·3구간 타임라인·소리 크기 규칙을 장면마다 그대로 쓴다.

### 7.1 긴 영상이 되는 조건

- 글→영상 + 소리 포함(LTX)이고 길이가 20초를 넘을 때. 글("3분", "1분 30초", "90초")이나 길이 칸(30초·1분·1분 30초·2분·3분)으로 정한다.
- 3분이 넘으면 3분으로 맞추고 안내한다.
- 사진을 붙인 요청(이미지→영상)과 "소리 없이" 요청은 지금처럼 한 장면(20초·5초)으로 만들고 안내한다. 이번 단계의 긴 영상은 글→영상만이다.
- 긴 영상은 대화 설정과 상관없이 **늘 계획 카드를 거친다** (GPU 를 한 시간 넘게 쓴다).

### 7.2 흐름

| 순서 | 하는 일 | 쓰는 것 |
|---|---|---|
| 1 | **구성안**: 제목, 한 줄 줄거리, 설정집(인물·장소의 고정된 모습, 시간대, 빛), 배경음악(태그·빠르기·조성), 장면표(장면마다 길이·장소·인물·앞 장면과 이어지는지·카메라·동작·소리·한국어 한 줄) | 27B, purpose `video_story`, 검사 후 최대 2번 고쳐 쓰기 |
| 2 | **계획 카드**: 총 길이, 장면 수, 장면표, 배경음악, 크기, 화질, 예상 시간 → 승인 | 기존 계획 카드에 장면표를 더함 |
| 3 | **장면마다**: 연출 계획표 → 첫 화면(이어지는 장면은 앞 장면 마지막 프레임, 아니면 장면 이미지) → 영상 프롬프트(소리 단락은 음악 없이) → LTX 이미지→영상 | 기존 부품 그대로 (`video.plan`·`expand_image`·`video.render`·`video.fix`, Z-Image, LTX 레시피) |
| 4 | **배경음악**: 총 길이 + 2초 한 곡, 반주만 | ACE-Step 1.5 XL Turbo 레시피 `ace_step_music` (새로) |
| 5 | **합치기**: 영상 이어 붙이기, 장면 소리 크기 맞추기, 음악 섞기, 음량 맞춤 | 허브의 ffmpeg (`studio/assemble.py`, GPU 안 씀) |
| 6 | **결과 메시지 하나** (합친 영상). 장면 이미지·클립·음악은 결과 폴더에만 남는다 | |

**구성안 검사**: 장면 길이 5~20초(정수), 합계가 목표 길이의 ±10%, 장소·인물 id 가 설정집에 있음, 첫 장면은 이어짐이 아님, 이어지는 장면은 앞 장면과 장소가 같음,
영어 칸에 한글 없음·`ko` 칸은 한국어, 음악 조성은 ACE-Step 이 받는 값·빠르기 50~180, 요청에 사람이 없으면 인물 없음.

**장면 하나의 글**: 영상 렌더러에는 "요청 = 장면의 한국어 한 줄", "지킬 것 = 설정집 + 이 장면의 영어 묘사(카메라·동작·소리)"를 넘긴다.
그래서 요청 단어 검사·연출 계획표 검사·방향 검사가 장면마다 그대로 돈다. 앞뒤 장면은 넣지 않는다: "지킬 것"은 반드시 지킬 말 검사에도 쓰여,
실내 고정 장면에 앞 장면의 비나 다음 장면의 빠른 줌을 요구하게 되기 때문이다 (11-17 검토).
장면 소리에는 음악 낱말을 쓰지 않지만, 화면에서 실제로 연주하는 악기(장면 동작에 나오는 피아노 등)의 소리는 된다.

**이어지는 장면**: 같은 장소에서 동작이 이어지면 앞 장면 클립의 마지막 프레임(레시피가 PNG 로 따로 저장)을 첫 화면으로 쓴다.
세 번 연속 이으면 네 번째는 새 장면 이미지로 바꾼다 (색·선명도 변화가 쌓이는 것을 막는 [추정] 값, 실측 뒤 조정).

**실패**: 장면 이미지·장면 영상 작업이 실패하면 그 작업만 시드를 바꿔 한 번 더 한다. 그래도 실패하면 요청이 실패하지만 만든 장면은 남는다.
실패 안내의 버튼은 늘 "다시 시도"다(같은 구성안, 남은 장면부터, 결과 파일 지문이 같은 장면만 다시 쓴다). 실패한 요청에 말로 "다시 만들기"를 해도 끝난 장면부터 잇는다.
승인한 적 없는 계획을 이어받으면 계획 카드를 다시 보인다(승인 없이 GPU 를 쓰지 않는다). 음악이 실패하면 음악 없이 합치고 안내한다.
긴 영상은 소리 포함 LTX 레시피로만 만든다: LTX 레시피가 꺼지면 소리 없는 Wan(5초)으로 바꾸지 않고 계획을 접는다.

### 7.3 합치기 (ffmpeg)

- 영상: 장면 클립을 다시 인코딩하지 않고 이어 붙인다 (concat, `-c copy`). 모두 같은 레시피·크기라 가능하다. concat 목록에 클립마다 영상 길이(`duration`)를
  적어, 소리가 영상보다 긴 클립이 있어도 다음 장면이 제때 시작한다 (적지 않으면 컷마다 화면이 멈추고 소리가 앞서 간다, 11-17 검토).
- 소리: 장면마다 길이를 영상 길이에 맞추고(apad·atrim), 크기를 고르게 한다(loudnorm -20 LUFS). 장면 경계에는 0.08초 페이드로 딸깍 소리를 막는다.
- 음악: -28 LUFS 로 깔고 처음 1.5초·끝 3초 페이드. 섞은 뒤 -14 LUFS(유튜브 기준), 최고 -1.5 dBTP. 소리는 AAC 192k.
  중간 믹스는 32비트 실수 WAV 라 0 dBFS 를 넘는 피크가 잘리지 않는다. 마지막 맞춤은 측정값으로 고정 이득을 쓰려 하지만, 최고값이 -1.5 dBTP 를 넘으면
  loudnorm 이 스스로 시간에 따라 바뀌는 방식(dynamic)으로 넘어간다 (시험 믹스 둘 다 그랬다, 크기는 맞는다).
- 결과: 같은 요청의 결과 폴더에 `long_<요청 앞 8자>.mp4`. 길이가 장면 합계와 0.5초 넘게 다르면 실패로 본다.
- 허브 이미지에 ffmpeg 를 더한다 (`hub/Dockerfile`). `install/update.sh` 가 매번 `docker compose build hub` 를 하므로 다음 업데이트에 들어간다.

### 7.4 이어 받기·취소·진행

- 장면이 끝날 때마다 `work.scenes[i]` 에 클립·마지막 프레임 경로를 남긴다. 허브가 다시 시작되면 끝난 장면은 건너뛰고, 접수해 둔 작업은 다시 접수하지 않고 이어서 본다
  (ComfyUI client_id 가 장면·종류·시도마다 다르다: `studio-<요청>-i3a1`(장면 이미지) `v3a1`(영상) `m1`(음악)).
- 취소하면 지금 도는 작업만 멈춘다.
- 진행 카드 칩: 구성안 → 장면 → 음악 → 합치기. 글은 "장면 3/18 · 생성 45%". 전체 %는 (끝난 장면 + 지금 장면 진행) ÷ (장면 수 + 1).
- 예상 시간 [추정]: 장면마다 LTX 실행(레시피 추정식) + 장면 이미지 약 25초 + LLM 약 90초, 음악 약 40초, 합치기 약 30초. 3분(10초 장면 18개, 빠름)은 약 70~80분.

- 끝난 장면의 클립이 결과 폴더에서 없어졌거나 바뀌었으면(지문이 다름) 그 장면을 다시 만들고, 그 장면에서 이어지는 다음 장면도 다시 만든다 (첫 화면이 달라졌으므로).
