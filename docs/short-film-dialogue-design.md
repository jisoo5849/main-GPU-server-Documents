# 대사 있는 10분 단편 애니메이션 설계 초안 (2026-11-19)

채팅 스튜디오의 긴 영상(최대 3분, 대사 없음)을 넘어, **한국어 대사가 있는 약 10분짜리 단편 애니메이션 한 편**을 만드는 설계다.
구현 전 초안이며, F0 실측(7절)으로 모델 선택과 숫자를 고친다. 표시: [추정] 계산·짐작, [실측 필요] 메인에서 재야 함, [TBD] 사용자 결정 전.

## 0. 결론 먼저

- 가능하다고 본다. 다만 지금의 "요청 한 줄 → 자동으로 끝까지" 방식으로는 안 되고, **대사를 먼저 만들고 그 소리에 입을 맞춰 영상을 만드는**
  애니메이션 제작 순서(목소리 녹음 → 애니매틱 → 본 작업 → 후반)를 그대로 따라야 한다.
- 대사는 **한국어 음성 합성(TTS)으로 인물마다 고정된 목소리**를 만들고, 말하는 샷은 **소리 → 입 모양 영상 모델**(LTX-2.3 IA2V 또는 InfiniteTalk, 서버에 있음)로 만든다.
  행동·풍경 샷은 지금 쓰는 LTX-2.5 그대로다.
- 서버에 **없는 것은 한국어 TTS 하나**다. 후보 1순위는 Qwen3-TTS(Apache-2.0, 한국어, 목소리 설계·복제)이고, 설치와 한국어 청취 시험이 먼저다.
- 10분이면 샷 약 120개, GPU 약 7~12시간 [추정]이다. 사람이 확인하는 관문 4곳(대본·캐릭터와 목소리·애니매틱·최종 전)을 두고, 렌더는 밤에 돌린다.
- 필요한 새 화면은 채팅이 아닌 **제작실**(대본·캐스트·샷 목록·애니매틱·샷 하나만 다시 만들기)이다.

### 2.2 이 저장소에 이미 있는 것

- 긴 영상 흐름(`director._run_long`): 구성안 → 장면마다 계획표·첫 화면·영상 글·클립 → 음악 → 합치기. 이어 받기·취소·진행 표시가 있다.
- 장면 이음: 앞 클립 마지막 프레임 잇기, 디졸브·컷 섞기(`assemble.run(transitions=)`), 샷 크기 연속 검사(`shot_rank`).
- 연출 규칙: 손·접촉 동작 금지(`PHYSICS_RE`), 마지막 프레임 규칙(`ending`), 앞뒤 장면 정보(`scene_direction`), 화풍 한 줄(`story_style`).
- 소리: 장면 소리 크기 맞춤, 음악 깔기, -14 LUFS(유튜브) 맞춤.

### 2.4 F0 실측 1차 (2026-11-19, 메인 관리자 ComfyUI, 공식 템플릿)

같은 첫 화면(Z-Image Turbo 로 만든 2D 애니메이션풍 여자아이 정면 미디엄 클로즈업, 1280×704)과 같은 한국어 말소리 7초로 비교했다.
한국어 TTS 가 아직 없어서 말소리는 A(LTX-2.5 가 대사까지 만든 영상)에서 뽑아 B 네 가지에 똑같이 넣었다. 결과는 결과 폴더 `admin/main/2026-11-19/f0_dialogue/`.

| 방식 | 생성 시간 (7초 영상) | 크기 | 입-소리 상관 [거친 지표] | 말할 때/쉴 때 입 움직임 | 그림체·얼굴 |
|---|---|---|---|---|---|
| A LTX-2.5 대사 동시 생성 | 59초 | 1280×704, 24fps | 0.50 | 1.73배 | 유지 |
| B1 LTX-2.3 IA2V | **50초** | 1280×704, 24fps | 0.37 | **1.91배** | 유지, 입 모양이 또렷하게 바뀜("오" 모양 등) |
| B2 InfiniteTalk (한 인물, 177프레임 한 번에) | 261초 | 832×480, 25fps | 0.34 | 1.31배 | 유지 |
| B3 Wan2.2 S2V (4스텝, 2조각) | 78초 | 832×464, 16fps | 0.42 | 1.29배 | 대체로 유지, 입 움직임이 작음, 소리보다 3초 길게 나옴 |
| B4 HuMo 17B (177프레임) | 248초 | 832×464, 25fps | 0.36 | 1.33배 | **얼굴 크기·머리 모양·색이 바뀜** |

- 지표: 입 주변 고정 상자의 화면 변화와 말소리 크기(0.1초 단위)의 상관, 그리고 말하는 구간과 쉬는 구간의 입 주변 변화 비. 머리가 움직여도 값이 오르므로 순위의 참고로만 쓴다. 판정은 사용자가 소리를 켜고 본다.
- 1차 판단 [사용자 청취 전]: **B1(LTX-2.3 IA2V)가 1순위**다. 가장 빠르고, 720p 이고, 지금 쓰는 LTX 와 같은 계열이라 행동 샷과 화질·색이 맞고, 쉴 때와 말할 때의 입 차이가 가장 크다.
  InfiniteTalk 는 두 인물·긴 대사용 후보로 남긴다. HuMo 는 얼굴이 바뀌어서, S2V 는 16fps·작은 입 움직임이라 뺀다.
- 캐릭터 일관성: 기준 그림 한 장 + Qwen-Image-Edit 2511(int8, Lightning 4스텝)으로 웃는 클로즈업·3/4 옆모습·걸어오는 넓은 샷을 그렸고 세 장 모두 같은 아이로 보였다. 장당 6~17초(첫 장은 모델 올리기 포함). 결과 크기는 1392×752 라 영상 크기로 맞춰야 한다.
- 남은 F0: 한국어 TTS 설치·청취(4.4절), InfiniteTalk 두 인물 모드, 한국어 TTS 소리로 B1·B2 다시 비교.
- **사용자 결정 (11-19): 입 모양은 정확하지 않아도 되고 느려도 된다. 대화한다는 느낌만 주면 된다.** 그래서 대사 샷은 LTX-2.3 IA2V 로 정한다(가장 빠르고, 소리가 쉬는 곳에서 입이 멈춰 대화 느낌이 난다).
  InfiniteTalk·S2V·HuMo 는 쓰지 않는다. IA2V 가 안 되는 샷(예: 아주 긴 대사)은 LTX-2.5 I2V 에 "말하는 모습" 글만 주고 소리는 TTS 를 얹는 길로 대신한다.
- TTS 설치 첫 시도(11-19): ComfyUI-Manager 로 `ComfyUI-QwenTTS`(ailab, 등록소 v1.1.4, 노드 코드 GPL-3.0, 내부 사용) 설치가 실패했다.
  원인은 `runtime/models.yaml` 이 허브 연동 노드 폴더 `/opt/mgs/nodes`(읽기 전용)를 `is_default: true` 구역에 두어 custom_nodes 의 첫 경로가 된 것이다.
  Manager 는 그 첫 경로에 설치하므로 이 서버에서는 **모든 사용자의 Manager 노드 설치가 실패**하고 있었다. 연동 노드를 기본이 아닌 별도 구역(`mgs_nodes`)으로 옮겼다.
  같은 파일에 TTS 모델 폴더 키 `tts: TTS` 를 더했다. 모델은 공용 저장소 `TTS/Qwen3-TTS/<모델 이름>/` 에 미리 넣는다(실행 공간은 읽기 전용이라 노드가 받지 못한다).
  받을 모델: Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign 4.52GB, -1.7B-Base 4.54GB, Qwen3-TTS-Tokenizer-12Hz 0.68GB (Apache-2.0, 로그인 불필요, 11-19 Hugging Face API 로 확인).
- TTS 설치 결과(11-19): `runtime/models.yaml` 수정 반영 뒤 Manager 로 `ComfyUI-QwenTTS` 1.1.4 설치에 성공하고 노드 11개가 보인다.
  실행하면 두 가지 문제가 차례로 나왔다. ① 작업공간의 `transformers` 가 5.20.2 라 노드의 호환 코드가 실패("cannot import name 'Qwen3TTSTokenizerV1Config'") →
  관리자 작업공간에서 `transformers==4.57.3`, `tokenizers 0.22.2`(`huggingface_hub 0.36.2` 도 같이 내려감)로 내리자 해결(`constraints.txt` 에는 해당 줄이 없었음).
  ② GPU 로 실행하면 KV 캐시를 늘리는 `torch.cat` 에서 "out of memory"(할당 4.37GiB, CUDA 가 말하는 남은 양 34~42MiB, 그 순간 nvidia-smi 는 570MiB 사용)가 두 번 똑같이 났다.
  ComfyUI 가 GPU 여유를 미리 잡아 두고(comfy-aimdo 로 짐작 [미확인]) 모델 관리 밖의 노드가 쓸 몫이 없는 것으로 보인다.
  Advanced 노드에서 `device=cpu`, `precision=fp32` 로 돌리면 대사 한 줄(약 6초 분량)이 45초에 만들어졌다. 100줄이면 약 75분이라 본 제작 전에 GPU 로 돌릴 길(ComfyUI 실행 옵션의 VRAM 예약, 또는 TTS 만 따로 도는 작업)을 정해야 한다 [TBD].
- F1 1차 (11-19, 하나·민준 6샷 약 25초, 관리자 ComfyUI 수작업, 결과 `admin/main/2026-11-19/f0_dialogue/`):
  ① 목소리 B(5살 안팎 아이, 사용자 선택)의 첫 대사를 기준 소리로 삼아 같은 목소리로 새 대사를 복제(`AILab_Qwen3TTSVoiceClone_Advanced`, 참조 소리 + 참조 글)했고, 민준은 새로 설계한 남자아이 목소리의 첫 대사를 기준으로 복제했다. 대사 6줄이 CPU 로 180초(줄당 약 30초), 길이 2.9~4.8초. 같은 목소리로 들리는지는 사용자 청취 [미확인].
  ② 키프레임: 하나 기준 그림 1장, 민준은 Z-Image 로 1장 만든 뒤 Qwen 편집 2511 로 표정·방향만 바꿔 6장(하나는 왼쪽에서 오른쪽을, 민준은 오른쪽에서 왼쪽을 봄, 180도 규칙). 두 인물이 모든 컷에서 같은 얼굴·옷으로 보였다.
  ③ 대사 샷: LTX-2.3 IA2V 로 샷당 18~28초. 첫 시도는 프롬프트의 "friend off screen" 때문에 화면 가장자리에 상대 인물(한 컷에는 어른)을 지어내 그려서, "alone in the frame, no other people" 을 넣어 다시 만들었다(2차). 실제 장면 간 연결은 컷으로 이은 '대화하는 느낌'이 목표이고 입 모양은 정확하지 않아도 된다는 사용자 결정(D9)에 맞는다.
  ④ 교훈: IA2V 프롬프트에는 화면 밖 인물을 말하지 않는다(모델이 그려 넣는다). 대사 길이를 영상 길이(초 단위, 올림)로 맞춰 줘야 한다.
- F1 목소리 다듬기(11-19, 사용자 청취 결과): ① 민준의 첫 목소리는 "중후한 아저씨" 같다는 지적을 받았다. 원인은 설명에 "여자아이보다 낮고 둥근 목소리"를 넣은 것으로 보이며(말소리 높이 중앙값 약 239Hz, 새 후보는 348~444Hz), "6살, 높고 가볍고 맑다, 전혀 낮지 않다, 어른이 아니다"로 다시 설계한 M1 을 사용자가 골랐다.
  ② M1 을 기준으로 복제한 대사는 "아직 어색하다"였고 사용자가 어색한 곳은 **억양과 감정**이라고 했다. 복제는 기준 샘플의 말투를 그대로 따라가 감정을 바꾸기 어렵다.
  ③ 줄마다 목소리 설명에 감정 지시("무지개를 발견한 설렘, '무지개'에서 반가운 높낮이", "웃음 섞인 투정, 길게 끄는 말" 등)와 "자연스러운 어린이 속도"를 덧붙여 줄마다 설계하자 사용자가 "새 테이크가 낫다", 그중 하나의 첫 대사 테이크 2(`emo_S1_take2`)가 억양·감정에 가장 잘 맞는다고 했다. 새 대사는 이전보다 15~70% 길고 말소리 높이가 올랐다(하나 364~432Hz, 민준 327~400Hz).

## 3. 핵심 결정: 대사를 어떻게 만들까

| 길 | 방법 | 좋은 점 | 문제 |
|---|---|---|---|
| A. 영상 모델이 함께 만들기 | LTX 프롬프트에 대사를 따옴표로 넣는다 (11-16 시험) | 지금 바로 됨, 입 모양이 자연스러움 | 샷마다 목소리가 바뀜, 발음·문장을 고칠 수 없음, 길이를 맞출 수 없음, 여러 인물이면 말하는 사람이 바뀔 수 있음(LTX-2 보고) |
| **B. 음성 먼저 → 입 맞춤 영상 (권장)** | 인물마다 고정 목소리로 TTS → 그 소리로 말하는 영상(IA2V 등) | 목소리 일관, 대사 수정이 싸다(소리만 다시), 대사 길이가 샷 길이를 정함, 자막 시간이 정확 | 한국어 TTS 설치 필요, 입 맞춤 모델의 애니메이션·한국어 품질은 [실측 필요] |
| C. 사람이 녹음 | 사내 인원·성우 녹음 → B 와 같은 흐름 | 한국어 연기 품질이 가장 좋음 | 사람·장비·동의서 필요 |

- **B 를 기본으로 한다.** 실제 애니메이션도 목소리를 먼저 녹음하고 그 소리에 맞춰 그린다. 대사가 정해져야 샷 길이와 편집이 정해진다.
- C 는 B 와 흐름이 같아서 나중에 바꿔 끼울 수 있다. TTS 로 애니매틱을 만들고 마음에 들면 그대로, 아니면 사람 녹음으로 바꾼다(임시 녹음 → 본 녹음 방식).
- A 는 군중 웅성거림, 짧은 감탄("와!") 같은 배경 소리에만 쓴다.

## 4. 전체 흐름

```
① 기획        요청 → 이야기(로그라인·시놉시스) → 대본(장면·지문·대사·감정) → 샷 목록        ─▶ [관문 1: 대본 승인]
② 캐스팅      캐릭터 시트(전신·상반신·얼굴·표정) · 장소 기준 그림 · 화풍 · 인물별 목소리      ─▶ [관문 2: 캐릭터·목소리 승인]
③ 애니매틱    대사 TTS 전부 → 샷 길이 확정 → 샷마다 첫 화면(키프레임) → 정지 그림 + 대사 + 임시 음악 영상
                                                                                      ─▶ [관문 3: 애니매틱 승인]
④ 본 렌더     대사 샷: 첫 화면 + 대사 소리 → 입 맞춤 영상 / 반응·행동·풍경 샷: LTX-2.5 I2V / 중요한 샷은 테이크 2~3개
⑤ 후반        편집 타임라인 → 영상 잇기(컷·디졸브·J/L 컷) · 소리 4트랙 섞기(대사·환경음·효과음·음악) · 자막 · 음량
                                                                                      ─▶ [관문 4: 샷 검수 → 문제 샷만 다시]
⑥ 최종        mp4 + 자막 파일(SRT) + 샷별 원본(결과 폴더)
```

- 관문 3(애니매틱)이 비용을 가장 많이 아낀다. GPU 영상 생성(전체의 약 70% [추정]) 전에 이야기 흐름, 대사 길이, 구도를 10분 통째로 본다.
- 각 단계는 지금처럼 GPU 작업 하나씩 대기열에 들어간다. 그래서 다른 사람 작업이 사이사이 끼어들 수 있다(한 번에 한 작업 원칙 그대로).

### 4.1 기획: 이야기·대본·샷 목록

- LLM(qwen3.8:27b)이 단계별로 쓴다: 로그라인 → 시놉시스(막·시퀀스) → 대본 → 샷 목록. 단계마다 검사와 고쳐 쓰기를 둔다(구성안과 같은 방식).
- 대본은 사용자가 고칠 수 있어야 한다. 10분 대본(대사 약 100줄)은 채팅 카드에 다 안 들어가서 제작실에서 편집한다(6절).
- 대본 형식(예):
  - 예: `S03 산책로 / 낮` → 지문 `하나가 강아지 보리를 따라 언덕길을 뛰어오른다.` → `하나: (숨차게, 웃으며) 보리야, 같이 가!`
- 분량 맞추기: 대본 단계에서 대사 길이를 미리 잰다. 한국어 낭독 속도를 초당 약 5음절로 잡고 [추정, TTS 실측으로 고침], 장면 합이 목표(600초 ±10%)에 맞는지 검사한다.
- 10분 기준 예상 분량 [추정]:

| 항목 | 값 |
|---|---|
| 시퀀스 | 8개 (평균 75초) |
| 샷 | 약 120개 (평균 5초) |
| 대사 샷 / 반응 샷 / 행동·풍경 샷 | 약 65 / 20 / 35 |
| 대사 | 약 100줄, 줄당 평균 3초, 대사 시간 합 약 5분 |

### 4.2 캐스팅: 캐릭터·장소·화풍·목소리

**캐릭터 시트** (인물마다, 관문 2)
- 화풍 문장 + 외형 문장으로 정면 전신을 여러 장 뽑고 사용자가 고른다(Qwen-Image 2512 또는 Z-Image).
- 고른 그림을 기준으로 Qwen-Image-Edit 2511 이 3/4·옆·뒤 전신, 상반신, 얼굴, 표정 4가지(기쁨·슬픔·놀람·화남)를 만든다.
- 샷 크기별 기준을 따로 둔다. 참조가 전신이면 클로즈업도 전신으로 나왔기 때문이다(11-03 실측).
- 디자인 규칙: 인물끼리 머리색·옷 색·체격을 확연히 다르게 한다. 두 인물이 한 사람으로 합쳐지는 일이 있었다(10-27).
- 시그니처 3~4개(머리 모양, 옷 색, 소품)를 정하고 모든 샷에서 검사한다.

**장소 기준 그림**: 장소마다 넓은 샷 1장 + 반대 방향 1장(대화 장면의 맞은편 배경).

**목소리** (인물마다, 관문 2)
- 목소리 설계: 글 설명으로 목소리를 만든다(Qwen3-TTS VoiceDesign).
  - 예: "밝고 높은 7살 여자아이 목소리, 또박또박하지만 숨이 조금 섞임"
- 후보 3개를 같은 대사 3줄로 들려주고 사용자가 고른다.
- 고른 목소리의 샘플 소리(약 10초)와 그 글을 저장하고, 이후 모든 대사를 이 샘플로 복제(Base 모델)해서 목소리를 고정한다.
- 감정: 감정별 샘플(보통·기쁨·슬픔·화남)을 같은 설명으로 따로 만들어 두고 대사의 감정 지시에 맞는 샘플을 쓴다 [실측 필요: 감정 샘플끼리 같은 사람으로 들리는지].
- 실존 인물(연예인·직원) 목소리 복제는 하지 않는다. 사람 녹음(C)을 쓰면 본인 서면 동의를 받는다.

### 4.3 샷 목록과 대화 연출 규칙

| 샷 종류 | 예 | 첫 화면 | 영상 엔진 | 소리 |
|---|---|---|---|---|
| D 대사 | 한 인물이 말함 (미디엄 클로즈업~미디엄) | 캐릭터 기준 + 장소 기준 → Qwen 편집 | 입 맞춤 모델 (F0 에서 결정) | 대사 TTS (영상 소리는 버림) |
| R 반응 | 듣는 얼굴, 끄덕임 | 같음 | LTX-2.5 I2V ("입을 다물고 듣는다") | 상대 대사가 이어서 깔림(L 컷) |
| A 행동 | 걷기·뛰기·놀기 | 같음 또는 앞 샷 마지막 프레임 | LTX-2.5 I2V (지금 방식) | LTX 환경음·효과음 |
| E 풍경 | 장소 소개, 시간 경과 | 장소 기준 그림 | LTX-2.5 I2V | 환경음 |
| V 화면 밖 목소리 | 내레이션, 뒷모습·먼 샷 위 대사 | — | 다른 샷 위에 얹음 | TTS |

대화 연출 규칙 (샷 목록 검사로 강제한다)
- **한 샷에서 말하는 사람은 한 명**이다. 대화는 주고받는 샷(A 의 얼굴 → B 의 얼굴)으로 나눈다. 여러 인물이 함께 말하는 샷은 모델이 말하는 사람을 바꿀 수 있어서다.
- 투샷(두 인물이 함께 보임)은 한 명만 말하거나 아무도 말하지 않을 때만 쓴다. InfiniteTalk 여러 인물 모드가 F0 에서 통과하면 넓힌다. (11-24 통과: 두세 사람이 보이는 대사 컷, 13절)
- 말하는 인물의 얼굴은 화면 높이의 약 1/4 이상(미디엄 이상 가까이)이다. 입이 작으면 맞춤이 안 보이고 모델도 틀리기 쉽다 [추정].
- 대사 중에는 크게 걷거나 뛰지 않는다. 말하며 걷는 장면은 뒷모습·먼 샷 + 화면 밖 목소리(V)로 바꾼다.
- 대화 장면에서 두 인물의 좌우 자리를 고정한다(180도 규칙). 예: 하나는 늘 화면 왼쪽, 보리는 오른쪽.
- 긴 대사(약 8초 넘게 [추정])는 두 샷으로 나누고 사이에 반응 샷을 넣는다.
- 손·접촉 동작 금지, 마지막 프레임 규칙, 샷 크기 연속은 지금 긴 영상 규칙을 그대로 쓴다.

샷 길이: 대사 샷은 대사 소리 길이 + 앞 0.3초 + 뒤 0.5초 [추정]로 정한다. LTX 프레임 수(8n+1)에 맞춰 올림한다.

| **Qwen3-TTS** 12Hz 1.7B / 0.6B | 지원 (10개 언어) | 글로 설계(VoiceDesign), 약 3초 샘플로 복제(Base), 한국어 기본 목소리 있음(CustomVoice) | Apache-2.0 | 공식 보고서의 한국어 WER 약 1.74~1.76 (기계 받아쓰기 기준, 사람 평가 아님). ComfyUI 커뮤니티 노드 여러 개 |
| Fun-CosyVoice3 0.5B | 지원 (9개 언어) | 샘플 복제, 지시문 | Apache-2.0 로 알려짐 [원문 확인 필요] | |
| Chatterbox Multilingual | 지원 (23개 언어, `ko`) | 샘플 복제, 감정 세기 조절 | MIT | 결과 소리에 들리지 않는 워터마크가 들어감 |
| 제외 | XTTS-v2 (CPML, 비상업), F5-TTS 가중치 (CC-BY-NC) | | | 상업 불가 |

- F0 에서 세 후보를 같은 대사 20줄(어린이·어른, 감정 4가지, 숫자·영어 섞인 문장)로 만들어 사용자가 듣고 고른다. Claude 는 소리를 들을 수 없어서 판정은 사용자가 한다.
- 실행 위치: ComfyUI 커스텀 노드로 실행 환경 이미지에 넣고, TTS 도 GPU 작업으로 대기열을 거친다("모든 GPU 사용은 DB 를 거친다" 원칙). 모델 파일은 포털 "모델 추가"(model-inbox)로 넣는다.
- 작업 단위: 대사 한 줄마다 작업을 만들면 모델 올리기가 매번 붙으니, 한 인물의 대사를 묶어 한 작업으로 만든다 [실측 필요: 모델 올리는 시간].
- 글 다듬기: 숫자·영어·기호를 한글 읽기로 바꾼 뒤 TTS 에 넣는다.
  - 예: "3시" → "세 시", "OK" → "오케이"
- 발음 검사(자동): 만든 소리를 받아쓰기(ASR)해서 대본과 글자 차이를 잰다. 차이가 크면 다시 만든다. 서버에 받아쓰기 도구가 없어서 whisper 계열 설치가 필요하다 [TBD].
- 대사마다 테이크 2개를 만들어 두고, 애니매틱에서 사용자가 고를 수 있게 한다.

### 4.5 애니매틱 (관문 3)

- 대사 TTS 를 전부 만든 뒤 샷 길이를 확정한다.
- 샷마다 첫 화면(키프레임)을 만든다: Qwen-Image-Edit 2511 에 캐릭터 기준(image1) + 다른 인물(image2) + 장소 기준(image3)을 넣는다.
- 정지 그림을 샷 길이만큼 보여 주고 대사·임시 음악·자막을 깐 10분 영상을 ffmpeg 로 만든다. GPU 영상 생성은 아직 하지 않는다.
- 사용자는 여기서 대사 수정(그 줄만 TTS 다시), 샷 순서·길이 수정, 키프레임 다시 만들기를 한다. 고친 만큼만 다시 만든다.

## 12. 스튜디오 대사 영상 v1 (11-19 구현, 메인 시험 전)

11-19 숲길 단편(니키·푸토르, 95초)을 손으로 만든 순서를 채팅 스튜디오 안쪽 흐름으로 옮겼다. 사용자에게는 긴 영상 요청 하나다.

**언제 이 흐름으로 가나**
- 긴 영상(20초 넘게) 요청에 대화·대사 말이 있을 때다(`intent.wants_dialogue`). 따옴표 대사, "대화", "말하며", "묻고 답", "설명해 주" 같은 말을 본다.
- `STUDIO_DIALOGUE=true` 이고 목소리 설계·복제·입 맞춤·장면 이미지 레시피가 모두 켜져 있어야 한다. 아니면 지금까지의 긴 영상으로 만든다.

**흐름** (`director._run_long` 의 대사 갈래, 단계 칩: 구성안 → 목소리 → 장면 → 음악 → 합치기)
1. **구성안** (`video.write_dialogue_story`): 긴 영상 구성안에 인물마다 이름·목소리 설명, 장면마다 종류(`talk`·`shot`)·말하는 사람·대사·말투를 더한다. 검사(`dialogue_problems`)는 다음을 확인한다.
   - 말하는 장면에는 그 사람 혼자, 클로즈업 또는 미디엄 클로즈업이어야 한다.
   - 대사는 60자 안이어야 한다.
   - 실제 사람 목소리 흉내는 안 된다.
   - 말하는 장면은 앞뒤 장면과 이어 쓰지 않는다.
2. **계획 카드**: 목소리 목록과 장면마다 대사를 보인다. 녹음 전에 대본을 확인하라는 뜻이다. 대사 길이에 맞춰 장면 길이가 조금 바뀐다고 적는다.
3. **목소리** (`_dlg_voices`):
   - 인물마다 **기준 소리** 하나를 정한다. 라이브러리 인물(니키·푸토르)은 사용자가 승인한 기준 소리 파일(`voice_ref`)과 그 글(`voice_ref_text`)을 그대로 쓰고 새로 설계하지 않는다. 그 밖의 인물은 구성안의 `sample_ko`(그 인물이 할 법한 두 문장)를 `qwen3_tts_voice` 로 한 번 설계한다.
   - 그 소리를 기준으로 대사를 한 줄에 한 작업씩 녹음한다(`qwen3_tts_clone`). 기본은 기준 소리와 그 글을 함께 주는 **맥락 복제**(`STUDIO_VOICE_CLONE=icl`)이고, `xvector` 로 바꾸면 목소리 특징만 복제한다(아래 "목소리 시험" 참고).
   - 결과는 허브가 ffmpeg 로 앞뒤 무음과 작은 숨·잡음 꼬리(-50dB 아래)를 자르고 끝에 0.3초를 붙인다. 이 WAV 를 입력 폴더 `studio/<사용자>/<요청 8자>/` 에 둔다.
   - 녹음이 `4초 + 글자 × 0.45초` 보다 길면 늘어진 녹음으로 보고 시드를 바꿔 한 번 더 한다(숲길 L3 는 10초 대사가 32초였다). 설계한 기준 소리도 `4초 + 글자 × 0.5초` 보다 길면 한 번 더 설계한다(맥락 복제는 기준 소리와 글이 짝이라 소리를 자르지 못한다).
   - 녹음 길이에 맞춰 장면 길이를 고친다. 말하는 장면은 대사 + 1초(4~20초)이고, 화면 밖 목소리 장면은 대사 + 1초보다 짧지 않게 한다.
4. **인물 기준 그림** (`_dlg_casts`): 혼자 가까이 나오는 인물마다 Z-Image 로 반신 그림을 한 장 만든다. 말하는 사람과 듣는 얼굴이 해당한다.
5. **장면**:
   - **말하는 장면** (`_dlg_scene`):
     - 기준 그림을 Qwen 편집으로 장면의 첫 화면으로 고친다. 얼굴·옷은 그대로 두고 구도·표정·배경·바라보는 쪽만 바꾼다. 두 사람은 서로 마주 보게 한다.
     - 그 대사 WAV 로 입을 맞춘다(`ltx23_ia2v_talk`, LTX-2.3 IA2V). 글에는 늘 "alone in the frame, no other people" 이 들어간다.
   - **혼자 나오는 가까운 장면**(듣는 얼굴): 첫 화면만 같은 방식으로 만들고, 영상은 긴 영상 길(계획표 → 영상 글 → LTX-2.5)로 만든다.
   - **나머지 장면**: 긴 영상과 같다.
6. **음악**: 긴 영상과 같다(ACE-Step, 고친 장면 길이의 합).
7. **합치기** (`_dlg_finish` → `assemble.run_dialogue`):
   - 샷 사이는 디졸브 0.5초이고, 대사는 샷 시작 + 0.2초에 놓는다. 음악은 -14dB, 마지막에 -14 LUFS 로 맞춘다.
   - 말하는 샷은 대사 끝 + 0.9초에서 자른다(`trims`). IA2V 는 대사가 끝난 뒤 화면이 어두워진다.
   - 자막은 허브가 Pillow + 나눔고딕으로 투명 PNG 를 그려 덧씌운다(`assemble.render_subtitle`). 글꼴이 없으면 자막 없이 합치고 안내 한 줄을 붙인다.

**레시피 4개** (`hub/app/studio/recipes/`, 레시피 검사 V1~V13 통과)

| id | action | 내용 |
|---|---|---|
| `qwen3_tts_voice` | voice | Qwen3-TTS VoiceDesign 1.7B, CPU fp32, 한국어, 토큰 상한 자리 |
| `qwen3_tts_clone` | voice_clone | Qwen3-TTS VoiceClone 1.7B, 기준 소리(LoadAudio)와 그 글(`ref_text`) → 대사, CPU fp32. 복제 방식은 자리 `x_vector` (감독이 `STUDIO_VOICE_CLONE` 으로 넣는다) |
| `qwen_image_2512_scene` | scene_image | 공식 템플릿 `image_qwen_Image_2512` 의 Lightning 4스텝(1280×704 약 6초, 사용자가 이 그림을 화풍으로 골랐다). 인물 라이브러리의 인물이 나오는 대사 영상의 장면 첫 화면을 그린다 (아래 "화풍" 참고) |
| `ltx23_ia2v_talk` | talk | 공식 템플릿 `video_ltx2_3_ia2v` 에서 프롬프트 다듬기 노드 5개(Gemma 생성·스위치·미리보기)를 뺐다. 부정 글은 화풍과 상관없는 결함으로 바꿨다. 크기·길이·대사 소리 자리를 둔다. 판 2(11-20): 클립 가운데 프레임(검사 그림) 저장 |

- 목소리 레시피는 글이 영상 모델의 positive 로 가지 않으므로 `negative_source: none` 이다. 레시피 검사(V1·V4·V5)와 접수 직전 부정 자리 확인이 이를 받아들인다.
- 소리 입력 자리는 `input_audio` 이다. V12 표본은 `studio/_check/sample.wav` 이다.

**인물 라이브러리: 같은 인물·같은 그림체 (11-19)**

11-19 메인 첫 시험은 실사였고 인물도 손으로 만든 니키·푸토르와 달랐다. 인물 그림은 글에서 새로 그려지므로, 요청 글에 외형을 길게 써도
같은 얼굴이 되지 않는다. 그래서 이야기에 이미 정해진 인물은 `hub/app/cast_library.json` 에 두고 `hub/app/cast_lib.py` 가 다룬다.
- **언제:** 요청 글에 인물 이름(니키·푸토르, 영문 Niki·Putor 도)이 나오면 자동으로 쓴다. 이름이 없는 요청은 그대로다. 11-20 부터 **대사 없는 긴 영상도** 이름이 나오면 쓴다(구성안에 외형·그림체를 알리고, 장면 그림은 같은 레시피로 그린다). 대사 없는 영상의 구성안에는 이름 칸이 없어 모델에게 인물 id 를 라이브러리 id(`niki`·`putor`)로 쓰게 하고, 그래도 다르게 쓰면 외형 글이 라이브러리 외형과 거의 같은지(90% 이상)로 맞춘다. 20초 이하 한 컷 영상은 아직 쓰지 않는다.
- **구성안을 쓰기 전:** 구성안 지시문에 "이미 있는 인물" 글(이름·외형·그림체)을 붙여 모델이 인물을 다르게 쓰지 못하게 한다.
- **구성안이 나온 뒤:** 설정집의 같은 인물(이름 `name_ko` 로 맞춤)의 외형·목소리·목소리 후처리·기준 그림을 라이브러리 값으로 덮어쓴다.
  - 모델이 외형을 다르게 써도 최종은 라이브러리 값이다.
  - 그림체: 구성안이 실사이거나 그림체가 비어 있고 사용자가 "실사"를 말하지 않았으면 라이브러리 그림체로 바꾼다. 사용자가 말한 화풍(애니메이션 등)은 지킨다.
- **얼굴:** 기준 그림(`ref`, 결과 폴더 안의 상대 경로)이 있으면 말하는 얼굴·듣는 얼굴의 인물 기준 그림을 Z-Image 로 새로 그리지 않고 그 그림을 쓴다. 이후는 같다(Qwen 편집으로 장면 첫 화면, 입 맞춤).
  - 기준 그림 파일이 없으면 새로 그리고 `dialogue_cast_ref_missing` 기록을 남긴다.
  - 계획 카드에 "등록 인물"과 "그림체"가 보인다.
- **목소리:** 승인된 기준 소리 파일(`voice_ref`, 결과 폴더 안의 상대 경로)과 그 글(`voice_ref_text`)을 쓴다. 파일이 없으면 라이브러리의 목소리 설명(`voice`)으로 새로 설계하고 `dialogue_voice_ref_missing` 기록을 남긴다. `voice_fx: "bass"`(푸토르)는 11-19 사용자가 고른 "P5a + 저음 보강 + 낮고 느리게 + 약한 따뜻한 포화"를 ffmpeg 로 옮긴 후처리다(`assemble.VOICE_FX`).
  - 후처리는 대사 줄에만 걸고, 복제의 기준 목소리에는 걸지 않는다(두 번 걸리지 않게).
  - 기준 소리 파일: 푸토르 = 승인된 숲길 단편 L1 대사(15.35초), 니키 = 승인된 기준 목소리 `ref_niki_a`(6.62초). `admin/main/2026-11-19/cast/{putor,niki}_voice_00001.flac` (FLAC 무손실로 저장). `voice_ref_text` 는 그 소리가 말하는 글 그대로여야 한다.
- **대사 소리 크기:** 대사 줄마다 크기를 재서 -18 LUFS 로 맞춘다(`assemble.VOICE_LUFS`, 고정 이득 + 피크 보호). 인물끼리 크기가 같아지고 음악(-14dB)보다 확실히 크다.
  - 11-19 메인 시험 결과는 대사 구간이 음악 구간보다 4~6dB 높을 뿐이었다. TTS 원본이 작았고, 손으로 만들 때는 브라우저 압축기의 보정 이득이 약 +11dB 를 더해 줬다.
- **인물 추가:** `cast_library.json` 에 항목을 더한다. 외형 글은 45낱말 안, 영어이고 화풍 낱말에 'photograph' 를 넣지 않는다(실사로 읽힌다). 기준 그림은 결과 폴더에 두고 `ref` 에 상대 경로를 적고, 기준 소리와 그 글은 `voice_ref`·`voice_ref_text` 에 적는다. 파일 위치는 `STUDIO_CAST_FILE` 로 바꿀 수 있다.

한 영화 안의 모든 정지 그림과 영상 글이 같은 그림체를 지키게 하는 장치다. 라이브러리 인물이 나오면 대사가 있든 없든 똑같이 적용한다.

- **글 맨 앞에 같은 그림체 앞머리**("Semi-realistic digital painting, 2.5D concept art…")를 모든 Qwen 장면 그림 글에 붙인다.

- **아직 못 막는 것:** 영상 모델이 장면 사이에서 질감을 조금씩 바꾸는 것은 글로 막을 수 없다. 메인에서 같은 요청으로 대사 영상과 대사 없는 영상을 각각 만들어 비교해 본다. 라이브러리에 없는 인물의 대사 영상은 Z-Image(기준 그림·넓은 장면)가 섞이지 않고 한 계열이라 그대로 둔다. 20초 이하 한 컷 영상은 라이브러리를 쓰지 않는다.

**알려진 한계 (v1)**
- 복제한 목소리는 음색이 고정되는 대신 감정 지시가 약하다. 복제 모델은 말투 지시문을 받지 못하고, 기준 소리의 말투·속도를 따른다. 감정을 넓히려면 기준 소리 자체를 더 감정이 담긴 같은 음색의 소리로 바꾼다(사용자 11-19: "아까보다 나아졌다", 시험 2에서는 "감정이 없고 책 읽는 듯"). 대본 쪽은 감탄사·말줄임표로 감정이 드러나는 대사를 쓰게 했다.
- 두 사람 이상 나오는 장면은 긴 영상과 같이 글로 새로 그린다. 그래서 얼굴이 기준 그림과 조금 다를 수 있다. 숲길 단편에서 여러 장 참조 편집은 인물이 복제되기 쉬웠다.
- 장면 클립 안의 소리(새·바람 등)는 합칠 때 쓰지 않는다(대사와 섞이지 않게, 사용자 확인 설정). 배경 소리를 낮게 섞는 것은 다음 판에서 시험한다.
- 대사 녹음은 CPU 라 한 줄에 1~3.5분 걸린다. 대사 10줄이면 녹음만 약 20~35분이다.
- 저음 보강 후처리는 브라우저(WebAudio)에서 쓰던 사슬의 ffmpeg 근사다. 귀로 비교해 보고 다르면 `assemble.VOICE_FX` 를 고친다.

  - 고침: 장면 그림 레시피 `qwen_image_2512_scene`(Lightning 4스텝)을 더하고, 라이브러리 인물이 나오는 대사 영상은 넓은 장면의 첫 화면을 이 레시피로 그린다(`director._scene_image_recipe`). 글 맨 앞에 이야기의 그림체를 붙인다. 라이브러리의 그림체 문장도 "…fantasy film look" 에서 위 앞머리로 바꿨다. 레시피가 꺼져 있으면 지금까지처럼 Z-Image.
  - 화원: 장면 글에 장소를 구체적으로 쓰면 꽃밭이 제대로 나온다 (레시피 시험 그림: 장미 아치와 꽃밭, 나비).
- **푸토르가 젊은 남자 목소리로, 감정 없이 책 읽듯 나왔다** (사용자 11-19). 아래 "목소리 시험"에 원인과 고친 것이 있다.

**목소리 시험 (11-19, 메인 관리자 작업공간 ComfyUI)**

제가 소리를 들을 수 없어서 음높이·거칠기·무게 중심·말 속도를 브라우저에서 수치로 재어 사용자가 승인한 푸토르 대사와 견주었다. 같은 대사 3줄(위로·기쁨·생각)을 방식별로 녹음했다.

| 푸토르, 방식 | 음높이 중앙값(Hz) | 상위 10%(Hz) | 거칠기 HNR(dB) | 무게 중심(Hz) | 속도(글자/초) |
|---|---|---|---|---|---|
| 기준: 승인된 푸토르 대사 5줄(줄마다 설계) | 108 | 144 | 11.3 | 376 | 4.2 |
| 기준 소리 L1 (승인) | 87 | 109 | 10.2 | 316 | 4.3 |
| **A.** 시험 2 방식: 인사말로 새로 설계한 기준 + 특징만 복제 | 94~121 (평균 105) | **244** (한 줄은 394) | 10.6 | 274 | 5.8 |
| **B.** 승인된 기준 + 특징만 복제 | 95 | 146 | 10.0 | 330 | 5.9 |
| **C.** 승인된 기준 + 맥락 복제 | 88 | 113 | 8.1 | 353 | 5.4 |

- **원인 1: 기준 소리를 영상마다 새로 설계했다.** A 의 줄은 음높이가 높아졌다 낮아졌다 하고(상위 10% 가 244Hz), 한 줄은 400Hz 가까이 튀었다. 새로 설계한 기준 소리는 시드마다 음색이 크게 다르다(이 시험의 기준 소리는 무게 중심 160Hz 로 승인된 L1 의 316Hz 보다 훨씬 어두웠다). 승인된 소리를 기준으로 하면 줄마다 음높이가 79~99Hz 에 모인다.
- **원인 2: 기준 문장이 인사말이고 설명에 "Natural Korean speech, clear pronunciation. Emotion: calm and friendly, relaxed" 를 덧붙였다.** 손으로 승인받은 방식은 '목소리 설명 + Emotion: …' 한 줄과 인물다운 말이었다.
- **원인 3: 목소리 특징만 복제(`x_vector_only`)한다.** 복제 모델은 말투 지시문을 받지 못하고, 특징만 복제하면 모델의 평평한 기본 말투가 나온다. 기준 소리와 그 글을 함께 주면(맥락 복제) 기준 소리의 속도·쉼·음높이 움직임을 따른다.
- **원인 4: 대사 글이 설명문이다.** 대본이 감정 없는 설명 투였다.
- **고친 것:**
  1. 라이브러리 인물은 승인된 기준 소리(`voice_ref`+`voice_ref_text`)를 쓴다. 영상마다 같은 목소리다.
  2. 라이브러리가 아닌 인물은 구성안이 쓴 `sample_ko`(그 인물이 할 법한 두 문장)로 설계하고, 설계 지시문에서 위 문구를 뺐다(`video.voice_instruct`·`voice_sample`).
  3. 복제는 기본이 맥락 복제다(`STUDIO_VOICE_CLONE=icl`). 듣고 B(`xvector`)가 낫다면 설정만 바꾼다.
  4. 구성안 지시문에 "대사는 읽는 글이 아니라 말이다: 말투, 감탄사(허허·어머·아), 말줄임표, 물음표·느낌표로 감정을 드러내고 줄마다 길이와 감정을 달리한다" 를 넣었다.
- 니키는 B·C 가 비슷했다(음높이 278~288Hz, 길이 7.0~8.6초). 기준 소리는 승인된 `ref_niki_a` 이다.
- **사용자 청취 결과 (11-20): 푸토르와 니키 모두 C(승인된 기준 소리 + 맥락 복제)가 가장 적합하다.** 기본값 `STUDIO_VOICE_CLONE=icl` 을 그대로 둔다.
- **수치로 알 수 있는 것은 음높이·거칠기·무게 중심·속도의 안정성까지다.** 어느 쪽이 더 감정이 있고 나이에 맞게 들리는지는 사용자가 듣고 판단한다 (듣기 화면: 메인 관리자 ComfyUI 에셋 `vfix/` 폴더의 `M0xvec_`·`M1xvec_`·`M2icl_` 파일).

### 13.1 결정과 컷 규칙

- 사용자 결정(11-24): 세 사람이 함께 있는 장면은 대사 컷에도 "셋 모두 나오게".
- 사용자 확정 규칙(11-24, 다른 모든 규칙보다 앞선다): "대화 할 때는 대화를 주고받는 이들이 나와야 하고, 독백 씬에는 클로즈업이 나와야 해".
- 11-28 사용자 결정: 대화 컷은 서로 마주 보는 투샷 ("실제 영화 및 애니같은 연출", 고른 안 "마주 보는 투샷만"). 함께 나오는 규칙과 3명 한도는 그대로이고, 얼굴을 카메라 쪽으로 돌리지 않고 서로 3/4 로 마주 본다(13.7). 독백 클로즈업·한 사람 컷·끝 프레임 규칙은 그대로다.
- 4.3절의 "한 샷에서 말하는 사람은 한 명"은 그대로다. 4.3절이 "InfiniteTalk 여러 인물 모드가 F0 에서 통과하면 넓힌다"로 남긴 조건이 이번 실측(X1·X6)에서 처음 통과해, 듣는 사람이 같은 화면에 나온다.
- D9(대사 샷은 LTX-2.3 IA2V)는 혼자 컷에만 남는다(13.3).

| 대사 | 화면에 나오는 사람 | 샷 | 영상 레시피 |
|---|---|---|---|
| 한 사람에게 하는 말 | 말하는 사람, 듣는 사람, 그 자리의 나머지 (사람 3명까지) | 두 사람 미디엄 투샷, 세 사람 미디엄 그룹샷 | `wan21_infinitetalk_duo` (InfiniteTalk) |
| 모두에게 하는 말 | 그 자리의 사람 모두 (3명까지) | 같음 | 같음 |
| 독백 (혼잣말·생각·전화·관객에게, 그 자리에 없는 사람을 부름) | 말하는 사람 혼자 (같은 장소에 다른 사람이 있어도) | 클로즈업·미디엄 클로즈업 | `ltx23_ia2v_talk` 판 5 (LTX) |

- 듣는 사람은 입을 다문 미소로 듣는다 (`video.LISTEN_FACE`: 첫 화면 인물 입히기와 영상 글이 같은 말을 쓴다).
- 카메라는 고정이다. 구성안 규칙에서 "very slowly pushing camera" 를 뺐고, 대사 컷 샷 글의 카메라 움직임 말(push in·dolly·zoom·pan·tilt·track)을 지운다 (`video.still_shot`).
- 대화 컷의 샷 글은 사람 수에 맞춘다: 미디엄 크기가 아니거나 한 사람을 가리키는 샷 글은 미디엄 투샷·그룹샷으로 바꾼다 (`video.group_shot`).
  - 예: 'full shot' → 'medium group shot', 'medium shot of Beth at the table' → 'medium two-shot'.
- 독백의 샷 글이 클로즈업보다 넓으면 미디엄 클로즈업으로 바꾼다 (`video.close_shot`).
- 같은 사람들·같은 장소의 대화 컷만 앞 컷을 같은 화면으로 잇는다(continue, `video._same_talk_group`: 화면에 나오는 사람과 장소만 본다). 독백은 잇지도 이어지지도 않는다.
- 네 사람 이상이면 세 명만 둔다 (`video.GROUP_MAX`). 말하는 사람·듣는 사람이 먼저다. present 를 쓴 구성안은 나머지를 자리 차례 앞쪽부터 고른다 (`video._present_cut`·`_present_seats`, 13.5).
- 독백 컷의 장면 글은 말하는 사람만 쓴다. 다른 인물 이름, 가족·사람 말(mother·girl·the two of them …), 다른 성별 대명사, 모르는 고유명사가 든 문장은 검사가 고쳐 쓰게 하고 영상 글에서는 뺀다 (`video._speaker_only`).
  - 까닭: 화면 밖 사람의 이름이 그 사람을 그려 넣는다 (11-21 실험 R3).
  - they·them 은 같은 문장에서 가장 가까운 복수 명사가 물건·동물이면('gazes at fireflies as they dance') 그것을 가리키는 것으로 보고 넘긴다 (`video._other_mention`·`_thing_before`, `test_fb_01`). 몸 낱말(eyes·tears·hands …)은 세지 않는다. 사람만 하는 동작('watches them laugh'·'as they talk')이면 앞에 물건이 있어도 다른 사람이다 (`_people_act`).
- 말하는 사람이 그 장소에 없는 대사(문 밖·벽 너머·다른 방·전화)는 talk 가 아니라 목소리를 얹은 shot 이다. 그 사람을 그 장소에 그리지 않고(`offscreen` 표시), 그 말에 대답하는 컷에서도 그 사람은 그 자리에 없다.
  - present 를 쓴 구성안: 말하는 사람이 present 에도 characters 에도 없는 talk (`video._present_view`, 13.5).
  - 칸이 없는 구성안: 장면 글로 짐작한다 (`video._offscreen_voice`).
- 설정을 끄면(`STUDIO_DUO_TALK=false`) 12절 규칙 그대로다: 모든 대사가 말하는 사람 혼자 클로즈업(크기 2까지)이고, 자리 지도(13.6)도 쓰지 않는다.

### 13.3 왜 두세 사람 컷만 InfiniteTalk 인가

- X2: 같은 투샷을 LTX-2.3 IA2V 로 만들면 말하는 사람 입이 거의 움직이지 않았다.
- LTX 에는 화면의 여러 사람 가운데 누가 말할지 정하는 수단이 없다 (공개 이슈 https://github.com/Lightricks/ComfyUI-LTXVideo/issues/395 : 엉뚱한 인물이 말하거나 둘이 함께 말한다).
- InfiniteTalk 두 화자 모드는 마스크로 말하는 사람을 정하고, 무음 자리의 사람은 입을 다물고 들었다 (X1·X6·X9·X11~X13).
- 혼자 컷은 LTX 그대로다. D9 의 까닭(가장 빠르고 720p 이고, 말 없는 컷과 같은 LTX 계열이라 화질·색이 맞는다)이 그대로이고, InfiniteTalk 는 480p 로 그려 키워야 한다.

### 13.4 누구에게 하는 말인가 (`video._present_target`·`line_target`)

- 구성안은 대사 장면마다 `listener` 칸을 쓴다: 듣는 사람 id, "everyone"(모두에게), "nobody"(독백) (`video.DIALOGUE_EXTRA_DUO`, `dialogue_schema`). 규칙 글은 그 자리(present)에 있는 사람이나 동물만 듣는 사람이 될 수 있다고 적는다.
- 모델이 쓰는 비슷한 말도 받는다 (`video._read_listener`).
  - 예: 'Beth'·'베스' → 그 사람, themselves·monologue·N/A·아무도·on the phone → 독백, 모두·다들·the family → 모두에게.
  - 말하는 사람 자신(자기 id·자기 이름)은 독백이다.
- "nobody" 라고 분명히 적은 장면은 추정하지 않는다.
- present 를 쓴 구성안 (`video._present_target`, 13.5): 그 자리 여부는 그 자리 사람 P 로만 정한다.
  - 듣는 사람이 P 에 있으면 그 사람에게 하는 말이다. present 를 쓴 장면에서 듣는 사람이 present 에도 characters 에도 없으면 그 자리에 없는 사람(문 밖·다른 방·전화 너머)이라 독백(혼자 클로즈업)이다. 화면 밖 목소리와 같은 기준이고, 검사는 "nobody" 길을 먼저 적은 문구 하나로 고치게 한다 (13.5 검사, `test_s3_06`·`test_fc_01`).
  - 처음 명세(3차 명세 1.3)는 듣는 사람을 믿고 P 에 넣었다. 11-25 최종 직접 확인에서 문 밖에서 부른 엄마에게 하는 대답에 다락방에 없는 엄마가 그려져 바꿨다.
  - 칸이 비었거나 모르는 값이면 추정한다: (a) characters 의 다른 사람, (b) 같은 장소에서 가장 가까운 앞 대사(먼저 본다)나 뒤 대사의 다른 화자로, 그 사람이 P 에 있을 때만 (`video._present_partner`), (c) 그 밖에는 독백.
  - (b) 에 '요청이 대화일 때만' 조건을 두지 않는다. P 가 그 자리 여부를 정하므로 그 자리에 없는 사람을 고를 일이 없다.
- 칸이 없는 구성안(예비, `video.line_target`):
  - 듣는 사람이 그 순간 그 장소에 없으면 독백이다 (`video._here`). 예: 문 밖에서 부르는 엄마, 방금 뛰어나간 니키를 부르는 엄마.
  - 칸이 비었거나 모르는 값이면 추정한다. (a) 구성안이 characters 에 다른 사람을 적었으면 그 첫 사람. (b) 요청이 대화(`wants_exchange`)이면 같은 장소에서 가장 가까운 앞 대사(먼저 본다)나 뒤 대사의 다른 화자. 그 화자가 화면에 보이고 그 자리에 있어야 한다 (`video._line_partner`: 같은 사람이 이어 말한 줄은 건너뛰고, 화면 밖 목소리·떠난 사람·장소가 바뀌면 멈춘다). (c) 그 밖에는 독백.
- 같은 사람의 다른 모습으로 적은 듣는 사람은 그 장면에 보이는 모습으로 읽는다 (`video._look_here`, present 쪽은 `video._scene_present`).
- 구성안 검사(`video.dialogue_problems`)는 어긋나면 고쳐 쓰게 한다. present 를 쓴 구성안은 `_present_talk_problems`, 칸이 없는 구성안은 `_group_talk_problems` 이고 뜻은 같다.
  - 대화인데 듣는 사람이 characters 에 없으면 "the person spoken to must be in the shot".
  - 독백인데 두 사람 이상이거나 샷이 미디엄 이상이면 위반.
  - 모두에게 하는 말인데 그 자리 사람이 빠졌으면 그 사람을 더하게 한다.
  - 듣는 사람으로 적은 사람이 그 자리에 없으면 "nobody" 로 고치게 한다. present 쪽은 문구 하나에 "nobody"(혼자 클로즈업) 길을 먼저, "장면들이 그 사람을 이 장소에 보일 때만" present 에 넣는 길을 뒤에 적는다.
  - 듣는 사람이 말하는 사람 자신이면 그것만 말하고, 모르는 값이면 추정한 사람을 넣으라고 하지 않는다.
  - 한 장면에 같은 사람의 두 모습이 있으면 위반.
- 다듬기(`video.clean_dialogue_story`)는 위반이 남아도 뜻을 살려 고친다. 대사 장면마다 `listener`·`monologue`·`to_all` 표시를, 이야기에 `duo_rules` 표시를, present 를 쓴 구성안이면 장면마다 `present` 를 남긴다.

### 13.5 그 자리에 있는 사람 (`present`, 11-25 "방식 바꾸기")

**바꾼 까닭**

- 2차에서는 코드가 장면 글(영어)의 떠남·들어옴·없음 말을 낱말 목록과 문장 꼴로 읽어 "지금 그 장소에 누가 있는가"를 짐작했다 (아래 '칸이 없는 구성안의 예비').
- 검토·확인을 네 번 하고 네 번 고쳤지만 지적이 14 → 17 → 23 → 28건으로 줄지 않았다. 고칠 때마다 흔한 문장이 새로 깨졌다 (28건 가운데 9건쯤이 바로 앞 고침에서 생겼다).
- 사용자 결정(11-25): "방식 바꾸기". 구성안을 쓰는 언어 모델(`settings.expand_model`, 기본 qwen3.8:27b)이 이야기를 이해하고 장면마다 그 자리에 있는 사람을 직접 적는다.
  - 코드는 그 칸만 보고 13.1 의 규칙을 지킨다. 검사는 칸끼리 맞는지만 본다. 어떤 검사도 장면 글을 읽어 그 자리 여부를 정하지 않는다.
  - 낱말 짐작은 칸이 없는 구성안(예전에 저장된 것, 모델이 칸을 빠뜨린 것)에만 쓰는 예비다. 예비 쪽은 더 넓히지 않는다.
- 같은 날 화풍도 같은 방식으로 바꿨다 (`docs/reference-system-design.md` 14.3).

**구성안 칸과 규칙 글**

- 두세 사람 규칙의 구성안 칸(`video.DIALOGUE_SCHEMA`)은 장면마다 `present` 를 요구한다: 그 장면 동안 그 장소에 있는 모든 사람·동물의 id (화면에 보이든 아니든). 꺼짐 칸(`DIALOGUE_SCHEMA_SOLO`)과 대사 없는 영상 칸(`STORY_SCHEMA`)에는 없다.
- 규칙 글(`video.DIALOGUE_EXTRA_DUO`)이 정하는 것:
  - characters(보이는 사람)는 늘 present 안에 있다.
  - 같은 장소의 뒤 장면에도, 떠나는 장면이 나오거나 없다고 적히기 전까지 present 에 남는다. 떠나는 사람은 그 장면까지, 들어오는 사람은 그 장면부터 present 다. 장소가 바뀌거나 시간이 뛰면 실제로 있는 사람부터 다시 적는다.
  - talk 의 말하는 사람은 늘 present 다. 그 장소에 없는 사람(문 뒤·다른 방·전화의 목소리)은 present 에 없고 shot 에서만 말한다. 대화 요청이어도 이런 목소리에게 talk 장면을 따로 요구하지 않는다.
  - listener 의 id 는 늘 present 안의 사람이다. 부르거나 대답하는 상대가 그 장소에 없으면(문 뒤·다른 방·전화·방금 떠남) 듣는 사람이 아니라 "nobody" 다 (fixC: 예전 줄 '듣는 사람은 늘 present' 는 그 자리에 없는 사람을 present 에 넣게 했다). "everyone" 은 present 의 모두다.
  - 대화 요청의 줄 수 규칙(`video.dialogue_count_rules`, 두세 사람 규칙)도 "그 장소에 있는 말하는 사람마다 talk 장면 하나(다른 방·전화 목소리는 필요 없음)" 로 같은 말을 한다.
  - 대화 줄의 characters 는 말하는 사람, 듣는 사람, present 의 나머지 차례로 사람 3명까지다.
- 예전에 대화 줄 괄호 안에 적던 짐작 설명(앞 장면의 사람은 떠나거나 없다고 적히기 전까지 그 자리에 있다)은 present 규칙으로 옮겼다.

**다듬기 (`video.clean_dialogue_story`)**

- 장면 하나라도 `present` 가 리스트면 그 구성안 전체를 이 방식으로 다듬는다 (`video.has_present`). 설정을 끄면 present 를 보지 않는다.
- 장면의 그 자리 사람 P (`video._present_view`·`_scene_present`): 쓴 present 가운데 설정집 인물 ∪ 이 장면 characters ∪ 말하는 사람(화면 밖 목소리가 아닐 때). 듣는 사람은 present 칸이 없는 장면에서만 더한다 (13.4: present 를 쓴 장면에서 present·characters 에 없는 듣는 사람은 그 자리에 없는 사람이다).
  - present 항목은 듣는 사람 칸과 같은 방식으로 읽는다 (`video._read_present`, fixC): id 그대로, 대소문자만 다른 id, 한 사람에게만 맞는 이름('베스'·'Beth'·'제임스' — 같은 사람의 두 모습이면 아래 차례로 모습을 고른다). 칸을 읽는 것이지 장면 글을 짐작하는 것이 아니다.
  - 그대로는 못 읽지만 이름이 한 사람에게만 들어 있는 항목('베스(엄마)')은 고칠 id 로 P 에 넣는다 (`video._written_present`, fixD). 검사는 그 id 를 쓰라고 하면서 그 사람을 그 자리에 있다고 본다. 예전에는 칸 검사만 그렇게 보고 P·대사 검사는 없다고 보아, 그 사람이 듣는 사람이면 같은 판에 'write the id "beth"' 와 '듣는 사람이 present 에 없다 → 혼자 클로즈업' 이 함께 나왔다. 독백 길을 따르면 같은 방의 엄마에게 하는 말이 혼자 클로즈업이 되어 다음 판에 그대로 통과했다 (G0 위반, 11-25 좁은 확인). 그 밖의 읽지 못한 항목은 P 에 넣지 않는다.
  - present 칸이 없는 장면은 characters·말하는 사람·듣는 사람만이다 (짐작하지 않는다).
  - 같은 사람의 두 모습(제임스 ↔ 안경 쓴 제임스)은 하나만 남긴다: 이 장면의 말하는 사람 → characters → 듣는 사람 칸에 쓴 모습을 먼저, 없으면 먼저 쓴 모습. 듣는 사람 칸의 모습은 present 를 쓴 장면에서도 모습 고르기에 쓴다 — P 에 넣지는 않는다 (`_scene_present` 의 prefer, fixC: 빠지면 present 에 먼저 쓴 안경 없는 제임스가 남아 잇기가 끊겼다). 대화 컷의 듣는 사람도 이 모습을 따른다 (`_present_target`).
    - 듣는 사람 칸이 화면 모습보다 뒤인 까닭: listener 에 'james' 만 적어도 화면의 안경 쓴 제임스를 이겨, 대화 컷 사이에 안경 없는 제임스가 끼고 잇기가 끊겼다 (`test_fb_03`).
- 화면 밖 목소리: talk 인데 말하는 사람이 쓴 present 에도 characters 에도 없으면 목소리를 얹은 shot 으로 바꾸고(`offscreen` 표시) P 에 넣지 않는다.
- 대화 컷 (`video._present_cut`): [말하는 사람, 듣는 사람] + 구성안이 characters 에 적은 나머지(동물도) + P 의 다른 사람. 사람 3명까지, 같은 사람은 한 모습이다. 동물은 3명에 세지 않고, 듣는 동물은 남는다.
  - P 의 다른 사람은 같은 장소 구간에서 적은 차례로 만든 자리 차례 앞쪽부터 고른다 (`video._present_seats`). 예: 넷이 있는 자리에서 모두에게 하는 말은 말하는 사람 + 자리 차례로 둘.
  - 모두에게 하는 말인데 P 에 다른 사람이 없으면 독백이다.
- 독백은 [말하는 사람] 혼자 클로즈업 그대로이고, 독백 샷 글 정리(`video._mono_shot`)도 그대로 쓴다. 이것은 그 자리 판정이 아니라 지시문 정리다.
- 다듬은 장면마다 P 를 `present` 로 남긴다. 뒤 단계가 쓴다.
- 이 방식에서는 장면 글로 그 자리 여부를 짐작하는 도우미(`_run_state`·`_presence`·`_here`·`_place_people`·`_listed_gone`·`_first_seen_here`·`_listed_voice_off`·`_offscreen_voice`·`_animal_here`·`_absent`·`_moves`)를 부르지 않는다. 시험(`test_s3_10b`)은 이 도우미들을 부르면 실패하게 바꿔 놓고 다듬기·검사·뒤 단계를 돌린다.

**검사 (`video.dialogue_problems` 의 `_present_field_problems`·`_present_talk_problems`)**

고쳐 쓰게 하는 문구는 영어이고 장면 번호가 붙는다.
- present 가 없는 장면 → present 를 쓰게 한다. 읽지 못한 항목 → 지적. 이름이 한 사람에게만 들어 있으면('베스(엄마)') 고칠 id 를 알려 준다 ('write the id "beth"', fixC). 그 사람은 칸 검사·P·대사 검사가 모두 그 자리에 있는 사람으로 본다 (fixD) — 듣는 사람이면 '듣는 사람이 그 자리에 없다' 대신 'put "beth" in "characters"' 가 함께 나온다.
- present 에 같은 사람의 두 모습이 함께 있다 → 이 장면이 보이는 모습 하나만 남기게 한다 (규칙 글 'never put both entries in one scene', fixC).
- characters 의 사람이 present 에 없다 → present 에 넣거나 characters 에서 빼게 한다. 그 사람이 듣는 사람이면 빼는 길을 끝까지 적는다(빼면 독백: "nobody", 혼자 클로즈업).
- talk 의 말하는 사람이 present 에 없다 → "the speaker must be in present", 다른 곳의 목소리는 shot 이다.
- 듣는 사람이 그 자리(P)에 없다 → 문구 하나만 낸다 (`video._listener_away_problem`, fixC): "nobody" 로 바꾸고 혼자 클로즈업(독백 길의 장면 글·샷 글이 다른 사람을 가리키면 그것도), 문 너머·다른 방·전화의 대답은 독백이라는 말, 그리고 "장면들이 그 사람을 이 장소에 보일 때만" present 에 넣고 대화 컷(characters 와 샷까지 적음)으로. 일반 독백 문구와 present 칸 문구를 같은 판에 함께 내지 않는다 (11-25 최종 확인: 한 판에 서로 반대로 시켰고, present 에 넣는 길을 먼저 적어 문 너머 엄마를 다락방 투샷에 들였다).
- 대화 줄: characters 가 말하는 사람 + 듣는 사람 + present 의 나머지(사람 3명까지)인지 본다. 더할 사람은 남은 자리만큼만 말한다 (넷 이상이면 'add one more person from "present" (…)').
- 모두에게 하는 말: present 의 사람(3명까지)이 모두 characters 에 있어야 한다.
- 독백: characters 가 [말하는 사람], 샷은 클로즈업까지, 장면 글·샷 글에 다른 사람 없음 (13.1 그대로).
- 대화 요청의 "말하는 인물마다 얼굴이 보이는 talk 장면" 규칙은 말한 줄이 모두 그 장면의 P 밖에서 나온 화자(목소리 shot·화면 밖 talk — 문 밖·다른 방·전화)에게 묻지 않는다 (fixC: 예전에는 '어느 장면의 present 에도 없는 화자'만 보아, 부엌에서 말없이 한 번 보인 엄마가 다락방에 목소리로만 말하면 문구가 나왔고 따르면 엄마를 다락방 present 에 넣게 됐다). 그 자리에 있으면서 목소리로만 말한 사람에게는 그 줄 가운데 하나를 talk 로 바꾸게 한다.

고쳐 쓰기 차례(`video.write_dialogue_story`·`write_story`, 3번까지)는 처음 messages(지시문·요청)에 마지막 답과 그 답의 문제만 붙여 보낸다 (`video.repair_turn`, fixC). 마지막 답은 읽은 JSON 을 빈칸 없이 다시 써서 보낸다. 앞 차례의 답과 문구를 모두 쌓으면 세 번째 차례가 계속 길어졌다.

그래도 3분 대사 구성안은 `HELPER_NUM_CTX`(12288)에 들지 않는다 (11-25 좁은 확인). 지시문이 '약 18장면(12~36)'·'10~13초에 한 줄'·'대사 장면 초 = 글자/6+1' 을 요구해 대사 장면이 15~22개가 되고, 길이 180±18초를 채우면 22장면을 넘기 쉽다. fixC 가 잰 9.3K~10.3K 는 장면 글이 짧은(action 약 10낱말) 18장면 기준이었다. 보통 길이(action 약 25낱말)로 다시 잰 고쳐 쓰기 차례(입력 + 이번 답, Qwen 토크나이저 근사)는 다음과 같다 (fixD 탐침 `ctx_fd.py`):

| 구성안 | 빈칸 없는 답 | 들여쓴 답 |
|---|---|---|
| 18장면 (143초) | 11,546 | 12,136 |
| 22장면 (156초) | 12,896 | 13,602 |
| 26장면 (177초) | 14,235 | 15,057 |
| 30장면 | 15,567 | 16,505 |
| 36장면, 장면 글이 낱말 상한 가까이 | 21,405 | 22,517 |

그래서 구성안 차례는 시작할 때 num_ctx 를 한 번 정해 그 차례의 모든 호출에 같은 값을 준다 (`video.story_num_ctx`·`story_options`, fixD). 같은 GPU 차례 안의 호출이 같은 값이라 모델을 다시 올리지 않는다.
- 값 = 지시문·요청(넉넉한 어림 `video.approx_tokens`: ASCII 3글자·한글 1글자에 1토큰) + 앞 답(빈칸 없음) + 고쳐 쓰기 문구(16개, 2,600) + 이번 답(들여씀). 답은 그 요청의 장면 수 상한(n_max)으로 센다: 대사 영상 장면 하나 들여씀 260·빈칸 없음 200, 대사 없는 영상 170·130, 장면 밖(bible·music) 1,200·900. 1024 단위로 올리고 `HELPER_NUM_CTX` 보다 작지 않다.
- 답 크기가 아니라 요청 길이와 지시문(라이브러리 인물 글·대화 규칙)으로 정해진다. 예: 3분 대사 영상(장면 상한 36)은 가족 3명 27,648·니키와 푸토르 26,624, 대사 없는 3분 영상(상한 26)은 15,360~16,384, 1분 대사 영상은 15,360~16,384, 1분 이하 대사 없는 영상은 12,288 이다.
- `HELPER_NUM_CTX` 가 0 이면(Ollama 기본값을 쓰라는 설정) 주지 않는다. 다른 허브 안 호출(도우미·제작진·영상 렌더러·결과 검사)은 그대로 `HELPER_NUM_CTX` 다.
- 시험 `test_fd_01` 은 18~36장면 구성안을 세 차례 돌려, 넉넉한 어림으로 센 가장 긴 차례가 그 값 안인지 본다 (36장면·낱말 상한 가까이는 어림이 JSON 을 약 1.3배로 세어 빼고, 근사 토크나이저로 위 표의 22.5K).

**뒤 단계**

- 다듬은 장면에 present 가 있으면 다음이 그것을 따른다. 없으면 예전 그대로다.
  - `video.scene_people`: present 에 있는 말하는 사람만 넣는다. 그 자리에 없는 목소리를 그 장소에 그리지 않는다.
  - `video.talk_group`: 독백 표시면 None 이고, present 안의 사람만 센다.
  - 자리 지도·자리 차례·바라보는 쪽(`_run_seats`·`group_order`·`_seat_order`·`layout_slots`·`facing_of`)은 scene_people·talk_group 으로 정해지므로 present 를 따른다.
  - 감독의 대사 컷 경로(`director._dlg_scene`: `video.talk_group`·`duo_talk`·`layout_slots`, 말하는 사람 칸 `_speaker_span`)도 같다.
- 앞 컷 잇기(`video._same_talk_group`)는 present 를 비교하지 않고 화면에 나오는 사람과 장소만 본다. 화면 밖 사람(넷 이상일 때 컷에 못 든 사람)이 그 사이에 나가거나 들어와도 끝 프레임은 바뀌지 않기 때문이다.

예 (떠남을 present 로만 적은 가족 아침 식탁, `test_s3_01`):

| 장면 | 구성안이 쓴 것 | present | 다듬은 결과 |
|---|---|---|---|
| 1 넓은 장면 | [베스, 제임스, 니키] | [베스, 제임스, 니키] | 그대로 |
| 2 베스 대사 | [베스, 제임스, 니키], listener everyone | [베스, 제임스, 니키] | 그대로, 모두에게 하는 말 |
| 3 말 없는 장면 | [니키], 'Niki grabs her school bag and waves goodbye.' | [베스, 제임스, 니키] | 니키는 이 장면까지 그 자리에 있다 |
| 4 베스 대사 | [베스, 제임스], listener 제임스 | [베스, 제임스] | [베스, 제임스], 미디엄 투샷 |
| 5 제임스 대사 | [제임스, 베스], listener 베스, 잇기 | [베스, 제임스] | [제임스, 베스], 앞 컷을 잇는다 |

- 'waves goodbye' 는 예비 낱말 목록에 없는 떠남이다. present 가 없으면 예비 짐작이 니키를 남겨 장면 4 가 세 사람 컷이 된다. 'Niki heads off to school' 도 present 로 적으면 같다.
- 반대로 '등교 준비를 하는 니키'·'학교에 간다' 장면 뒤에도 present 에 니키가 있으면 셋 모두 나온다 (`test_s3_02`). 장면 글이 '둘만 남았다'고 해도 present 가 이긴다 (`test_s3_03`).
- 다락방의 니키를 문 밖에서 부르는 엄마(present 에 엄마가 없음)는 목소리 shot 이 되고, 니키의 대답은 혼자 클로즈업이다 (`test_s3_04`).

**칸이 없는 구성안의 예비 (2차의 낱말 짐작, 넓히지 않는다)**

present 가 하나도 없는 구성안은 2차 규칙 그대로 장면 글로 짐작한다. 그 결과가 넷째 검토 고침 뒤와 같은지는 `test_s3_11` 이 본다.

- 대화 컷은 같은 장소·같은 시간 구간에서 앞서 화면에 나온 사람을 뒤에 더한다 (사람 3명까지, 동물은 세지 않는다, `video._place_people`·`_run_state`).
- 독백에는 사람을 더하지 않는다.
- 그 장소를 떠난 사람은 다시 나올 때까지 더하지 않는다 (`video._moves`).
  - 떠남: 'runs out the door'·'gets up and leaves'·'goes to school'·'sets off'·'인사하고 나간다'·'집을 나선다'·'학교에 간다'.
  - 떠남이 아님: 'goes off'(알람)·'run out of milk'·'looks out the kitchen door'·'slips off her chair'·'지나간다'·'이야기를 이어 나간다', 바람·부정·전하는 말.
  - 누가 떠나는지는 그 말의 주어로 본다.
  - 움직임의 목적지가 지금 장소면 들어옴이다 (예: 정원 장면의 'runs out into the garden').
- 없다고 적힌 사람도 뺀다 (`video._absent`).
  - 예: "Niki's chair is empty"·'while Niki sleeps upstairs'·'니키가 없는'·'둘만 남았다'.
- 화면 밖에서 들어온 사람은 넣는다 (예: 'Beth looks up as Niki walks in').
- 구간 앞에서 아직 나오지 않은 사람도, 뒤 장면에서 처음 보이는 장면이 들어오는 장면이 아니면 그 자리에 있던 것으로 본다 (`_first_seen_here`).
  - 이것은 모두에게 하는 말과 구성안이 말하는 사람만 적은 대화에만 쓴다. 대화면 그 뒤 장면에 말하는 사람이나 듣는 사람도 함께 나와야 한다.
  - 예: 부엌 구간 첫 장면의 '다녀왔습니다!'(모두에게 하는 말)는 다음 장면에 들어오는 말 없이 나오는 베스·제임스와 함께 그룹 컷이 된다.
  - 대화 상대를 직접 적은 컷(정원의 [베스, 니키])에는 나중 넓은 장면의 사람을 끌어오지 않는다.
- 같은 사람의 다른 모습은 한 사람으로 세어 그 장면이 적은 모습 하나만 남긴다. 이를 위해 `cast_lib.apply_to_story` 가 설정집에 `variant_of` 를 남긴다.

예 (present 가 없는 가족 아침 식탁 구성안을 예비 짐작으로 다듬은 결과):

| 장면 | 구성안이 쓴 것 | 다듬은 결과 |
|---|---|---|
| 1 넓은 장면 | [제임스, 베스, 니키] | 그대로 |
| 2 베스 대사 | [베스], listener 니키 | [베스, 니키, 제임스], 미디엄 그룹샷 |
| 3 니키 대사 | [니키], listener everyone | [니키, 베스, 제임스], 모두에게 하는 말 |
| 4 제임스 대사 | [제임스], listener nobody, 'medium shot', 'James glances at Beth …' | [제임스] 독백, 미디엄 클로즈업, 영상 글에서 베스 문장을 뺌 |
| 5 베스 대사 | [베스], listener 빈 칸 | 앞 대사의 제임스가 듣는 사람 → [베스, 제임스, 니키] |
| 6 말 없는 장면 | 'Niki grabs her bag and runs out the door' | 니키가 떠남 |
| 7 베스 대사 | [베스], listener 니키 | 니키가 그 자리에 없음 → 독백, 혼자 클로즈업 |
| 8 제임스 대사 | [제임스], listener 빈 칸 | 앞 대사의 베스 → [제임스, 베스], 미디엄 투샷 (니키는 이어 받지 않음) |

### 13.6 자리 차례 (180도 규칙)

- 같은 장소 구간마다 자리 지도를 만든다 (`video._run_seats`). 사람이 둘 이상 나오는 장면(넓은 장면·대사 컷)을 차례로 보며, 처음 함께 나온 장면의 좌우를 끝까지 지키고 새 사람만 끼워 넣는다.
  - 예: 13.5 예비 짐작 예(여덟 장면 식탁)의 넓은 장면이 [제임스, 베스, 니키] 라서, 그 뒤 대사 컷은 말하는 사람이 바뀌어도 제임스 왼쪽, 베스 가운데, 니키 오른쪽이다.
- 세 사람은 왼쪽이 오른쪽을, 가운데가 카메라를, 오른쪽이 왼쪽을 본다. 두 사람은 서로 마주 본다 (`video.layout_slots`).
- 구간에서 처음 함께 나온 장면의 좌우는 두 사람이면 1차 규칙(서로 마주 보는 좌우, `pair_facing`), 세 사람이면 그 장면에 적힌 차례다 (`video._seat_order`). `video.group_order` 도 같은 지도를 쓴다.
- 한 사람 컷(독백 클로즈업·기준 그림을 고친 첫 화면)의 시선은 같은 구간에서 가장 가까운 여럿 장면의 자리를 따른다 (`video.facing_of`). 왼쪽 자리는 오른쪽, 오른쪽 자리는 왼쪽, 가운데는 상대 쪽을 본다.
  - 예: 같은 예의 장면 4 제임스 독백은 오른쪽을, 장면 7 의 베스 독백은 장면 5 에서 말을 건넨 제임스 쪽(왼쪽)을 본다.
- 같은 사람의 다른 모습은 같은 자리다.
- 감독은 구도 그림과 같은 이 차례(`layout_slots`)에서 말하는 사람 칸(마스크 1)을 정한다 (13.8).
- 자리 지도는 두세 사람 규칙으로 다듬은 이야기(`duo_rules` 표시)에만 쓴다. 꺼짐·대사 없는 영상·1차 이야기는 1차 그대로다.

### 13.7 첫 화면과 영상 글

- 대화 컷의 첫 화면은 장면 잇기의 구도 그림 길로 그 사람들을 모두 그린다 (`docs/reference-system-design.md` 12절: ① 얼굴 없는 형상 → ② 두 사람 입히기 → ③ 세 번째 사람).
  - 구도 글(`video.layout_prompt`): 두 사람은 서로 마주 보는 투샷이다(11-28). 왼쪽 형상은 오른쪽, 오른쪽 형상은 왼쪽을 3/4 로 보고, 두 머리의 앞쪽은 카메라에 보인다. 세 사람은 나란히 앉거나 서고(InfiniteTalk 칸이 겹치지 않게, 13.8) 말하는 사람과 듣는 사람이 서로를, 나머지는 말하는 사람을 본다. 가운데 사람의 쪽은 `video._middle_facing` 이 정하고, 모두에게 말하는 가운데 사람·말 없는 넓은 장면만 예전처럼 카메라 쪽이다.
    - 옆얼굴(full side profile)·뒷모습은 막는다: 얼굴 입히기·소품 검사·입 맞춤이 얼굴과 입을 봐야 한다.
    - 11-24 판은 "두 얼굴 모두 카메라 쪽 3/4", "가운데는 카메라를 본다"였다.
  - 머리 위 여유(화면 높이의 약 10%)를 두고 머리를 키우지 않는다 (`_frame_hint`·`_group_heads`). 머리가 화면 맨 위에 붙은 첫 화면은 영상에서 잘렸다.
  - 인물 입히기 글(`_act_sentence`): 말하는 사람은 실제 자리에서 듣는 사람 쪽으로 말하고, 나머지는 입을 다문 미소로 듣는다. 시선은 `video.talk_facing` 한 문장이 자리로 쓴다(11-28): 두 사람은 "The person on the left looks toward the right and the person on the right looks toward the left: the two face each other in three-quarter view, eyes meeting; every face stays visible to the camera (no full side profile, no back view)." 세 사람은 말하는 사람과 듣는 사람이 마주 보고 나머지가 말하는 사람 쪽으로 돌아본다. 듣는 쪽이 동물이거나 모두에게 하는 말이면 사람들이 말하는 사람 쪽을 본다.
    - 고쳐 잇기(`cut_edit_prompt`)·바로 그리기(`compose_prompt`)·③ 마지막 사람(`finish_prompt`)도 같은 문장을 쓴다. 세 사람 고쳐 잇기의 자리 문장은 위에서 소개한 사람을 짧은 이름(외형의 머리 구절)으로 부른다: 시선 문장이 늘어 편집 글 상한(1990자)에서 장소 문장이 잘렸다.
  - 세 사람이면 ②·③ 단계마다 그 단계에서 입히는 사람의 표정만 쓴다 (아직 얼굴 없는 형상에게 표정을 주면 그 형상을 사람으로 그린다).
- 영상 글(`video.duo_talk_prompt`, 3000자 이내)은 모두를 자리와 외형으로 쓰고(왼쪽 …, 가운데 …, 오른쪽 …), 누가 누구에게 말하는지도 자리로 쓴다.
  - 듣는 사람: "only listens with lips closed and a gentle closed-mouth smile".
  - 시선: 첫 화면과 같은 `talk_facing` 문장 + "They keep these eye lines the whole time." (11-28)
  - 카메라 고정, 장소, 화풍 줄이 붙는다.
  - 장면 글(action)은 넣지 않는다: 화면 밖 인물 이름이 섞여 그 사람을 지어냈다 (11-21 R3).
  - 화면의 동물도 적고("Also in the frame"), 듣는 쪽이 동물이면 "speaks to the small red fox" 처럼 쓴다.
- 혼자 대사 컷 영상 글(`video.talk_prompt`)은 샷 글의 카메라 움직임 말을 지우고, 독백이면 다른 사람을 가리키는 문장을 뺀다.
- 동물이 말하는 컷은 혼자 대사 레시피(LTX)이고 그 자리 사람도 화면에 있다. 영상 글은 동물만 말하고 사람들은 입을 다물고 듣게 쓴다 (`video._animal_talk_prompt`).
- 듣는 쪽이 동물뿐인 대사는 사람 한 명 컷이라 혼자 대사 레시피로 만든다.

### 13.8 레시피 `wan21_infinitetalk_duo` (판 2, action `talk_duo`)

- 그래프는 메인에서 통과한 실험 그래프 그대로다: Wan2.1 I2V 14B 480p fp8(KJ) + `wan2.1_infiniteTalk_multi_fp16`(ModelPatchLoader) + lightx2v I2V 480p LoRA 6스텝 cfg 1, wav2vec2 중국어 base 인코더. 라이선스 Apache-2.0.
- 848×464 로 생성해 1280×704 로 키운다 (ImageScale lanczos, 가운데 자르기). 25fps.
- 프레임 수는 장면 길이 × 25 + 1 을 4n+1 로 올려 한 번에 만든다 (`recipes.frames_for`, Video Extend 없음, X10).
- 소리 자리: `audio` = 말하는 사람의 대사, `audio2` = 0.12초 무음 (`files.write_silence_wav`, 요청 폴더에 한 번 만든다).
- 마스크 1 = 말하는 사람 칸, 마스크 2 = 마스크 1 의 반전(InvertMask: 말하는 사람을 뺀 나머지 전체).
  - 칸: 사람 n 명을 생성 폭 848 에 같은 너비로 나눈 칸 가운데 말하는 사람의 k 번째 칸 (`director._speaker_span`: x = round(k·848/n), 너비 = round((k+1)·848/n) − x).
  - 그래프에서는 SolidMask(0, 848×464) 위에 SolidMask(1, 너비)를 MaskComposite(add, x) 로 놓는다. 자리 이름은 `speaker_x`·`speaker_w`.
  - 예: 두 사람의 오른쪽 화자는 x 424·너비 424, 세 사람의 가운데 화자는 x 283·너비 282.
- 나머지 전체를 무음 쪽으로 두는 까닭: ComfyUI `comfy/ldm/wan/model_multitalk.py` 는 두 마스크로 만든 `x_ref_attn_map` 의 argmax 로 화면의 모든 토큰을 화자 1 이나 화자 2 에 배정한다(L-RoPE, 배경 칸이 따로 없다). 두 마스크 밖의 세 번째 사람은 말하는 사람 소리에 묶일 수 있다.
- 노드는 두 소리를 자리 1 다음 자리 2 로 이어 붙인다(`multi_audio_type="add"`). 그래서 대사가 늘 0초에서 시작하고, 합치기는 혼자 대사 컷과 같다 (대사는 샷 시작 + 0.2초, 대사 끝 + 0.9초에서 자름).
- 판 1(1차, PR #45)은 좌우 반쪽 고정 마스크에 `audio` = 왼쪽 사람, `audio2` = 오른쪽 사람이었다. 오른쪽 사람이 말하면 무음이 앞이라 대사가 0.12초 늦게 시작해, 잇는 프레임과 합치기를 그만큼 늦췄다(`line_delay`). 판 2 에서 없앴다.
  - 1차로 만든 클립을 이어받은 요청은 합칠 때 그 클립의 `line_delay` 를 계속 읽는다 (소리가 입보다 0.12초 앞서지 않게).
  - 판이 다른 옛 두 화자 작업(`L{i}w_pending` 의 version)은 이어받지 않고 시도 번호만 잇는다.
- 레시피 검사 V6(`recipes._duo_problems`)이 보는 것:
  - 영상 노드 하나(two_speakers), 첫 화면 → start_image.
  - 대사 → audio_encoder_output_1, 무음 → mode.audio_encoder_output_2 (바뀌면 엉뚱한 사람 입이 움직인다).
  - 마스크 1 의 짜임과 `speaker_x`·`speaker_w` 자리, 마스크 2 = 마스크 1 의 InvertMask.
  - frames 자리 = length(4n+1), CreateVideo fps = defaults.fps.
  - `audio2`·`speaker_x`·`speaker_w` 자리는 `talk_duo` 레시피만 쓸 수 있다.
- 예상 시간은 X1 기준(약 301프레임 115초)으로 프레임 수에 비례한다 [추정].

### 13.9 설정·감독·내려가기 (`STUDIO_DUO_TALK`, `director._dlg_scene`)

- 설정 `STUDIO_DUO_TALK`(기본 켜짐, `.env.example`). 끄면 13.1 끝의 예전 규칙이다.
- 구성안을 두세 사람 규칙으로 쓸지는 요청마다 정한다 (`director._duo_ready`): 설정 켜짐, 장면 잇기 가능(`STUDIO_CHAIN` + `edit_ref` 레시피), `talk_duo` 레시피 켜짐, 가로 영상.
  - 하나라도 아니면 예전 혼자 클로즈업 규칙으로 쓴다. 투샷 첫 화면을 LTX 로 입 맞추지 않게 하려는 것이다 (X2).
- 대화 컷은 `talk_duo` 레시피로 만든다.
- 클립 검사는 가운데 프레임의 사람 수가 정확히 그 수(2·3)여야 한다 (`checks.clip_rule(duo=True)`).
  - 듣는 사람이 사라져도 다시 만든다 (fewer_ok 거짓).
  - 장면 글에 무리 말이 있으면 더 많아도 된다.
  - 얼굴 이상(말하는 입)은 보지 않는다 (`checks.DUO_TALK_SKIP`). 클로즈업 예외(`CLOSE_SKIP`)는 해당 없다.
- 아래 경우에는 LTX 대사 레시피로 내려간다. 영상 글·검사는 두세 사람 그대로이고, 사건 `duo_fallback` 을 남긴다.

| 까닭 (reason) | 언제 |
|---|---|
| off | 구성안을 쓴 뒤 설정이 꺼짐 |
| portrait | 세로·정사각 영상 (848×464 가로 생성을 가운데 자르면 사람이 잘린다. 구성안은 처음부터 혼자 규칙이라 대개 생기지 않는다) |
| recipe_off | 두 화자 레시피가 꺼짐 |
| solo_first_frame | 첫 화면이 기준 그림 한 장을 고친 한 사람 그림 (장면 잇기 없이 만든 컷) |
| failed | 두 화자 작업 실패 (run_error·run_oom·lost·no_output·run_timeout·gpu_prepare·submit) |

- 실패해 내려간 컷은 `duo_failed` 로 기억해, 허브가 다시 시작해도 두 화자 작업을 새로 접수하지 않는다. 다시 만들기가 지운다.
- LTX 로 내려간 투샷은 말하는 입이 거의 움직이지 않을 수 있다(X2). 영화를 잃지 않으려는 길이다.
- 사건 `long_scene_start`·`long_scene_done` 에 `duo`·`people` 을 남긴다.
- 운영자 기록 화면에 "두세 사람 대사(InfiniteTalk)"·"독백(혼자 클로즈업)"·"모두에게 하는 말"을 보인다 (`opview.long_view`).

### 13.11 한계

- 480p 생성을 1280×704 로 키우므로 LTX 컷(720p)보다 흐릴 수 있다 [실측 필요]. 1280×704 직접 생성(X8)은 46분·72GB 라 쓰지 않는다.
- 세로·정사각 영상은 두세 사람 대화 컷을 만들지 않는다 (구성안부터 혼자 규칙).
- X5a 처럼 말하는 차례가 바뀌는 순간 앞 사람 입이 따라 움직일 수 있다. 지금은 한 클립에 대사 한 줄이라 클립 안에서 차례가 바뀌지 않지만, 듣는 사람 입이 움직이는지는 자동 검사가 보지 않는다 (입 모양은 보지 않기로 함, 11-20).
- 클립 검사는 가운데 한 장만 본다.
- 동물이 말하는 컷은 LTX 혼자 대사 레시피인데 그 자리 사람도 나온다. 사람들의 입이 움직이지 않는지는 메인에서 본다.
- 그 자리 사람과 듣는 사람은 구성안 모델이 쓴 present·listener 를 믿는다. 모델이 이 칸을 제대로 쓰는지는 실제 구성안 모델(qwen)로 아직 보지 않았다.
  - 칸끼리 어긋나면 검사가 고쳐 쓰게 하지만, 칸끼리는 맞는데 틀린 값(예: 떠난 사람을 present 에 계속 둠)은 잡지 못한다.
  - present 를 쓴 장면에서 듣는 사람을 present 에도 characters 에도 적지 않으면 그 자리에 없는 사람으로 보아 독백(혼자 클로즈업)이다. 같은 방 사람을 빠뜨린 실수여도 같다. 검사 문구는 "nobody" 길을 먼저 적으므로, 모델이 그 길을 고르면 대화가 클로즈업으로 남는다.
  - 칸이 없는 구성안의 예비 짐작은 영어·한국어 문장 꼴을 보는 규칙이라 드문 표현은 놓칠 수 있다 (넓히지 않는다).
- 독백 글의 they·them 판정(13.1)은 문장 꼴 규칙이라 애매한 문장이 남는다. 예: 'Niki looks up from her books; they look so happy together.' 는 books 를 가리키는 것으로 본다.
- 네 사람 이상은 세 사람만 나온다. present 를 쓴 구성안은 나머지를 자리 차례 앞쪽부터 고르므로, 넷 가운데 오른쪽 끝 사람이 말하면 바로 옆 사람 대신 왼쪽 사람들이 나올 수 있다.
- 목소리로만 나오는 사람도 기준 그림을 만든다 (`video.anchor_ids` 는 그대로).
- 3분 대사 구성안 차례는 num_ctx 를 약 27K 로 올린다 (13.5). 그만큼 GPU 메모리가 느는지는 재지 않았다 (13.12).
- 운영자 기록 화면은 장면의 present 를 보이지 않는다.

### 13.12 메인에서 확인할 것 (`sudo` 가 필요한 일은 사용자가 한다)

1. 병합 뒤 메인에서 `cd /opt/mgs-src && sudo git pull origin main && sudo bash install/update.sh` (작업이 없을 때).
2. `cd /opt/mgs-src && sudo docker compose exec -T hub python -m app.cli studio-check wan21_infinitetalk_duo ltx23_ia2v_talk qwen_image21_edit_photo qwen_image_2512_scene qwen_image_2512_scene_quality` 로 V1~V13 통과를 본다 (뒤의 셋은 화풍 일반화의 레시피).
   - V10 은 모델 파일을 본다: Wan2_1-I2V-14B-480p_fp8_e4m3fn_scaled_KJ, wan2.1_infiniteTalk_multi_fp16, lightx2v_I2V_14B_480p_cfg_step_distill_rank64_bf16, wav2vec2-chinese-base_fp16, umt5_xxl_fp8_e4m3fn_scaled, Wan2_1_VAE_bf16 (11-24 실험에 쓴 파일).
   - V11 은 점이 든 입력 이름(`mode.audio_encoder_output_2`·`mode.mask_1`·`mode.mask_2`)이 통과하는지 본다.
3. `STUDIO_DUO_TALK` 는 `.env` 에 없으면 기본 켜짐이다. 끄려면 `STUDIO_DUO_TALK=false` 를 넣고 허브를 다시 시작한다.
4. 스튜디오에서 시험한다.
   - 가족 식탁 대화: 한 사람에게 하는 말과 모두에게 하는 말이 그룹샷인지.
   - 같은 자리의 독백: 혼자 클로즈업인지, 다른 사람이 그려지지 않는지.
   - 한 사람이 떠난 뒤의 대화: 남은 두 사람 투샷인지.
   - 문 밖 목소리: 그 사람이 그려지지 않는지, 그 목소리에 하는 대답이 혼자 클로즈업인지.
   - 세로 영상: 구성안부터 혼자 클로즈업 규칙인지 (두세 사람 대사 컷이 없어야 한다).
   - 구성안: 모델이 장면마다 present 를 쓰는지, 떠남·들어옴·문 밖 목소리가 present 에 맞게 적히는지 (어느 장면에도 present 가 없는 구성안은 예비 짐작으로 다듬는다).
   - 3분 대사 요청으로 구성안 고쳐 쓰기 차례의 문맥을 잰다: Ollama 응답의 `prompt_eval_count`(+`eval_count`)가 그 차례의 num_ctx(3분 대사 영상 약 26.6K~27.6K, 13.5 고쳐 쓰기 차례) 안인지. 근사 계산은 26장면 보통 길이 약 14.2K~15.1K, 36장면·낱말 상한 가까이 약 22.5K 다. 이 차례에 Ollama 가 모델을 한 번만 올리는지(같은 num_ctx), GPU 메모리(nvidia-smi)가 12288 차례보다 얼마나 느는지도 본다 [TBD: qwen3.8:27b 의 문맥 길이당 메모리는 아직 재지 않았다].
5. 볼 것: 듣는 사람 입이 닫혀 있는지, 말하는 사람 입만 움직이는지, 컷마다 자리가 같은지, 혼자 대사 컷의 머리가 끝까지 화면 안인지(판 5), 대사와 입이 맞는지, 컷당 시간과 480p 키우기의 흐림.
