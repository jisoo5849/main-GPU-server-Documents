# 대사 있는 10분 단편 애니메이션 설계 초안 (2026-11-19)

채팅 스튜디오의 긴 영상(최대 3분, 대사 없음)을 넘어, **한국어 대사가 있는 약 10분짜리 단편 애니메이션 한 편**을 만드는 설계다.
구현 전 초안이며, F0 실측(7절)으로 모델 선택과 숫자를 고친다. 표시: [추정] 계산·짐작, [실측 필요] 메인에서 재야 함, [TBD] 사용자 결정 전.

## 0. 결론 먼저

- 가능하다고 본다. 다만 지금의 "요청 한 줄 → 자동으로 끝까지" 방식으로는 안 되고, **대사를 먼저 만들고 그 소리에 입을 맞춰 영상을 만드는**
  애니메이션 제작 순서(목소리 녹음 → 애니매틱 → 본 작업 → 후반)를 그대로 따라야 한다.
- 대사는 **한국어 음성 합성(TTS)으로 인물마다 고정된 목소리**를 만들고, 말하는 샷은 **소리 → 입 모양 영상 모델**(LTX-2.3 IA2V 또는 InfiniteTalk, 서버에 있음)로 만든다.
  행동·풍경 샷은 지금 쓰는 LTX-2.5 그대로다.
- 서버에 **없는 것은 한국어 TTS 하나**다. 후보 1순위는 Qwen3-TTS(Apache-2.0, 한국어, 목소리 설계·복제)이고, 설치와 한국어 청취 시험이 먼저다.
- 10분이면 샷 약 120개, GPU 약 7~12시간 [추정]이다. 사람이 확인하는 관문 4곳(대본·캐릭터와 목소리·애니매틱·최종 전)을 두고, 렌더는 밤에 돌린다.
- 필요한 새 화면은 채팅이 아닌 **제작실**(대본·캐스트·샷 목록·애니매틱·샷 하나만 다시 만들기)이다.

### 2.2 이 저장소에 이미 있는 것

- 긴 영상 흐름(`director._run_long`): 구성안 → 장면마다 계획표·첫 화면·영상 글·클립 → 음악 → 합치기. 이어 받기·취소·진행 표시가 있다.
- 장면 이음: 앞 클립 마지막 프레임 잇기, 디졸브·컷 섞기(`assemble.run(transitions=)`), 샷 크기 연속 검사(`shot_rank`).
- 연출 규칙: 손·접촉 동작 금지(`PHYSICS_RE`), 마지막 프레임 규칙(`ending`), 앞뒤 장면 정보(`scene_direction`), 화풍 한 줄(`story_style`).
- 소리: 장면 소리 크기 맞춤, 음악 깔기, -14 LUFS(유튜브) 맞춤.

### 2.4 F0 실측 1차 (2026-11-19, 메인 관리자 ComfyUI, 공식 템플릿)

같은 첫 화면(Z-Image Turbo 로 만든 2D 애니메이션풍 여자아이 정면 미디엄 클로즈업, 1280×704)과 같은 한국어 말소리 7초로 비교했다.
한국어 TTS 가 아직 없어서 말소리는 A(LTX-2.5 가 대사까지 만든 영상)에서 뽑아 B 네 가지에 똑같이 넣었다. 결과는 결과 폴더 `admin/main/2026-11-19/f0_dialogue/`.

| 방식 | 생성 시간 (7초 영상) | 크기 | 입-소리 상관 [거친 지표] | 말할 때/쉴 때 입 움직임 | 그림체·얼굴 |
|---|---|---|---|---|---|
| A LTX-2.5 대사 동시 생성 | 59초 | 1280×704, 24fps | 0.50 | 1.73배 | 유지 |
| B1 LTX-2.3 IA2V | **50초** | 1280×704, 24fps | 0.37 | **1.91배** | 유지, 입 모양이 또렷하게 바뀜("오" 모양 등) |
| B2 InfiniteTalk (한 인물, 177프레임 한 번에) | 261초 | 832×480, 25fps | 0.34 | 1.31배 | 유지 |
| B3 Wan2.2 S2V (4스텝, 2조각) | 78초 | 832×464, 16fps | 0.42 | 1.29배 | 대체로 유지, 입 움직임이 작음, 소리보다 3초 길게 나옴 |
| B4 HuMo 17B (177프레임) | 248초 | 832×464, 25fps | 0.36 | 1.33배 | **얼굴 크기·머리 모양·색이 바뀜** |

- 지표: 입 주변 고정 상자의 화면 변화와 말소리 크기(0.1초 단위)의 상관, 그리고 말하는 구간과 쉬는 구간의 입 주변 변화 비. 머리가 움직여도 값이 오르므로 순위의 참고로만 쓴다. 판정은 사용자가 소리를 켜고 본다.
- 1차 판단 [사용자 청취 전]: **B1(LTX-2.3 IA2V)가 1순위**다. 가장 빠르고, 720p 이고, 지금 쓰는 LTX 와 같은 계열이라 행동 샷과 화질·색이 맞고, 쉴 때와 말할 때의 입 차이가 가장 크다.
  InfiniteTalk 는 두 인물·긴 대사용 후보로 남긴다. HuMo 는 얼굴이 바뀌어서, S2V 는 16fps·작은 입 움직임이라 뺀다.
- 캐릭터 일관성: 기준 그림 한 장 + Qwen-Image-Edit 2511(int8, Lightning 4스텝)으로 웃는 클로즈업·3/4 옆모습·걸어오는 넓은 샷을 그렸고 세 장 모두 같은 아이로 보였다. 장당 6~17초(첫 장은 모델 올리기 포함). 결과 크기는 1392×752 라 영상 크기로 맞춰야 한다.
- 남은 F0: 한국어 TTS 설치·청취(4.4절), InfiniteTalk 두 인물 모드, 한국어 TTS 소리로 B1·B2 다시 비교.
- **사용자 결정 (11-19): 입 모양은 정확하지 않아도 되고 느려도 된다. 대화한다는 느낌만 주면 된다.** 그래서 대사 샷은 LTX-2.3 IA2V 로 정한다(가장 빠르고, 소리가 쉬는 곳에서 입이 멈춰 대화 느낌이 난다).
  InfiniteTalk·S2V·HuMo 는 쓰지 않는다. IA2V 가 안 되는 샷(예: 아주 긴 대사)은 LTX-2.5 I2V 에 "말하는 모습" 글만 주고 소리는 TTS 를 얹는 길로 대신한다.
- TTS 설치 첫 시도(11-19): ComfyUI-Manager 로 `ComfyUI-QwenTTS`(ailab, 등록소 v1.1.4, 노드 코드 GPL-3.0, 내부 사용) 설치가 실패했다.
  원인은 `runtime/models.yaml` 이 허브 연동 노드 폴더 `/opt/mgs/nodes`(읽기 전용)를 `is_default: true` 구역에 두어 custom_nodes 의 첫 경로가 된 것이다.
  Manager 는 그 첫 경로에 설치하므로 이 서버에서는 **모든 사용자의 Manager 노드 설치가 실패**하고 있었다. 연동 노드를 기본이 아닌 별도 구역(`mgs_nodes`)으로 옮겼다.
  같은 파일에 TTS 모델 폴더 키 `tts: TTS` 를 더했다. 모델은 공용 저장소 `TTS/Qwen3-TTS/<모델 이름>/` 에 미리 넣는다(실행 공간은 읽기 전용이라 노드가 받지 못한다).
  받을 모델: Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign 4.52GB, -1.7B-Base 4.54GB, Qwen3-TTS-Tokenizer-12Hz 0.68GB (Apache-2.0, 로그인 불필요, 11-19 Hugging Face API 로 확인).
- TTS 설치 결과(11-19): `runtime/models.yaml` 수정 반영 뒤 Manager 로 `ComfyUI-QwenTTS` 1.1.4 설치에 성공하고 노드 11개가 보인다.
  실행하면 두 가지 문제가 차례로 나왔다. ① 작업공간의 `transformers` 가 5.20.2 라 노드의 호환 코드가 실패("cannot import name 'Qwen3TTSTokenizerV1Config'") →
  관리자 작업공간에서 `transformers==4.57.3`, `tokenizers 0.22.2`(`huggingface_hub 0.36.2` 도 같이 내려감)로 내리자 해결(`constraints.txt` 에는 해당 줄이 없었음).
  ② GPU 로 실행하면 KV 캐시를 늘리는 `torch.cat` 에서 "out of memory"(할당 4.37GiB, CUDA 가 말하는 남은 양 34~42MiB, 그 순간 nvidia-smi 는 570MiB 사용)가 두 번 똑같이 났다.
  ComfyUI 가 GPU 여유를 미리 잡아 두고(comfy-aimdo 로 짐작 [미확인]) 모델 관리 밖의 노드가 쓸 몫이 없는 것으로 보인다.
  Advanced 노드에서 `device=cpu`, `precision=fp32` 로 돌리면 대사 한 줄(약 6초 분량)이 45초에 만들어졌다. 100줄이면 약 75분이라 본 제작 전에 GPU 로 돌릴 길(ComfyUI 실행 옵션의 VRAM 예약, 또는 TTS 만 따로 도는 작업)을 정해야 한다 [TBD].
- F1 1차 (11-19, 하나·민준 6샷 약 25초, 관리자 ComfyUI 수작업, 결과 `admin/main/2026-11-19/f0_dialogue/`):
  ① 목소리 B(5살 안팎 아이, 사용자 선택)의 첫 대사를 기준 소리로 삼아 같은 목소리로 새 대사를 복제(`AILab_Qwen3TTSVoiceClone_Advanced`, 참조 소리 + 참조 글)했고, 민준은 새로 설계한 남자아이 목소리의 첫 대사를 기준으로 복제했다. 대사 6줄이 CPU 로 180초(줄당 약 30초), 길이 2.9~4.8초. 같은 목소리로 들리는지는 사용자 청취 [미확인].
  ② 키프레임: 하나 기준 그림 1장, 민준은 Z-Image 로 1장 만든 뒤 Qwen 편집 2511 로 표정·방향만 바꿔 6장(하나는 왼쪽에서 오른쪽을, 민준은 오른쪽에서 왼쪽을 봄, 180도 규칙). 두 인물이 모든 컷에서 같은 얼굴·옷으로 보였다.
  ③ 대사 샷: LTX-2.3 IA2V 로 샷당 18~28초. 첫 시도는 프롬프트의 "friend off screen" 때문에 화면 가장자리에 상대 인물(한 컷에는 어른)을 지어내 그려서, "alone in the frame, no other people" 을 넣어 다시 만들었다(2차). 실제 장면 간 연결은 컷으로 이은 '대화하는 느낌'이 목표이고 입 모양은 정확하지 않아도 된다는 사용자 결정(D9)에 맞는다.
  ④ 교훈: IA2V 프롬프트에는 화면 밖 인물을 말하지 않는다(모델이 그려 넣는다). 대사 길이를 영상 길이(초 단위, 올림)로 맞춰 줘야 한다.
- F1 목소리 다듬기(11-19, 사용자 청취 결과): ① 민준의 첫 목소리는 "중후한 아저씨" 같다는 지적을 받았다. 원인은 설명에 "여자아이보다 낮고 둥근 목소리"를 넣은 것으로 보이며(말소리 높이 중앙값 약 239Hz, 새 후보는 348~444Hz), "6살, 높고 가볍고 맑다, 전혀 낮지 않다, 어른이 아니다"로 다시 설계한 M1 을 사용자가 골랐다.
  ② M1 을 기준으로 복제한 대사는 "아직 어색하다"였고 사용자가 어색한 곳은 **억양과 감정**이라고 했다. 복제는 기준 샘플의 말투를 그대로 따라가 감정을 바꾸기 어렵다.
  ③ 줄마다 목소리 설명에 감정 지시("무지개를 발견한 설렘, '무지개'에서 반가운 높낮이", "웃음 섞인 투정, 길게 끄는 말" 등)와 "자연스러운 어린이 속도"를 덧붙여 줄마다 설계하자 사용자가 "새 테이크가 낫다", 그중 하나의 첫 대사 테이크 2(`emo_S1_take2`)가 억양·감정에 가장 잘 맞는다고 했다. 새 대사는 이전보다 15~70% 길고 말소리 높이가 올랐다(하나 364~432Hz, 민준 327~400Hz).

## 3. 핵심 결정: 대사를 어떻게 만들까

| 길 | 방법 | 좋은 점 | 문제 |
|---|---|---|---|
| A. 영상 모델이 함께 만들기 | LTX 프롬프트에 대사를 따옴표로 넣는다 (11-16 시험) | 지금 바로 됨, 입 모양이 자연스러움 | 샷마다 목소리가 바뀜, 발음·문장을 고칠 수 없음, 길이를 맞출 수 없음, 여러 인물이면 말하는 사람이 바뀔 수 있음(LTX-2 보고) |
| **B. 음성 먼저 → 입 맞춤 영상 (권장)** | 인물마다 고정 목소리로 TTS → 그 소리로 말하는 영상(IA2V 등) | 목소리 일관, 대사 수정이 싸다(소리만 다시), 대사 길이가 샷 길이를 정함, 자막 시간이 정확 | 한국어 TTS 설치 필요, 입 맞춤 모델의 애니메이션·한국어 품질은 [실측 필요] |
| C. 사람이 녹음 | 사내 인원·성우 녹음 → B 와 같은 흐름 | 한국어 연기 품질이 가장 좋음 | 사람·장비·동의서 필요 |

- **B 를 기본으로 한다.** 실제 애니메이션도 목소리를 먼저 녹음하고 그 소리에 맞춰 그린다. 대사가 정해져야 샷 길이와 편집이 정해진다.
- C 는 B 와 흐름이 같아서 나중에 바꿔 끼울 수 있다. TTS 로 애니매틱을 만들고 마음에 들면 그대로, 아니면 사람 녹음으로 바꾼다(임시 녹음 → 본 녹음 방식).
- A 는 군중 웅성거림, 짧은 감탄("와!") 같은 배경 소리에만 쓴다.

## 4. 전체 흐름

```
① 기획        요청 → 이야기(로그라인·시놉시스) → 대본(장면·지문·대사·감정) → 샷 목록        ─▶ [관문 1: 대본 승인]
② 캐스팅      캐릭터 시트(전신·상반신·얼굴·표정) · 장소 기준 그림 · 화풍 · 인물별 목소리      ─▶ [관문 2: 캐릭터·목소리 승인]
③ 애니매틱    대사 TTS 전부 → 샷 길이 확정 → 샷마다 첫 화면(키프레임) → 정지 그림 + 대사 + 임시 음악 영상
                                                                                      ─▶ [관문 3: 애니매틱 승인]
④ 본 렌더     대사 샷: 첫 화면 + 대사 소리 → 입 맞춤 영상 / 반응·행동·풍경 샷: LTX-2.5 I2V / 중요한 샷은 테이크 2~3개
⑤ 후반        편집 타임라인 → 영상 잇기(컷·디졸브·J/L 컷) · 소리 4트랙 섞기(대사·환경음·효과음·음악) · 자막 · 음량
                                                                                      ─▶ [관문 4: 샷 검수 → 문제 샷만 다시]
⑥ 최종        mp4 + 자막 파일(SRT) + 샷별 원본(결과 폴더)
```

- 관문 3(애니매틱)이 비용을 가장 많이 아낀다. GPU 영상 생성(전체의 약 70% [추정]) 전에 이야기 흐름, 대사 길이, 구도를 10분 통째로 본다.
- 각 단계는 지금처럼 GPU 작업 하나씩 대기열에 들어간다. 그래서 다른 사람 작업이 사이사이 끼어들 수 있다(한 번에 한 작업 원칙 그대로).

### 4.1 기획: 이야기·대본·샷 목록

- LLM(qwen3.8:27b)이 단계별로 쓴다: 로그라인 → 시놉시스(막·시퀀스) → 대본 → 샷 목록. 단계마다 검사와 고쳐 쓰기를 둔다(구성안과 같은 방식).
- 대본은 사용자가 고칠 수 있어야 한다. 10분 대본(대사 약 100줄)은 채팅 카드에 다 안 들어가서 제작실에서 편집한다(6절).
- 대본 형식(예):
  - 예: `S03 산책로 / 낮` → 지문 `하나가 강아지 보리를 따라 언덕길을 뛰어오른다.` → `하나: (숨차게, 웃으며) 보리야, 같이 가!`
- 분량 맞추기: 대본 단계에서 대사 길이를 미리 잰다. 한국어 낭독 속도를 초당 약 5음절로 잡고 [추정, TTS 실측으로 고침], 장면 합이 목표(600초 ±10%)에 맞는지 검사한다.
- 10분 기준 예상 분량 [추정]:

| 항목 | 값 |
|---|---|
| 시퀀스 | 8개 (평균 75초) |
| 샷 | 약 120개 (평균 5초) |
| 대사 샷 / 반응 샷 / 행동·풍경 샷 | 약 65 / 20 / 35 |
| 대사 | 약 100줄, 줄당 평균 3초, 대사 시간 합 약 5분 |

### 4.2 캐스팅: 캐릭터·장소·화풍·목소리

**캐릭터 시트** (인물마다, 관문 2)
- 화풍 문장 + 외형 문장으로 정면 전신을 여러 장 뽑고 사용자가 고른다(Qwen-Image 2512 또는 Z-Image).
- 고른 그림을 기준으로 Qwen-Image-Edit 2511 이 3/4·옆·뒤 전신, 상반신, 얼굴, 표정 4가지(기쁨·슬픔·놀람·화남)를 만든다.
- 샷 크기별 기준을 따로 둔다. 참조가 전신이면 클로즈업도 전신으로 나왔기 때문이다(11-03 실측).
- 디자인 규칙: 인물끼리 머리색·옷 색·체격을 확연히 다르게 한다. 두 인물이 한 사람으로 합쳐지는 일이 있었다(10-27).
- 시그니처 3~4개(머리 모양, 옷 색, 소품)를 정하고 모든 샷에서 검사한다.

**장소 기준 그림**: 장소마다 넓은 샷 1장 + 반대 방향 1장(대화 장면의 맞은편 배경).

**목소리** (인물마다, 관문 2)
- 목소리 설계: 글 설명으로 목소리를 만든다(Qwen3-TTS VoiceDesign).
  - 예: "밝고 높은 7살 여자아이 목소리, 또박또박하지만 숨이 조금 섞임"
- 후보 3개를 같은 대사 3줄로 들려주고 사용자가 고른다.
- 고른 목소리의 샘플 소리(약 10초)와 그 글을 저장하고, 이후 모든 대사를 이 샘플로 복제(Base 모델)해서 목소리를 고정한다.
- 감정: 감정별 샘플(보통·기쁨·슬픔·화남)을 같은 설명으로 따로 만들어 두고 대사의 감정 지시에 맞는 샘플을 쓴다 [실측 필요: 감정 샘플끼리 같은 사람으로 들리는지].
- 실존 인물(연예인·직원) 목소리 복제는 하지 않는다. 사람 녹음(C)을 쓰면 본인 서면 동의를 받는다.

### 4.3 샷 목록과 대화 연출 규칙

| 샷 종류 | 예 | 첫 화면 | 영상 엔진 | 소리 |
|---|---|---|---|---|
| D 대사 | 한 인물이 말함 (미디엄 클로즈업~미디엄) | 캐릭터 기준 + 장소 기준 → Qwen 편집 | 입 맞춤 모델 (F0 에서 결정) | 대사 TTS (영상 소리는 버림) |
| R 반응 | 듣는 얼굴, 끄덕임 | 같음 | LTX-2.5 I2V ("입을 다물고 듣는다") | 상대 대사가 이어서 깔림(L 컷) |
| A 행동 | 걷기·뛰기·놀기 | 같음 또는 앞 샷 마지막 프레임 | LTX-2.5 I2V (지금 방식) | LTX 환경음·효과음 |
| E 풍경 | 장소 소개, 시간 경과 | 장소 기준 그림 | LTX-2.5 I2V | 환경음 |
| V 화면 밖 목소리 | 내레이션, 뒷모습·먼 샷 위 대사 | — | 다른 샷 위에 얹음 | TTS |

대화 연출 규칙 (샷 목록 검사로 강제한다)
- **한 샷에서 말하는 사람은 한 명**이다. 대화는 주고받는 샷(A 의 얼굴 → B 의 얼굴)으로 나눈다. 여러 인물이 함께 말하는 샷은 모델이 말하는 사람을 바꿀 수 있어서다.
- 투샷(두 인물이 함께 보임)은 한 명만 말하거나 아무도 말하지 않을 때만 쓴다. InfiniteTalk 여러 인물 모드가 F0 에서 통과하면 넓힌다.
- 말하는 인물의 얼굴은 화면 높이의 약 1/4 이상(미디엄 이상 가까이)이다. 입이 작으면 맞춤이 안 보이고 모델도 틀리기 쉽다 [추정].
- 대사 중에는 크게 걷거나 뛰지 않는다. 말하며 걷는 장면은 뒷모습·먼 샷 + 화면 밖 목소리(V)로 바꾼다.
- 대화 장면에서 두 인물의 좌우 자리를 고정한다(180도 규칙). 예: 하나는 늘 화면 왼쪽, 보리는 오른쪽.
- 긴 대사(약 8초 넘게 [추정])는 두 샷으로 나누고 사이에 반응 샷을 넣는다.
- 손·접촉 동작 금지, 마지막 프레임 규칙, 샷 크기 연속은 지금 긴 영상 규칙을 그대로 쓴다.

샷 길이: 대사 샷은 대사 소리 길이 + 앞 0.3초 + 뒤 0.5초 [추정]로 정한다. LTX 프레임 수(8n+1)에 맞춰 올림한다.

| **Qwen3-TTS** 12Hz 1.7B / 0.6B | 지원 (10개 언어) | 글로 설계(VoiceDesign), 약 3초 샘플로 복제(Base), 한국어 기본 목소리 있음(CustomVoice) | Apache-2.0 | 공식 보고서의 한국어 WER 약 1.74~1.76 (기계 받아쓰기 기준, 사람 평가 아님). ComfyUI 커뮤니티 노드 여러 개 |
| Fun-CosyVoice3 0.5B | 지원 (9개 언어) | 샘플 복제, 지시문 | Apache-2.0 로 알려짐 [원문 확인 필요] | |
| Chatterbox Multilingual | 지원 (23개 언어, `ko`) | 샘플 복제, 감정 세기 조절 | MIT | 결과 소리에 들리지 않는 워터마크가 들어감 |
| 제외 | XTTS-v2 (CPML, 비상업), F5-TTS 가중치 (CC-BY-NC) | | | 상업 불가 |

- F0 에서 세 후보를 같은 대사 20줄(어린이·어른, 감정 4가지, 숫자·영어 섞인 문장)로 만들어 사용자가 듣고 고른다. Claude 는 소리를 들을 수 없어서 판정은 사용자가 한다.
- 실행 위치: ComfyUI 커스텀 노드로 실행 환경 이미지에 넣고, TTS 도 GPU 작업으로 대기열을 거친다("모든 GPU 사용은 DB 를 거친다" 원칙). 모델 파일은 포털 "모델 추가"(model-inbox)로 넣는다.
- 작업 단위: 대사 한 줄마다 작업을 만들면 모델 올리기가 매번 붙으니, 한 인물의 대사를 묶어 한 작업으로 만든다 [실측 필요: 모델 올리는 시간].
- 글 다듬기: 숫자·영어·기호를 한글 읽기로 바꾼 뒤 TTS 에 넣는다.
  - 예: "3시" → "세 시", "OK" → "오케이"
- 발음 검사(자동): 만든 소리를 받아쓰기(ASR)해서 대본과 글자 차이를 잰다. 차이가 크면 다시 만든다. 서버에 받아쓰기 도구가 없어서 whisper 계열 설치가 필요하다 [TBD].
- 대사마다 테이크 2개를 만들어 두고, 애니매틱에서 사용자가 고를 수 있게 한다.

### 4.5 애니매틱 (관문 3)

- 대사 TTS 를 전부 만든 뒤 샷 길이를 확정한다.
- 샷마다 첫 화면(키프레임)을 만든다: Qwen-Image-Edit 2511 에 캐릭터 기준(image1) + 다른 인물(image2) + 장소 기준(image3)을 넣는다.
- 정지 그림을 샷 길이만큼 보여 주고 대사·임시 음악·자막을 깐 10분 영상을 ffmpeg 로 만든다. GPU 영상 생성은 아직 하지 않는다.
- 사용자는 여기서 대사 수정(그 줄만 TTS 다시), 샷 순서·길이 수정, 키프레임 다시 만들기를 한다. 고친 만큼만 다시 만든다.

## 12. 스튜디오 대사 영상 v1 (11-19 구현, 메인 시험 전)

11-19 숲길 단편(니키·푸토르, 95초)을 손으로 만든 순서를 채팅 스튜디오 안쪽 흐름으로 옮겼다. 사용자에게는 긴 영상 요청 하나다.

**언제 이 흐름으로 가나**
- 긴 영상(20초 넘게) 요청에 대화·대사 말이 있을 때다(`intent.wants_dialogue`). 따옴표 대사, "대화", "말하며", "묻고 답", "설명해 주" 같은 말을 본다.
- `STUDIO_DIALOGUE=true` 이고 목소리 설계·복제·입 맞춤·장면 이미지 레시피가 모두 켜져 있어야 한다. 아니면 지금까지의 긴 영상으로 만든다.

**흐름** (`director._run_long` 의 대사 갈래, 단계 칩: 구성안 → 목소리 → 장면 → 음악 → 합치기)
1. **구성안** (`video.write_dialogue_story`): 긴 영상 구성안에 인물마다 이름·목소리 설명, 장면마다 종류(`talk`·`shot`)·말하는 사람·대사·말투를 더한다. 검사(`dialogue_problems`)는 다음을 확인한다.
   - 말하는 장면에는 그 사람 혼자, 클로즈업 또는 미디엄 클로즈업이어야 한다.
   - 대사는 60자 안이어야 한다.
   - 실제 사람 목소리 흉내는 안 된다.
   - 말하는 장면은 앞뒤 장면과 이어 쓰지 않는다.
2. **계획 카드**: 목소리 목록과 장면마다 대사를 보인다. 녹음 전에 대본을 확인하라는 뜻이다. 대사 길이에 맞춰 장면 길이가 조금 바뀐다고 적는다.
3. **목소리** (`_dlg_voices`):
   - 인물마다 **기준 소리** 하나를 정한다. 라이브러리 인물(니키·푸토르)은 사용자가 승인한 기준 소리 파일(`voice_ref`)과 그 글(`voice_ref_text`)을 그대로 쓰고 새로 설계하지 않는다. 그 밖의 인물은 구성안의 `sample_ko`(그 인물이 할 법한 두 문장)를 `qwen3_tts_voice` 로 한 번 설계한다.
   - 그 소리를 기준으로 대사를 한 줄에 한 작업씩 녹음한다(`qwen3_tts_clone`). 기본은 기준 소리와 그 글을 함께 주는 **맥락 복제**(`STUDIO_VOICE_CLONE=icl`)이고, `xvector` 로 바꾸면 목소리 특징만 복제한다(아래 "목소리 시험" 참고).
   - 결과는 허브가 ffmpeg 로 앞뒤 무음과 작은 숨·잡음 꼬리(-50dB 아래)를 자르고 끝에 0.3초를 붙인다. 이 WAV 를 입력 폴더 `studio/<사용자>/<요청 8자>/` 에 둔다.
   - 녹음이 `4초 + 글자 × 0.45초` 보다 길면 늘어진 녹음으로 보고 시드를 바꿔 한 번 더 한다(숲길 L3 는 10초 대사가 32초였다). 설계한 기준 소리도 `4초 + 글자 × 0.5초` 보다 길면 한 번 더 설계한다(맥락 복제는 기준 소리와 글이 짝이라 소리를 자르지 못한다).
   - 녹음 길이에 맞춰 장면 길이를 고친다. 말하는 장면은 대사 + 1초(4~20초)이고, 화면 밖 목소리 장면은 대사 + 1초보다 짧지 않게 한다.
4. **인물 기준 그림** (`_dlg_casts`): 혼자 가까이 나오는 인물마다 Z-Image 로 반신 그림을 한 장 만든다. 말하는 사람과 듣는 얼굴이 해당한다.
5. **장면**:
   - **말하는 장면** (`_dlg_scene`):
     - 기준 그림을 Qwen 편집으로 장면의 첫 화면으로 고친다. 얼굴·옷은 그대로 두고 구도·표정·배경·바라보는 쪽만 바꾼다. 두 사람은 서로 마주 보게 한다.
     - 그 대사 WAV 로 입을 맞춘다(`ltx23_ia2v_talk`, LTX-2.3 IA2V). 글에는 늘 "alone in the frame, no other people" 이 들어간다.
   - **혼자 나오는 가까운 장면**(듣는 얼굴): 첫 화면만 같은 방식으로 만들고, 영상은 긴 영상 길(계획표 → 영상 글 → LTX-2.5)로 만든다.
   - **나머지 장면**: 긴 영상과 같다.
6. **음악**: 긴 영상과 같다(ACE-Step, 고친 장면 길이의 합).
7. **합치기** (`_dlg_finish` → `assemble.run_dialogue`):
   - 샷 사이는 디졸브 0.5초이고, 대사는 샷 시작 + 0.2초에 놓는다. 음악은 -14dB, 마지막에 -14 LUFS 로 맞춘다.
   - 말하는 샷은 대사 끝 + 0.9초에서 자른다(`trims`). IA2V 는 대사가 끝난 뒤 화면이 어두워진다.
   - 자막은 허브가 Pillow + 나눔고딕으로 투명 PNG 를 그려 덧씌운다(`assemble.render_subtitle`). 글꼴이 없으면 자막 없이 합치고 안내 한 줄을 붙인다.

**레시피 4개** (`hub/app/studio/recipes/`, 레시피 검사 V1~V13 통과)

**인물 라이브러리: 같은 인물·같은 그림체 (11-19)**

11-19 메인 첫 시험은 실사였고 인물도 손으로 만든 니키·푸토르와 달랐다. 인물 그림은 글에서 새로 그려지므로, 요청 글에 외형을 길게 써도
같은 얼굴이 되지 않는다. 그래서 이야기에 이미 정해진 인물은 `hub/app/cast_library.json` 에 두고 `hub/app/cast_lib.py` 가 다룬다.
- **언제:** 요청 글에 인물 이름(니키·푸토르, 영문 Niki·Putor 도)이 나오면 자동으로 쓴다. 이름이 없는 요청은 그대로다. 11-20 부터 **대사 없는 긴 영상도** 이름이 나오면 쓴다(구성안에 외형·그림체를 알리고, 장면 그림은 같은 레시피로 그린다). 대사 없는 영상의 구성안에는 이름 칸이 없어 모델에게 인물 id 를 라이브러리 id(`niki`·`putor`)로 쓰게 하고, 그래도 다르게 쓰면 외형 글이 라이브러리 외형과 거의 같은지(90% 이상)로 맞춘다. 20초 이하 한 컷 영상은 아직 쓰지 않는다.
- **구성안을 쓰기 전:** 구성안 지시문에 "이미 있는 인물" 글(이름·외형·그림체)을 붙여 모델이 인물을 다르게 쓰지 못하게 한다.
- **구성안이 나온 뒤:** 설정집의 같은 인물(이름 `name_ko` 로 맞춤)의 외형·목소리·목소리 후처리·기준 그림을 라이브러리 값으로 덮어쓴다.
  - 모델이 외형을 다르게 써도 최종은 라이브러리 값이다.
  - 그림체: 구성안이 실사이거나 그림체가 비어 있고 사용자가 "실사"를 말하지 않았으면 라이브러리 그림체로 바꾼다. 사용자가 말한 화풍(애니메이션 등)은 지킨다.

**화풍 일관성 (11-20, 사용자: "화풍은 대사가 나올 때나 안 나올 때나 항상 같아야 한다")**

한 영화 안의 모든 정지 그림과 영상 글이 같은 그림체를 지키게 하는 장치다. 라이브러리 인물이 나오면 대사가 있든 없든 똑같이 적용한다.
- **정지 그림은 모두 Qwen 계열:** 넓은 장면·말 없는 장면은 장면 그림 레시피 `qwen_image_2512_scene`(Lightning), 말하는 얼굴·듣는 얼굴은 기준 그림을 Qwen 편집, 기준 그림 파일이 없어 새로 그릴 때도 같은 장면 그림 레시피다(`director._scene_image_recipe`). 이전에는 Z-Image 가 섞여 한 영화 안에서 디즈니·픽사풍과 회화풍이 갈렸다.
- **글 맨 앞에 같은 그림체 앞머리**("Semi-realistic digital painting, 2.5D concept art…")를 모든 Qwen 장면 그림 글에 붙인다.
- **영상 글 끝에 같은 화풍 고정 문장** `video.style_lock`("Keep exactly the look of the first frame in every frame: the same art style, the same colours and textures, never restyled.")을 말하는 장면(LTX-2.3 IA2V)과 말 없는 장면(LTX-2.5)에 똑같이 붙인다. 사진 화풍이면 붙이지 않는다.
- **확인한 것:** 두 영상 레시피의 부정 글은 다르지만(`ltx25_i2v_sound` 는 "cartoon, childish…", 입 맞춤은 결함만) 둘 다 증류 CFG 1 이라 부정 글이 화풍에 영향을 주지 않는다.
- **아직 못 막는 것:** 영상 모델이 장면 사이에서 질감을 조금씩 바꾸는 것은 글로 막을 수 없다. 메인에서 같은 요청으로 대사 영상과 대사 없는 영상을 각각 만들어 비교해 본다. 라이브러리에 없는 인물의 대사 영상은 Z-Image(기준 그림·넓은 장면)가 섞이지 않고 한 계열이라 그대로 둔다. 20초 이하 한 컷 영상은 라이브러리를 쓰지 않는다.

**알려진 한계 (v1)**
- 복제한 목소리는 음색이 고정되는 대신 감정 지시가 약하다. 복제 모델은 말투 지시문을 받지 못하고, 기준 소리의 말투·속도를 따른다. 감정을 넓히려면 기준 소리 자체를 더 감정이 담긴 같은 음색의 소리로 바꾼다(사용자 11-19: "아까보다 나아졌다", 시험 2에서는 "감정이 없고 책 읽는 듯"). 대본 쪽은 감탄사·말줄임표로 감정이 드러나는 대사를 쓰게 했다.
- 두 사람 이상 나오는 장면은 긴 영상과 같이 글로 새로 그린다. 그래서 얼굴이 기준 그림과 조금 다를 수 있다. 숲길 단편에서 여러 장 참조 편집은 인물이 복제되기 쉬웠다.
- 장면 클립 안의 소리(새·바람 등)는 합칠 때 쓰지 않는다(대사와 섞이지 않게, 사용자 확인 설정). 배경 소리를 낮게 섞는 것은 다음 판에서 시험한다.
- 대사 녹음은 CPU 라 한 줄에 1~3.5분 걸린다. 대사 10줄이면 녹음만 약 20~35분이다.
- 저음 보강 후처리는 브라우저(WebAudio)에서 쓰던 사슬의 ffmpeg 근사다. 귀로 비교해 보고 다르면 `assemble.VOICE_FX` 를 고친다.

**목소리 시험 (11-19, 메인 관리자 작업공간 ComfyUI)**

제가 소리를 들을 수 없어서 음높이·거칠기·무게 중심·말 속도를 브라우저에서 수치로 재어 사용자가 승인한 푸토르 대사와 견주었다. 같은 대사 3줄(위로·기쁨·생각)을 방식별로 녹음했다.

| 푸토르, 방식 | 음높이 중앙값(Hz) | 상위 10%(Hz) | 거칠기 HNR(dB) | 무게 중심(Hz) | 속도(글자/초) |
|---|---|---|---|---|---|
| 기준: 승인된 푸토르 대사 5줄(줄마다 설계) | 108 | 144 | 11.3 | 376 | 4.2 |
| 기준 소리 L1 (승인) | 87 | 109 | 10.2 | 316 | 4.3 |
| **A.** 시험 2 방식: 인사말로 새로 설계한 기준 + 특징만 복제 | 94~121 (평균 105) | **244** (한 줄은 394) | 10.6 | 274 | 5.8 |
| **B.** 승인된 기준 + 특징만 복제 | 95 | 146 | 10.0 | 330 | 5.9 |
| **C.** 승인된 기준 + 맥락 복제 | 88 | 113 | 8.1 | 353 | 5.4 |

- **원인 1: 기준 소리를 영상마다 새로 설계했다.** A 의 줄은 음높이가 높아졌다 낮아졌다 하고(상위 10% 가 244Hz), 한 줄은 400Hz 가까이 튀었다. 새로 설계한 기준 소리는 시드마다 음색이 크게 다르다(이 시험의 기준 소리는 무게 중심 160Hz 로 승인된 L1 의 316Hz 보다 훨씬 어두웠다). 승인된 소리를 기준으로 하면 줄마다 음높이가 79~99Hz 에 모인다.
- **원인 2: 기준 문장이 인사말이고 설명에 "Natural Korean speech, clear pronunciation. Emotion: calm and friendly, relaxed" 를 덧붙였다.** 손으로 승인받은 방식은 '목소리 설명 + Emotion: …' 한 줄과 인물다운 말이었다.
- **원인 3: 목소리 특징만 복제(`x_vector_only`)한다.** 복제 모델은 말투 지시문을 받지 못하고, 특징만 복제하면 모델의 평평한 기본 말투가 나온다. 기준 소리와 그 글을 함께 주면(맥락 복제) 기준 소리의 속도·쉼·음높이 움직임을 따른다.
- **원인 4: 대사 글이 설명문이다.** 대본이 감정 없는 설명 투였다.
- **고친 것:**
  1. 라이브러리 인물은 승인된 기준 소리(`voice_ref`+`voice_ref_text`)를 쓴다. 영상마다 같은 목소리다.
  2. 라이브러리가 아닌 인물은 구성안이 쓴 `sample_ko`(그 인물이 할 법한 두 문장)로 설계하고, 설계 지시문에서 위 문구를 뺐다(`video.voice_instruct`·`voice_sample`).
  3. 복제는 기본이 맥락 복제다(`STUDIO_VOICE_CLONE=icl`). 듣고 B(`xvector`)가 낫다면 설정만 바꾼다.
  4. 구성안 지시문에 "대사는 읽는 글이 아니라 말이다: 말투, 감탄사(허허·어머·아), 말줄임표, 물음표·느낌표로 감정을 드러내고 줄마다 길이와 감정을 달리한다" 를 넣었다.
- 니키는 B·C 가 비슷했다(음높이 278~288Hz, 길이 7.0~8.6초). 기준 소리는 승인된 `ref_niki_a` 이다.
- **사용자 청취 결과 (11-20): 푸토르와 니키 모두 C(승인된 기준 소리 + 맥락 복제)가 가장 적합하다.** 기본값 `STUDIO_VOICE_CLONE=icl` 을 그대로 둔다.
- **수치로 알 수 있는 것은 음높이·거칠기·무게 중심·속도의 안정성까지다.** 어느 쪽이 더 감정이 있고 나이에 맞게 들리는지는 사용자가 듣고 판단한다 (듣기 화면: 메인 관리자 ComfyUI 에셋 `vfix/` 폴더의 `M0xvec_`·`M1xvec_`·`M2icl_` 파일).
