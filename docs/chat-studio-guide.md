# 채팅 스튜디오 사용·운영 안내

설계는 `docs/chat-studio-design.md`(chat-studio-design 브랜치)에 있다. 이 문서는 구현된 P1~P4 를 쓰고 운영하는 방법만 적는다.
기본은 꺼져 있다(`STUDIO_ENABLED=false`). 코드를 올려도 켜기 전에는 아무에게도 열리지 않는다.

## 1. 사용자: 무엇을 할 수 있나

주소는 `http://<메인>/studio`. 상단 메뉴의 "스튜디오" 링크로도 들어간다. 글은 한국어로 쓰면 된다.

| 보내는 것 | 결과 |
|---|---|
| 글만 ("비 오는 밤 골목의 작은 카페") | 이미지 |
| 글만 + 영상 말 ("바다 위를 나는 드론 영상") | 글→영상. 기본은 **소리 포함**(효과음·배경음악, 최대 20초), 안쪽에서는 장면 이미지를 먼저 만들고 그 이미지로 영상을 만든다 (아래 참고) |
| 사진 + 글 (또는 사진만) | 사진으로 만드는 영상 |
| 사진 + 편집 말 ("이 사진을 수채화 스타일로 바꿔줘") | 편집한 이미지 |
| 이미지 결과 뒤 "이걸로 영상 만들어줘" 또는 [이걸로 영상 만들기] | 그 이미지로 영상 |
| 결과 뒤 "하나 더", [다시 만들기] | 같은 프롬프트로 시드만 바꿔 다시 |
| 이미지 결과 뒤 "더 밝게" | 원래 요청에 이번 말을 더해 새 이미지 |
| 영상 결과 뒤 "더 천천히" | 같은 첫 화면으로 새 영상 |
| 이미지 결과 뒤 "배경만 노을로 바꿔줘" | 편집한 이미지 |
| 글 + 20초 넘는 길이 ("비 오는 저녁 귀갓길 3분 영상", 길이 칸 30초~3분) | **긴 영상**: 장면 여러 개를 만들어 이어 붙이고 배경음악 한 곡을 깐다 (아래 참고) |
| 글 + 대화·대사 + 20초 넘는 길이 ("두 사람이 숲길을 걸으며 대화하는 1분 영상") | **대사 영상** (`STUDIO_DIALOGUE=true` 일 때, 11-19): 인물마다 목소리를 먼저 녹음하고, 말하는 장면은 그 소리로 입을 맞추고, 디졸브·대사·자막·음악으로 합친다. 계획 카드에 목소리와 대사가 보인다. 꺼져 있으면 긴 영상으로 만든다. 요청에 라이브러리 인물(니키·푸토르)의 이름이 있으면 정해진 외형·그림체·기준 그림·목소리로 만든다 (`docs/short-film-dialogue-design.md` 12절) |

- 입력창 위의 **길이**(2~20초), **소리**(자동·포함·없음), **화질**(빠름·높음), **비율**(가로·세로·정사각) 칸은 글에 쓴 지정보다 우선한다. **소리**: 자동은 소리 포함(LTX-2.5, 영상과 소리를 한 번에 만든다, 최대 20초, 화질 높음 없음), 없음은 소리 없는 영상(Wan 2.2, 5초까지). 글에 "소리 없이"가 있으면 없음으로, "음악 없이"는 소리 포함에서 음악만 뺀다. 소리 포함 영상의 음악은 영상 안에서 같이 만든다. 따옴표로 쓴 대사("안녕하세요")는 그대로 말하게 한다(한국어 발음은 확인 중). **화질 높음**도 소리 포함이 기본이다: 증류 없는 LTX-2.3 dev(1단계 30스텝·CFG 3.5 + 증류 LoRA 2단계 보정, 11-17 실측 10초 약 122초, 빠름 LTX-2.5 distilled 는 83초)로 만든다. 소리 칸을 없음으로 하면 소리 없는 Wan 높음(약 11분)이다. 높음은 늘 계획 카드를 거친다. 소리 포함 높음 레시피가 꺼져 있으면 높음을 고른 요청은 화질을 지켜 소리 없는 Wan 높음으로 만들고 안내 한 줄이 붙는다(소리 칸을 포함으로 직접 고르면 빠른 LTX 로 내려가고 그 안내가 붙는다). 앞 영상이 소리 없는 Wan 이면 "더 천천히" 같은 이어 말하기도 소리 없이 이어 간다. 길이는 영상, 비율은 이미지·글→영상에 적용되고, 사진으로 만드는 영상은 사진 비율을 따른다.
- **화질 "높음"**은 영상(이미지→영상·글→영상)과 이미지 편집에만 있다. 4스텝 가속을 끄고 기본 방식(영상 20스텝, 편집 40스텝)으로 돌려 장면을 더 정확히 따르고 "엉뚱한 물체·사람" 같은 부정 프롬프트가 실제로 적용된다. 영상은 해상도도 1024×576 으로 올린다(빠름은 848×480). 대신 **몇 분 이상 걸리고**(영상 약 9분 예상 [추정], 11-16 실측: 848×480 에서 약 6분) GPU 를 오래 쓰므로, 대화 설정과 상관없이 **늘 계획 카드로 예상 시간을 먼저 보이고 승인**을 받는다. 다시 만들기·이어 말하기("더 천천히")는 원래 요청의 화질을 이어 간다. 이미지 생성(Z-Image Turbo)은 가속 스위치가 없어 높음이 없고 빠름으로 만든다.
- 왼쪽 아래 **"긴 영상은 먼저 계획 확인"** 을 켜면 영상 요청마다 길이·크기·예상 시간을 카드로 먼저 보여 주고, [승인]해야 만든다. 카드가 떠 있을 때 "응"이라고 보내도 승인이다. 다른 말을 보내면 계획을 고친다. 24시간 답이 없으면 취소된다.
- 결과는 `\\main\results\studio\chat\<날짜>\<나>\` 에도 저장된다.
- **글→영상은 안쪽에서 두 단계**로 만든다: ① 요청 글로 장면 이미지(Z-Image) 한 장을 먼저 만들고 ② 그 이미지를 첫 화면으로 영상(Wan I2V)을 만든다. 글만으로 영상을 만들 때보다 구도·내부 디테일이 정확하다 (11-16 조종석 요청에서 T2V 가 손·핸들에 쏠린 문제). 사용자에게는 **한 작업**이다: 진행 카드 하나("프롬프트 작성 → 장면 준비 → 움직임 설계 → 생성 → 마무리"), 채팅에 나오는 결과는 영상 하나뿐이고 이미지라는 말은 나오지 않는다. 장면 이미지 파일은 결과 폴더에만 남는다. 계획 카드(화질 높음 등)는 예전 글→영상과 같은 모양(요약·프롬프트·길이·예상 시간)이다. 장면 이미지는 빠름(8스텝, 약 30초)이라 승인 전에 만들어 두고, 시간이 오래 걸리는 영상 생성은 승인한 뒤에 돈다. 다시 만들기는 저장된 프롬프트로 장면 이미지를 새로 만든다. 끄려면 `.env` 의 `STUDIO_T2V_VIA_IMAGE=false` (글만으로 영상). 장면 이미지는 화질 높음이 없어 빠름(8스텝)으로 만든다.
- 영문 프롬프트는 채팅 화면에도 결과 파일 메타데이터에도 남지 않는다 (D18).
- **긴 영상 (20초 넘게, 3분까지, 11-17)**: 글에 "3분", "1분 30초", "90초"처럼 쓰거나 길이 칸에서 30초~3분을 고르면 된다. 영상 모델은 한 번에 20초 한 컷까지라
  ① 구성안(제목·줄거리·인물과 장소의 고정된 모습·배경음악·장면표)을 먼저 쓰고 ② **계획 카드에 장면표를 보여 승인을 받는다**(대화 설정과 상관없이 늘, GPU 를 한 시간 넘게 쓰므로)
  ③ 장면마다 연출 계획표 → 첫 화면(같은 장소에서 이어지는 장면은 앞 장면의 마지막 프레임, 아니면 장면 이미지) → 영상(효과음 포함, 음악 없이)
  ④ 배경음악 한 곡(ACE-Step) ⑤ 이어 붙이기(장면 소리 크기 맞춤, 음악 섞기)를 한다. 결과는 영상 하나다. 진행 카드는 "구성안 → 장면 3/18 → 음악 → 합치기"로 보인다.
  카드가 떠 있을 때 다른 말을 보내면 구성안을 다시 쓴다. 장면이 두 번 실패하면 요청이 실패하지만 만든 장면은 남고, [다시 시도]는 남은 장면부터 만든다. [다시 만들기]는 같은 구성안으로 장면을 모두 새로 만든다(카드를 다시 보인다).
  사진으로 만드는 영상과 "소리 없이" 영상은 지금처럼 한 장면(20초·5초)이다. 3분(10초 장면 18개)은 빠름 기준 약 70~80분 걸린다 [추정]. 장면마다 GPU 작업을 따로 넣으므로 그 사이에 다른 사람·다른 요청의 작업이 끼어든다(같은 사용자는 `STUDIO_MAX_ACTIVE_PER_USER`, 기본 2건까지 함께 돈다).
  허브에 합치기 도구(ffmpeg)가 없는 판에서는 20초로 줄이고 안내한다. 장면 사이 인물 얼굴은 아직 완전히 같지 않다(다음 단계, `docs/long-video-design.md` 7.5).

## 2. 관리자: 켜는 순서

1. 코드 반영: `sudo git pull origin <브랜치> && sudo ./install/update.sh` (허브가 다시 만들어지므로 작업이 없을 때)
2. 채팅 전용 계정·작업공간 (한 번만, 설계서 7.2): `studio` 시스템 계정과 `studio-chat` 작업공간을 만들고 `studio` 로그인은 막는다.
3. 레시피용 모델 파일이 공용 저장소에 있어야 한다. 없으면 그 레시피는 허브 시작 검사에서 꺼진다.
4. `.env` 에 `STUDIO_ENABLED=true`, `STUDIO_ENV_SLUG=studio-chat`, `STUDIO_ALLOWED_USERS=<시범 사용자 로그인 이름들, 쉼표>` (비우면 모든 사용자에게 열린다) → 대기열을 일시 정지하고 `app.cli status` 의 `active` 가 0 이 되면 허브를 다시 만든다.
5. 확인: `docker compose exec -T hub python -m app.cli studio-check` — 레시피 V1~V13 이 모두 통과해야 한다.

### 2.1 레시피 (ComfyUI 워크플로우)

| id | 용도 | 템플릿 |
|---|---|---|
| `wan22_i2v_14b_fast` | 사진 → 영상 | Wan 2.2 14B Image to Video, 4스텝 LoRA (같은 이름 + `_quality` 는 가속을 끈 높음 변형. 빠른 레시피에서 자동으로 만들어지며 파일이 없다) |
| `wan22_t2v_14b_fast` | 글 → 영상 | Wan 2.2 14B Text to Video, 4스텝 LoRA |
| `ltx23_dev_i2v_sound_quality` | 사진·장면 이미지 → 영상 + 소리, **높음** | LTX-2.3 dev fp8 (증류 없이 1단계 30스텝·CFG 3.5, 부정 프롬프트 적용, 2단계는 증류 LoRA 0.5 로 3스텝 보정), 1280×704 24fps, 2~20초. 11-17 메인 실측 10초 122초 |
| `ltx25_i2v_sound` | 사진·장면 이미지 → 영상 + 소리 | LTX-2.5 22B distilled int8 (공식 템플릿 `video_ltx2_5_i2v` 를 API 형식으로 바꾼 것, 2패스 + 2배 업스케일), 1280×704 24fps, 2~20초. 11-16 메인 실측 5초 50초·10초 57초·20초 137초 |
| `zimage_turbo_t2i` | 이미지 | Z-Image Turbo, 8스텝 (메인 Export 기준, 판 2) |
| `qwen_image_edit` | 이미지 편집 | Qwen Image Edit 2511, 4스텝 LoRA |

새 레시피나 새 판을 넣는 법: studio-chat 의 ComfyUI(포트는 `create-env` 가 알려 준다)에서 템플릿을 열고 **내보내기 (API)** 로 JSON 을 받는다 → `app.cli studio-import 파일.json --id 이름 --action image|i2v|t2v|edit` 로 뼈대를 만들고 "사람이 확인할 것" 목록을 처리한다 → `version` 을 올리고 `studio-check` 로 검사 → 허브 재시작.
잇달아 접수가 3번 실패한 레시피는 허브를 다시 시작할 때까지 꺼진다 (`STUDIO_RECIPE_FAIL_LIMIT`).

허브 시작 때 검사(작업공간·레시피·모델 저장소·Ollama 모델)를 통과하지 못하면 `/studio` 는 503 안내이고, 허브를 다시 시작하지 않아도 30초에서 5분까지 간격을 늘려 가며 자동으로 다시 검사해 준비되는 대로 연다 (11-19). 모델 저장소가 비어 보이면 로그에 저장소 경로와 모델 파일 수가 남고, 계속 비어 있으면 그때 허브를 다시 시작한다.

### 2.2 설정 (`.env`)

| 항목 | 기본 | 뜻 |
|---|---|---|
| `STUDIO_ASK_LONG_SECONDS` | 300 | 계획 카드를 띄우는 예상 시간 기준(초). 0 이면 모든 영상 |
| `STUDIO_SOUND_DEFAULT` | true | 영상을 소리 포함(LTX-2.5)으로 만드는 것이 기본. false 면 소리 없는 Wan 이 기본 (화면의 소리 칸이 우선) |
| `STUDIO_T2V_VIA_IMAGE` | true | 글→영상을 장면 이미지 → 영상 두 단계로 (사용자에게는 한 작업). false 면 글만으로 영상 |
| `STUDIO_PLAN_TTL_HOURS` | 24 | 승인 없이 지나면 자동 취소 |
| `STUDIO_INSPECT` | idle | 결과 검사: on / idle(대기열에 다른 ComfyUI 작업이 없을 때만) / off |
| `STUDIO_CHAIN` | true | 장면 잇기 (11-20, `docs/scene-chaining-design.md`): 같은 샷이 이어지는 컷은 앞 장면 마지막 프레임 그대로 잇고, 그 밖의 사람 장면은 인물 기준 그림(자리가 남으면 장소 그림도)만으로 빈 화면에서 새로 그린다(`qwen_image_compose_ref`, 인물마다 알아볼 소품을 검사해 다섯 번까지 다시 그림, 11-21). 새로 그리기 레시피가 꺼져 있으면 앞 프레임을 고쳐 잇는다. 사람이 나오는 장면은 끝 키프레임을 영상 모델에 주고 끝 프레임에 인물이 있는지 늘 검사한다(STUDIO_PICTURE_CHECK 와 상관없이). 인물 기준 그림은 영화 화풍(반실사·애니·실사)에 맞춘다. 편집 레시피(`qwen_image_edit_ref`)가 꺼져 있으면 예전 방식(장면마다 새 그림)이다 |
| `STUDIO_REF_LAYOUT` | true | 구도 그림에서 그리기 (11-21, `docs/reference-system-design.md` 11·12절): 사람이 나오는 새 컷을 ① 장소 그림 위에 얼굴 없는 형상을 정확한 수·자리로 그린 구도 그림 → ② 그 그림에 인물 기준 그림의 얼굴·머리·옷을 입히기(세 사람 이상이면 ③ 한 명씩)로 그린다. 컷마다 같은 장소 그림을 써서 배경이 이어진다. 장소 그림이나 기준 그림이 없으면, 또는 false 면 기준 그림으로 바로 새로 그린다(`STUDIO_CHAIN` 의 방식) |
| `STUDIO_PICTURE_CHECK` | true | 긴 영상·대사 영상의 그림·클립 자동 검사 (11-20): 장면 그림·편집 그림·클립 가운데 프레임을 시각 모델로 보고 사람 수·몸의 이상·화풍이 틀리면 씨앗을 바꿔 다시 만든다 (그림 최대 두 번, 클립 한 번). 한 장 약 15초 |
| `CREW_CAST_MODE` | safe | 정본 인물 장면의 제작진 (11-26, `docs/crew-mode.md`): safe = 이미지·글→영상 장면 이미지 + 긴 영상·대사 영상의 영화 전체 초안 하나(설정집 빛·시간, 장소 그림 대기, 사람 없는 컷의 빛 계획), image = 이미지만, off = 예전처럼 건너뜀. 빛·시간·카메라·구도·색·대기·분위기만 고르고 모습·옷·손·소품·화풍은 정본 그대로. 메인 `.env` 에 키가 없어도 safe 로 켜진다 |
| `STUDIO_VOICE_CLONE` | icl | 대사 녹음의 복제 방식: icl(기준 소리와 그 글로 말투까지 따른다) / xvector(목소리 특징만) |
| `STUDIO_MAX_ACTIVE_PER_USER`·`STUDIO_MAX_OPEN_PER_USER` | 2 / 5 | 사용자당 동시 실행·열린 요청 |
| `STUDIO_LLM_WAIT_SECONDS` | 3600 | LLM 차례를 이만큼 못 받으면 실패 (점검·정지 시간은 세지 않음) |
| `TZ` | (없음) | 결과 폴더 날짜의 시간대. 한국 날짜로 하려면 `TZ=KST-9` (설계 D20, 메인에서 확인 뒤) |

### 2.3 로그인 첫 화면 (D1b)

기본은 `/` 로 들어오면 내 ComfyUI 가 열린다. 채팅을 첫 화면으로 쓰는 사용자는:

```bash
docker compose exec -T hub python -m app.cli --by <이름> set-home <사용자> studio
docker compose exec -T hub python -m app.cli --by <이름> set-home <사용자> comfy   # 되돌리기
```

스튜디오가 꺼져 있거나 시범 사용자가 아니면 설정과 상관없이 ComfyUI 로 간다. 채팅 화면의 "포털" 링크로 언제든 포털에 갈 수 있다.

## 3. 운영자 기록 화면

관리자 메뉴 옆 **"채팅 기록"** (`/admin/studio`). 요청마다 판단(규칙 번호), 첫 화면 읽기, 최종 프롬프트, 길이를 고른 이유, 걸린 검사, GPU 차례별 대기·실행·VRAM, LLM 차례가 끝난 이유, 결과·검사를 본다. 접수 검증 실패 같은 확인 필요 요청은 목록 위에 모인다. [API JSON 내려받기]는 접수 때 값으로 다시 만든 그래프로, ComfyUI 에서 열어 다시 실행해 볼 수 있다.
사용자 글과 AI 답은 글자 그대로만 보인다 (이스케이프 + 응답 헤더). 관리자만 열 수 있다.
정본 인물 영화(11-26)는 "제작진" 칸에 영화 전체 초안 기록(`film_crew`: 썼는지·회차·고른 항목·남은 위반)과 빛 계획이, 긴 영상의 "설정집·배경음악·제작진 빛 계획" 에 같은 빛 계획이 보인다.
메인에서 실제로 돌았는지는 이 기록과 "시스템 프롬프트" 칸의 제작진 지시문("You are a small production crew of experts preparing the shared look …")으로 본다.

## 5. 아직 하지 않은 것

- LLM 이 애매한 말의 의도를 판단하는 기능(R10)과 대화 제목 자동 만들기: 지금은 사진이 있으면 영상, 없으면 이미지로 정한다.
- 콘텐츠 안전 거르기(D11): 규칙으로 막을 낱말 목록을 아직 정하지 않았다.
- 채팅만 쓰는 사용자(작업공간 없음, D1a)와 검사 문제 시 자동 재생성(D8)은 받지 않는다 (권장안).
- 영상 요청의 LLM 차례 묶기(설계 5.6): 기능에는 영향이 없고, 차례 수를 줄이는 최적화다.
